# @kolu/acp-harness — the one package that runs the protocol out loud

[`@kolu/acp`](../acp) is the Agent Client Protocol's words and pure projections over them; nothing in it waits, spawns, or knows a subprocess exists. This is where one does.

`@kolu/acp-harness` spawns an ACP adapter, holds one session on it, and turns a stream of protocol frames into the transcript rows kolu's contract declares. It is **the volatility receptacle**: everything hard about talking to an agent over a pipe — a child that dies mid-turn, a frame from a conversation you already left, a question that blocks a turn until a person answers it, a background task that outlives the turn that armed it — is hidden here, and the dependency arrow points out. [`kolu-server`](../server) holds exactly ONE of these — the [Conductor](https://kolu.dev/conductor), covering every host — and never spells `session/prompt`.

## The door

One entry, deliberately. A second subpath would be a second way to reach a subprocess, and there is exactly one subprocess.

```ts
const harness = await startHarness({
  leg, adapter,                 // how it reads its wire, what to spawn
  cwd, configDir, mcpServers, teaching,  // where it works, the store its signature is read from, what it can reach, the standing prompt the CALLER wrote
  log, resume,                  // a session id to `session/load`, or null for a fresh one
  resumedSeq, fleet, model,     // the highest `seq` already persisted; the terminals remembered; the model a person chose
  onChange,                     // { kind: "state" } | { kind: "rows", upserts, removes, appends }
});
```

`mcpServers` is an array of two arms, discriminated by `kind`. A `{kind:"stdio"}` entry is a program on this machine (`name`, `command`, `args`, `env`); a `{kind:"http"}` entry is a server already running (`name`, `url`, `headers` — where a bearer token rides). kolu hands exactly one of the second kind: its fleet MCP face, served in-process by kolu-server on loopback, which is how one conversation reaches terminals on every host. On the wire the arms differ by ONE key, and it is not `kind`: ACP's stdio arm is the one with **no `type` key at all**, and the pinned adapter silently DROPS an entry carrying `type: "stdio"` — so the in-tree discriminant is named `kind` precisely so it can never be confused with the wire's `type`.

`startHarness` does spawn + `initialize` + (`session/load` when `resume` is a string, else `session/new`) + the leg's permission mode + the remembered `model`, all before it resolves — one `try` over the whole sequence, so a refusal or a deadline **stops the child** rather than leaving an adapter (and a `claude` under it) running for every retry. It never resolves into a half-open conversation, with **two** exceptions, both of which keep the child. An `auth` refusal resolves with `phase: "offline"` and `state.signIn = {why, methods, attempt: null}`, because the process that refused is the process a sign-in has to run against. And a `session/load` refused for any OTHER reason opens a fresh conversation instead: `-32002 Resource not found: <id>` is a fact about a string the CALLER wrote down — its store moved, its history was pruned, a different CLI answered — not evidence that the agent is broken, and the agent demonstrably is not, because it just refused. Read alike, that killed the adapter and the caller spawned another to ask the same dead id again. Every refusal is PUBLISHED through `onChange` before it is thrown, so the panel says why instead of looking idle.

**A refused open is not the only way an agent asks for a signature, and on the pair kolu ships it is not even the usual one.** Measured against `claude-agent-acp` 0.81.2 over agent-distro's `claude` 2.1.319 with an empty `$HOME`: the handshake advertises both paste-a-code methods, the agent pushes `_auth/status_update {kind:"none"}`, **`session/new` SUCCEEDS**, and `-32000` does not arrive until the turn. So `state.signIn` is published on all three — the agent saying nobody is signed in, a refused open, and a refused turn — and withdrawn when the agent names an account or a sign-in exits 0. An offer that waited for the refused open alone was no offer at all here: the panel drew a composer over an agent that could not answer, and the sign-in button reported that the agent had offered nothing.

Two error classes are the whole of what a caller may branch on: `HarnessUnavailable` (no child, no session) and `HarnessRefused` (`{why, auth}` — a refusal, the agent's or this end's). Anything else is a defect and propagates unwrapped, because a conductor that broke in a way nobody declared should crash loudly rather than arrive as a polite sentence in a chat.

The verbs are `prompt(text, mentions, attachments)` · `cancel` · `answer` · `signIn` · `signInInput` · `signInCancel` · `setOption` · `newSession` · `stop`, plus `state()`, `rows()` and `alive()` — the last for a caller deciding whether to replace a harness, since an `auth`-refused one is offline AND alive. `state()` answers the conductor state **minus `install`, `agentName` and `cwd`** (`HarnessState`): those were settled before this process started — the engine's and the caller's own — and a harness that echoed them back would be overwriting the caller's answer with a copy of it.

## The rules it keeps

Each of these is a bug that happened once. They are what the package is.

- **A prompt is ALWAYS a plain `session/prompt`, busy or idle.** The queue is the AGENT'S: a message sent mid-turn goes out immediately and waits there, marked `queued` until it is picked up. Nothing is held on this side — which is also why `cancel` has nothing to throw away.
- **The permission mode the leg names is asked for after a new session AND after a load**, before the conversation is entered — a mode belongs to the session, so a restored one that never asked is the one where every write becomes a question somebody answers by hand. A refusal is a row, not a failed bring-up, unless the leg says `bypassModeRequired`.
- **A resumed conversation's HISTORY is dropped; its NEWS is not.** `session/load` re-emits the whole transcript before it answers, and the caller's persisted rows are kept instead, because they carry kolu's own readings (tool cards, notices, the fleet) that no agent's transcript holds. Only the transcript-bearing kinds are dropped, though: an `available_commands_update`, `config_option_update` or `usage_update` on that same stream is the session as it stands NOW, and dropping it left a resumed conversation with no `/` completion and no context meter for the rest of its life. `resumedSeq` is the highest `seq` the caller holds, and every id and `seq` minted here starts after it.
- **The fleet a resumed conversation comes back with is the caller's.** Membership accrues from tool-call frames alone, and a resumed conversation's frames are the replay — so `fleet` seeds it at construction, and the first publish carries what the caller remembered instead of writing an empty list back over its record. Terminals this visit touches join on top.
- **A divider means the agent's memory was reset, and nothing else.** Two things mint one: `newSession()`, and a resume that could not be — a `session/load` the agent refused for the id, where the conversation that opens instead is a different one and the break says so, under one line naming the agent's own sentence for why. A bring-up, a resume that worked, and the replacement that comes up over a dead adapter mint none. The transcript KEEPS its history across the break — a `clear` would be a lie to a caller whose copy holds rows this process never minted — and the mark is withdrawn again if the new conversation would not open, because an open that failed reset nothing and a retry behind it is how four `— NEW SESSION —` lines come to sit on top of one another. A second break with nothing said between is not minted at all — including the break the CALLER is already holding, which a fresh transcript cannot see and `resumedEndsWithDivider` tells it about: without it, a `newSession` after a respawn minted one beside the caller's every time.
- **The model row is a SETTING as well as the header's reading.** Every `configOptions` row is published in `state().options`, the model's first and marked `kind: "model"`; a boolean row (no choices, a boolean `currentValue`) is marked `kind: "boolean"` and goes back to the agent as ACP's `{type: "boolean", value}` rather than as the string a caller spelled it with. Pulling the model row OUT for the header's name and window — and publishing the rest — is how a panel came to say "Opus 5.5" over a popover with no way to change the model.
- **An attachment is a content block or a refusal, never a silent drop.** An `image/*` needs the agent's advertised `promptCapabilities.image`, a text-like file (`text/*`, JSON, XML, JavaScript) embeds its text as a `resource` and needs `embeddedContext`, and everything else is a `resource_link` naming the absolute path the caller wrote. 10 MiB an attachment and 20 MiB a message, refused with a sentence naming the limit — and refused BEFORE the row is minted, so a person's message is still theirs to send. **The bytes are read off `path`**, which is the only copy there is: base64 cannot ride the `prompt` frame (an oversized frame closes the tab's socket), so the browser uploads in chunks and hands kolu-server a file. That is also why a RESTORED row can be sent again — it has a path like any other.
- **The roster moves only on the AGENT'S own word.** Each server kolu handed over starts `handed`, with `where` as the place we sent it — the absolute command for a program, the URL for an HTTP server; a leg's `rawMessages` report moves it to `connected` or to `unattached` carrying the word the agent used. A server the agent names and nobody handed over adds no row.
- **Nothing is published after `stop()`.** A turn still on the wire ends a moment later; its rows would be rows the caller persists for a conversation it has already let go. The one frame a shutdown owes a reader is sent by hand.
- **The stale-frame fence is armed as the session is LEFT.** A leftover chunk from the conversation just replaced would otherwise appear in one nobody spoke in. `leaving()` names the session being left BEFORE `activeSession` is nulled; nulling first made the fence a no-op.
- **The conversation being left is CLOSED at the agent, not merely dropped.** `newSession()` sends `session/close` for the id it is leaving, and sends it BEFORE it opens the next one. The pinned Claude adapter gives every session its own SDK `query()`, and `query()` spawns a `claude` the moment the session is made — ~276 MB apiece, still generating if the turn it was left in never ended — so a client that opens a second conversation without this leaves the first CLI running for the life of the adapter: **one `session/new`, one `claude`, for ever** (measured: two opens, two live children; a production padi was found holding five). Before rather than after the open, because a host must never carry two agent CLIs for one panel and because an open that FAILS would otherwise strand the old one with nothing on this side able to reach it. Closing ends the process and not the record — ACP spells forgetting `session/delete` — so a later resume of the id is still a resume. There is no capability to read first, so an agent without the method answers "method not found": that is logged and swallowed, never a refusal of the new conversation somebody asked for.
- **Prologue dedupe at ONE door.** An adapter may publish a startup banner and then repeat it as an ordinary message. The repeat is dropped on the exact text the open's own answer carried — never on a guess at prose — at the single `agent_message_chunk` door, so every downstream counter agrees.
- **A permission request is auto-approved only for a tool positively RECOGNISED** as belonging to an MCP server we handed over, choosing an option whose `kind` starts with `allow` — never "the first option". A tool it cannot name is one a person is asked about.
- **A frame refines, never retracts.** The kolu reading of a tool call is accumulated across frames (`refineKoluCall`), because the adapter puts the call's input on the arming frame and its answer on the settling one, and a card built from either alone is missing the half the other had.
- **A string the agent wrote is a terminal only if it IS one.** Each kolu tool's reading says where its subject is — a `watch_next` card's is the one terminal every drained event names, never the call's own `id`, which is the subscription's name — and the ref found there becomes `terminalId` + `host` only when its id half passes `isTerminalId`, the check the row schema applies on encode. Anything else is no terminal at all, never half of one. A row is persisted and served through that schema, so one that fails it is a transcript that no longer opens.
- **An MCP answer is read through the LEG.** `kolu mcp` replies in a text content block, so `rawOutput` arrives as a JSON *string*; which corner of a frame an agent puts its structured answer in is exactly what a `Leg` exists to answer.
- **Sign-in has no API-key box.** ACP's `env_var` method kind is deliberately skipped; a `terminal` method's command is spawned here and its output streamed, and exit 0 is the whole of success — after which the harness opens the conversation FRESH, releasing whatever session was open: a signed-out `session/new` succeeds, so the session that existed belongs to a CLI with no credential, and the pinned adapter recreates that query only under `--hide-claude-auth`, which kolu does not pass. When the handshake advertises NOTHING, the published `why` names the adapter, what it calls itself, what kolu asked for (`auth.terminal`, `_meta["terminal-auth"]`) and the `configDir` the signature is read from — a dead end described, never a button this end invented. `configDir` is **stated, never plumbed**: nothing here opens that directory.
- **A turn the agent REFUSES is a turn that ended**, not an agent that has gone: the conversation stays ready and the next message goes to the same agent.

## Tests

Against **really spawned** fixture agents (`src/fixtures/`), not mocks — plain `.ts` files run as `process.execPath <file>`, since node strips types natively. A mock would prove only that the reader can read what the test wrote; a spawned agent proves the pipe, the codec, the ordering and the lifecycle. `subprocess-agent.ts` goes one further and holds a REAL child process per session, the way the pinned adapter holds a `claude`, so "a replaced conversation leaves one process, not two" is a count of processes rather than of bookkeeping. The lane is **`test:daemon`**, not `test:unit`: every case forks a detached process group, so it runs serially with the other daemon-forking packages, and one `afterEach` stops every harness a case started. The one pure file, `src/kolu.test.ts`, rides the same lane (a package declares one): each kolu tool read off the shapes it really takes and answers, and every reading — whatever strings sit in its arguments — encoded under the contract's row schema.

A fixture is only ever as honest as the measurement it was copied from, so the two signed-out agents are copies of two different measurements: `signed-out-agent.ts` refuses the OPEN with `-32000` (the protocol's own way of asking, and what every fixture here used to assume), and `signed-out-open-agent.ts` is the pinned pair's real sequence — methods at the handshake, `{kind:"none"}` pushed, the session OPENED, the TURN refused — with `--no-methods` and `--no-status` for the dead end and for an agent that says nothing about itself. The claim only the two binaries can keep is kept where they are: `packages/server/src/conductor/signedOut.live.test.ts` drives the real adapter and the real `claude` against a scratch `$HOME`, offers the sign-in, runs it as far as the URL, and cancels — a test may never complete a login or touch anybody's credential.

## What it deliberately does not do

`session/list` and the adopt/model-memory bookkeeping (kolu-server owns persistence and hands `resume`, `resumedSeq` and `model`), ACP client-owned terminals (`terminal/*` — the agent has kolu's terminals through MCP, so the extension is not advertised and nothing reads one), and native child sessions. None of them is a gap this package hides; each is a decision recorded where it was made.
