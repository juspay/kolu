## A. The registry cut — codex WINS over my own proposal; grok half-concedes by implication

Codex's evidence is decisive: `buildHostRegistry`'s core calls **only** `session.destroy()` (add-rollback, remove, destroyAll); the mirror-session members are consumed by the *pump*, never the registry. Under guarantees-at-the-knowing-endpoint, a slot must demand exactly what it uses — so the registry's role is `DestroyableSession { destroy(): void }`, not my `PoolableSession` (which demanded mirror-ness the registry never touches) and not grok's role-typed registry (same excess, smaller). **I withdraw PoolableSession.** The primer's "widen the slot to the role" was right in direction, wrong in target role — the *smallest true role* wins.

Codex's fleet-verbs shape also beats both alternatives on F4: optionality at **registry construction** (`controls` supplied → the returned type has `reconnect`/`recheckAll`; absent → those members don't exist, union-typed) — no optional methods on any session, no silent no-op, and the illegal call doesn't typecheck. That is the strictest capability shape anyone proposed. **Conceded.**

## B. Identity: universal YES — but on the base role (grok) or a daemon sub-role (codex)? Codex, by doctrine.

Grok puts `identity()` on `RemoteMirrorSession` itself; codex splits `DaemonMirrorSession extends MirrorSession { identity(); convergence() }`. The doctrine test: a base-role `identity(): X | null` satisfied by non-daemon far ends (an ephemeral drishti agent) is null *forever* — a structurally meaningless member, the silently-absent-behavior smell F4 exists to kill. Codex's split keeps the guarantee where daemon-ness is *known*. **Adjudication: codex's shape.** Grok's strongest rebuttal (make `hello` universal for every surface *server*, not just daemons — then nothing is null-forever) is bigger than the hosting side and worth its own question; until that exists, the sub-role is the honest boundary. FORK if grok holds.

## C. renew() NOW — I withdraw my third-daemon gate; codex's strategy type answers my own objection

My round-1 hold on `renew()` was population-based. Codex's shape dissolves it: `PreservationStrategy` carries `children: "survive" | "die"` **in the type** — the exact fact I insisted must never be buried is now un-buriable; and `renew()` is an interface over TWO already-existing enactments (padi drain, kaval recycle), so it's naming a proven shared intent, not building a receptacle for one. **Conceded, with two demands**: (1) the UI keeps per-daemon honesty ("running programs will stop" for kaval) — the type carries the fact, the dialogs must surface it; (2) precision on kaval: it has no bound session, so `RenewableDaemon` is implemented by `BoundPadi` only; kaval's `recycleKaval` *adopts the PreservationStrategy vocabulary* (`children: "die"`) without a forced shared runtime interface. With this, `BoundPadi = DaemonMirrorSession<PadiSurfaceClient> & RenewableDaemon` is a genuine alias and the six bespoke readout methods die.

## D. Pool vs client scope: codex and I hold "vocabulary, not machinery"; grok holds "one receptacle" — the genuine FORK

Grok's strongest form: the registry, once role-only, IS the "runtime set of live sessions" receptacle, and surface-app's dynamic scope is its consumer face. Codex's counter (which I join, from F1): the server side is a many-entry resource manager with socket eviction; the browser side is a Solid-owned *current-connection accessor* whose hard part is reactive teardown — merging them either leaks Solid into the server or erases eviction semantics. And codex's concrete browser proposal is decisively small: `controlPlane: Accessor<ControlPlane>` on the provider, subscription keyed off the accessor — static callers pass `() => surfaceApp`, dynamic callers swap the accessor. **This reshapes W4-PR2**: the framework delta may be exactly that accessor-ization, not a new "dynamic client scope" concept. **Fork stands** (grok: one machinery · codex+me: shared vocabulary "binding", separate machinery); the tiebreaker evidence would be a concrete shared kernel both sides consume without a Solid or eviction leak — neither radical produced one.
