## Codex proposals — steelman then position

### 1. PoolableSession is the wrong cut; split the roles (registry vs pump)

**Steelman**: The registry's implementation (hostFanout.ts:390-460) only ever calls three things on its stored sessions:
- `entry.session.destroy()` (add rollback line 404, remove line 431, destroyAll line 457)
- `session.reconnect()` (reconnect line 436)
- `session.recheck()` (recheckAll line 439)

It never calls `pin()`, `currentClient()`, `onState()`, `markConnected()`, or `isDestroyed()`. Those belong exclusively to the reconnect-mirror loop in `pumpRemoteSurface` (hostFanout.ts:199-260: pin, cursor.next which uses currentClient, pipeSessionStateToCell which subscribes onState, makeSink which calls markConnected, while (!session.isDestroyed())).

`reServeSurface` (reServeSurface.ts:95) and `pumpRemoteSurface` (hostFanout.ts:122) already take the full `RemoteMirrorSession` role. Typing the registry's `HostEntry.session` as `HostSession<C>` (or even a superset `PoolableSession`) leaks the mirror contract into a component that does not need or use it. This is exactly the "receptacle for a population of one" smell we hate.

Codex's split (DestroyableSession for the map lifecycle + separate `controls?` for fleet verbs) is smaller and more precise. The registry becomes a generic keyed resource manager; the mirror protocol is only required by the pump sites that actually drive it.

**My position (concede + strengthen)**: Full concession on the cut. My round-1 `PoolableSession` (role + destroy + optionals) was still too fat for the registry. Registry should be:

```ts
// smallest for the map owner
export interface DestroyableSession {
  destroy(): void;
}

export interface HostEntry<S extends DestroyableSession, H> {
  session: S;
  handler: H;
}
```

Fleet controls declared at construction time (no `?()` on the session):

```ts
export interface HostRegistryOptions<S extends DestroyableSession, H> {
  ...
  controls?: {
    reconnect(session: S): void;
    recheck(session: S): void;
  };
}
```

This kills the optional-method smell (aligns with claude F4) and lets drishti (or anyone) supply any destroyable — even non-surface things if a future fleet use appears. The pump sites stay on the full mirror role. Evidence: the body of buildHostRegistry never touches mirror methods; buildEntry is where the caller (who knows the contract) wires the pump.

### 2. MirrorSession rename + de-genericization

**Steelman**: `RemoteMirrorSession` is misleading — `PadiBindingSession` (local unix + endpoint) satisfies it (padiBinding.ts:366, remotePadiBinding.ts:322 also wraps). The `_C` is documentary only: the interface itself uses `Promise<unknown>` (hostSession.ts:224-231), and the long comment (hostSession.ts:206-223) explicitly says the role keeps the client opaque for structural forwarding and covariance. `reServeSurface` and `pump` already accept the role, not the class. The explicit `<typeof padiSurface.spec, typeof padiSurface.contract>` dance at server/index.ts:269-272 is noise. Rename to `MirrorSession` (or `SurfaceSession`) and default the client type.

Codex's proposed shape:

```ts
export interface MirrorSession<Client extends SurfaceClientLike = SurfaceClientLike> {
  pin(): Promise<Client>;
  currentClient(): Promise<Client> | null;
  ...
}
```

**My position (concede rename + partial de-gen, rebut full erasure)**: Concede the rename. "Remote" is baggage; both local and ssh arms implement the same receptacle for pump/re-serve. "Mirror" accurately describes the volatility (re-mirror on each fresh client).

On de-genericization: partial. The loose `unknown` (or `SurfaceClientLike`) in the role is load-bearing for the covariance the variance test pins (reServeSurface.variance.test-d.ts:1-70). A specific `HostSession<SpecificContract>` (whose `system.live` takes `Record<never>`) must be assignable to the un-annotated `pumpRemoteSurface({session})` call that drishti (and kolu) actually write. Narrowing the role to a precise `Client` reintroduces contravariance and breaks the test + real consumers.

Codex's `MirrorSession<Client = SurfaceClientLike>` with defaults on the pump/reServe signatures is viable and smaller than today's `RemoteMirrorSession<_C>`. We can adopt it, keep the loose default at the receptacle boundary, and let direct callers of `HostSession<C>` (or `PadiBindingSession`) keep the precise type via the class. This kills the public name `RemoteMirrorSession` and the explicit two-arg cast at server/index.ts without breaking assignability. Evidence: the role comment and variance test are the only reasons the generic exists at all.
