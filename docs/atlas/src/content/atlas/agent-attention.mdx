When an agent finishes a turn, or stops to ask you a question, kolu reacts: a sound,
an OS popup, an app-icon badge, a host-tab mark, a dock dot. That is all **one
thing** — getting your **attention** — and it now lives in one model, in one place.

<Svg svg={diagram} wide caption="It used to be three modules, split by whether you were looking at the host. Now one module applies the same rules everywhere, on top of the existing delivery code." />

## The rules — one set, every host

One set of rules, identical on every host. The only thing "which host you're looking
at" changes is whether a terminal counts as already **seen**.

| Agent state | Sound + popup (once) | On-screen marks | Goes away when |
| --- | --- | --- | --- |
| **Asking you** (waiting for input) | if not already seen | loud amber host-tab count + dock pip | you answer |
| **Just finished** (no input needed, PTY gone quiet) | if not already seen | quiet dim-amber host-tab dot + dock unread | you look at it |
| Working / idle | — | (optional "live" ring) | — |

The two host-tab marks speak **one** amber "needs you" language in two tiers: the
full-amber count for *asking* (blocking, actionable) and a dim-amber dot for an
*unseen finish* (a lesser nudge) — never a separate grey vocabulary.<Footnote>The dot reads the cross-host **unseen-finished** mark `useAttention` publishes, not the raw `finishedIds` — a finished agent idles in `waiting` ~forever, so "has any finished agent" would light every host permanently. The unseen rule is the pure, unit-tested `nextUnseenFinished`.</Footnote>
"Which host" enters in exactly one place — **seen**: a terminal you're staring at is
seen; one on a background host isn't. Everything else is host-agnostic.

## One word: attention

The code used to call this three things — *alerts*, *attention*, *notifications*.
Now it's one word, **attention**: the system that decides when a terminal needs you
and how to show it. **Notification** is kept for one thing only — the OS/browser
popup (the platform's own `Notification` API), a *channel* attention uses, not the
concept.

## How it's built

One `useAttention` module owns the rules. Underneath it: a pure `attentionTransitions`
decides "needs you now" vs "just finished" (unit-tested, off the wire); delivery — the
sound and OS popup — rides the existing `attentionNotify` seam <Cite file="packages/client/src/attentionNotify.ts" />; and agent-state → class stays in the shared `agentProjection` fold <Cite file="packages/terminal-vocab/src/agentProjection.ts" line={72} />. Every host reads its own `urgency` cell (now carrying `finishedIds` too), so a background host's finished agent pings and shows a quiet mark exactly like the active host's — the behavior that used to be missing.

Before, the rules were split across three modules by whether you were looking at the
host — `useTerminalAlerts` (active host), `useHostAttention` (the others), and an
active-only "seen" ledger — so the same agent behaved differently depending on focus.
Those are gone. Shipped in <PrLink pr={1931} />; the `activityAlerts` setting was
renamed `attentionAlerts` (with a migration).

## Effective finish — agent state fused with terminal quiet

An agent like Claude Code can mark its turn *finished* while background sub-agents keep
working, so a raw `waiting` is a **premature** "finished" — the transcript says done,
but the terminal is still moving bytes. The fix: a `waiting` terminal is only an
**effective** finish once its PTY has gone **quiet** for a debounce window (~5s). The
gate byte-taps *only* the `waiting` terminals — a small, bounded set — debounces each on
the same tracker the live-dot uses <Cite file="packages/padi/src/terminalActivityTracker.ts" />, and feeds the
settled set into the `urgency` fold, which admits a `waiting` terminal to `finishedIds`
only when settled. <Cite file="packages/padi/src/urgency.ts" line={64} />

Three decisions make it correct. It lives in **padi**, not the client live-dot
`useTerminalActivity` (which only sees attached tiles) — padi sees every terminal's
bytes, active *or* background, so the whole cross-host model rides it. <Cite file="packages/padi/src/finishGate.ts" /> It's
**default-excluded** — a terminal that just flipped to `waiting` isn't yet settled, so a
late observation only *delays* a finish (the lesser, non-blocking nudge), it can never
fire one early. And it gates **finished only**: the ASKING path (`awaiting_user`) is
blocking and actionable, so it fires at once, never debounced. Because "output stopped"
is a non-event on the wire, the gate carries its own debounce timer and pushes the
quiet-crossing edge into the reactor graph so `urgency` re-folds. It's a heuristic tuned
by the quiet window: a chatty background agent is caught, and an agent whose TUI redraws
at rest (a spinner emitting real bytes) would defer a real finish. Shipped in <PrLink pr={1938} />.

## Follow-ups

What the review gauntlet surfaced but the first cut left out. Items marked
**user-facing** change what you see or hear; the rest are internal quality or CI infra.

**Correctness**

- **Split-aware "seen".** *(user-facing)* The seen check compares the active *tile* id,
  so a finished pane you can plainly see inside a split can still chime. The right test
  is "a visible pane of the active tile," not tile-or-focus alone. <Cite file="packages/client/src/attention/useAttention.ts" line={113} />
- **Test the real path.** e2e drives a simulate hook that *bypasses* the detect→fire
  engine — the exact gap that let a `reconcile`-mutation bug ship. The engine has unit
  tests now; an e2e over the real *agent-state → deliver* path would close the class.

**Robustness**

- **Route notification-popup clicks through the deep-link resolver.** *(user-facing)*
  Clicking the **OS/PWA notification popup** — the banner the service worker shows when
  an agent needs you and you're not looking (it can arrive with kolu backgrounded or
  closed) — today calls a raw tile activation. Routing it through the same resolver
  `#/t/…` deep links use would land the right split, survive a cold boot (the app was
  closed when the popup arrived), and report a terminal that's since gone. <Cite file="packages/client/src/attention/useAttention.ts" line={257} />
- **Carry membership in the `urgency` cell.** *(user-facing, only if it bites)* A
  terminal first *seen* already-finished (a wake, another tab) can't be told from a real
  finish, because working terminals are invisible to the cell.

**Structure**

- Fold the app-badge painter's ordering/dedup/retry into `@kolu/surface-app`'s
  `setAttention` seam and route through it, dropping the app-local copy.
- Export surface-map's `WatchedValue` liveness so `useAttention` stops duplicating it.
- Move the e2e-only `AttentionDeps` fields off the production seam.
- **Model the finish gate's per-terminal lifecycle as a type, not six sets.** The gate
  tracks each terminal across six parallel keyed collections — `tracked`, `taps`,
  `tapGen`, `attached`, `settled`, `awaitingRearm` <Cite file="packages/padi/src/finishGate.ts" line={142} /> — whose
  invariants (settled ⟹ attached; settled ∧ awaitingRearm never co-hold) are enforced by
  call-order discipline, documented in prose. A single `Map<TerminalId, TapState>` with a
  discriminated `TapState` would make the illegal combinations unspellable at the type
  level. Deferred, not done: the state is a genuine *product* (attachment × episode ×
  quiet) plus per-tap metadata (`tapGen`, the disposer) that coexists with every arm, so
  it isn't a clean single discriminant — and the current form is quiet-window-timing
  sensitive, thoroughly unit-tested (incl. the F1/F3/F5 edges), and freshly hardened
  through the review, so the rewrite is a follow-up to weigh carefully rather than churn
  to force now.

<Callout kind="note" title="CI hygiene — the recurring darwin flake">
The darwin `code-tab` fs-watch scenarios flake because odu leaks temp checkouts *and*
orphaned e2e processes on the macOS CI boxes, and the leaks peg fseventsd. A post-run
temp-dir + orphaned-process reap (plus hardening the file-watch `waitFor`s — a retry
doesn't touch the wedged fseventsd layer) would stop it recurring every darwin run.
Not attention code, but it's what turns a green PR red.
</Callout>
