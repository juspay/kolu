**osfacts is a product of its own** — its own repo, its own README, its own CI —
not a kolu module. One static Rust binary that answers *what does the OS say
about these processes and their sockets*, scoped to exactly what you asked,
honest about what it could not read, in about ten milliseconds. kolu and drishti
are its first two consumers, and the reason to build it is that the tool they
need genuinely does not exist — see the comparison below.<Footnote>Status:
proposed, deliberately future work; nothing here ships yet. Every measurement in
this note comes from the <PrLink pr={1982} /> candidate sweep — the note is
where that week's conclusions live on after the scratchpads that produced them
are gone.</Footnote>

The creed, one line per word — also the repo README's opening:

- **Scoped** — cost tracks the *ask* (`--roots` walks a subtree), never the host.
- **Attributed** — every snapshot carries the full pid→ppid table, so a
  grandchild listener walks back to its root.
- **Honest** — what it could not read is *reported*, never silently dropped.
- **Versioned** — schema version first; a mismatched consumer fails loudly
  instead of parsing a half-understood shape into zero rows.
- **Fast** — ~10 ms per snapshot, because interactive callers poll at
  seconds scale. This budget is the requirement that explains every rejection
  in the comparison table.

## User stories

Five flows, one contract — every story is the same verb with different facets,
never a consumer-shaped flag or mode:

| who                             | wants to know                                        | runs                                                | comes back                                                                                                                    |
| ------------------------------- | ---------------------------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| kolu's port sensor, every ~5 s  | which ports this terminal's subtree listens on       | `osfacts snapshot --roots 4242 --procs --ports`     | pid table + listener rows with raw addresses; unreadable pids listed, so a blind terminal renders *blind*, not *empty*        |
| drishti's inspector             | the process tree under a service, with memory and age | `osfacts snapshot --roots 991 --procs --mem --start-time` | one row per descendant with RSS and start time                                                                                |
| kolu's daemon supervisor        | is this pid still mine, and since when               | `osfacts snapshot --pids 991 --start-time`          | a start time to compare against the recorded one                                                                              |
| padi's socket takeover          | which pids hold this unix socket                     | `osfacts socket-holders /run/user/1000/padi.sock`   | the holder pids, or none                                                                                                      |
| a human at any shell            | all of it, readable                                  | `osfacts snapshot --json \| jq`                     | the same facts as JSON                                                                                                        |

## The contract

**One verb, composable facets, first-class scoping.**

```
osfacts snapshot --roots 4242,4310 --procs --ports
osfacts snapshot --pids 991 --mem --start-time
osfacts socket-holders /run/user/1000/padi.sock
```

- **Scoping is the headline.** `--roots` walks the given pids' subtrees,
  `--pids` takes an exact set, no flag means host-wide. Cost then tracks the
  *ask*, not the host — the property no surveyed tool has and the one the
  measurements say matters most.
- **Facets** so a consumer pays only for what it reads: `--procs`, `--ports`,
  `--mem`, `--start-time`. `socket-holders` is a second verb because it answers
  a different question (a path, not a pid set).
- **One versioned schema.** TSV on the hot path (`V<TAB>1` first, tagged rows),
  `--json` for humans and one-offs.
- **Raw address bytes, never a `wildcard` boolean.** Consumers keep exactly one
  classifier. Two predicates that must agree about `::ffff:0.0.0.0` is precisely
  how they come to disagree.
- **Cumulative CPU time per row**, so CPU% is a consumer-side diff between two
  snapshots rather than a sampling delay inside the tool.<Footnote>This is why
  `procs` costs ~30 ms even at its lowest setting: it sleeps to compute a rate
  nobody asked it for. A one-shot sampler should never sleep.</Footnote>
- **A MANDATORY `unreadable` section.** Every pid that could not be inspected is
  *reported*, with its errno — the policy of what is fatal stays in the
  consumer, the only layer that knows which pids it asked about.<Footnote>The
  sudo lesson made structural: when an unreadable pid was silently dropped, one
  `sudo` password prompt emptied the Ports section for every terminal on the
  host; when it threw indiscriminately, one foreign-uid descendant did the
  same.</Footnote>

## Why not an existing tool

Every candidate was **measured, not surveyed**, and each fails on the contract
above rather than on packaging — anything merely absent from nixpkgs could be
packaged in an afternoon, so packaging never counts as a
disqualifier.<Footnote>Earlier drafts listed "not packaged for darwin" against
osquery and "not in nixpkgs" against portls. Both struck: a packaging gap is an
errand, not an architecture verdict. The rows now stand on what each tool
*is*.</Footnote> The repo README carries this same table:

| candidate            | disqualifier                                                                                                                                                                                                                                              |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `osquery`            | **the wrong operational model**: a resident fleet-telemetry agent with a SQL surface, measured at ~378 ms per query and ~158 MB — built for querying thousands of machines every few minutes, not one machine every five seconds on a 10 ms budget          |
| `procs`              | **discards the bind address** — loopback and wildcard collapse to one row                                                                                                                                                                                  |
| `portls`             | no PPID, no process table — a listener cannot be walked back to its root                                                                                                                                                                                   |
| `rustnet`            | interactive capture TUI, needs packet-capture privilege                                                                                                                                                                                                    |
| `portview`           | **listener rows only, no process table** — a `shell → npm → node` server cannot be walked back to its terminal, because `npm` holds no listener and never appears. No subtree scoping either: its single-port query is a host-wide scan plus a filter (26.0 ms full vs 25.1 ms scoped) |
| `sysinfo`+`listeners` | wrapping the two crates enumerates the process list **twice**: 23 ms darwin / ~100 ms linux against 10 ms for a single pass — and `listeners` shipped the v4-mapped decode bug [we fixed upstream](https://github.com/GyulyVGC/listeners/pull/57)          |
| `lsof` / `netstat`   | `lsof` measured 93 ms; macOS `netstat` is **intermittently blind** — success and zero rows in one sampling window, 29 rows in the next, same boot                                                                                                          |

`portview` is also the strongest evidence *for* building this: it measures
**9.9 ms on darwin** against our C helper's 10.6 ms on the same box by the same
method, in Rust, in a single pass. Single-pass Rust matches C — the language was
never the constraint, the double enumeration was. That measurement is what
settles osfacts on Rust.

## Internals

One pass per platform, and no more:

- **linux** — `/proc`, scoped by descending `/proc/<pid>/task/<tid>/children`
  from each root rather than reading the whole pid table. That descent is
  exactly the `u-port-scan-subtree-descent` opportunity, and the cost accounting
  says it is worth ~96% of a scoped pass.
- **darwin** — a single libproc pass (`proc_listpids` → `proc_pidinfo` →
  `proc_pidfdinfo`), the shape the C helper already proved at ~4 ms of real
  work.

**Crates only where earned.** The fixed `listeners` for darwin address decoding
once [the upstream fix](https://github.com/GyulyVGC/listeners/pull/57) merges —
and **not `sysinfo`**: pairing them walks the host twice, which is disqualified
by construction.

### The regression suite is scar tissue

Every one of these is a bug that actually happened, so the suite is written from
the scars rather than from imagination — cargo integration tests, its own CI,
both platforms:

- the five bind fixtures (`127.0.0.1`, `0.0.0.0`, `::1`, `::`,
  `::ffff:127.0.0.1`);
- **v4-mapped vs v4-compatible** — the upstream crate reported
  `::ffff:127.0.0.1` as `::127.0.0.1`;
- **dual-stack flag ordering** — `insi_vflag` sets BOTH bits for `::`, so
  testing `INI_IPV4` first narrows the wildcard to `0.0.0.0`. Two independent
  tools and our own C helper each had this;
- **silent-empty detection** — a mechanism that answers "no ports" successfully
  is the worst possible failure here, and macOS `netstat` does it
  intermittently;
- **the `unreadable` contract** — an uninspectable pid must appear in output.

## How kolu and drishti adopt it

Inside kolu the OS is inspected in five places today, each with its own
hand-rolled reader, its own error policy, and its own platform split — five
answers to one question, and every one a place a platform quirk can be got wrong
independently.<Footnote>The week that produced <PrLink pr={1982} /> found four
such quirks, each fixed in exactly one of the five readers.</Footnote> All five
collapse into calls to the one binary — and a full-source sweep confirms the
list is exhaustive.<Footnote>The sweep covered every package including
`@kolu/surface`. The one near-miss: `surface-remote`'s `groupAlive` probe
(`process.kill(-pid, 0)` — process-*group* liveness inside a SIGTERM→SIGKILL
escalation timer). Deliberately not a consumer: group liveness is not in the
fact set, and forking a snapshot binary inside an escalation timer is the wrong
operational model. The `@kolu/surface` example apps read full process tables
but are framework demos, not kolu runtime.</Footnote>

| consumer today       | asks                                                  | reads today                                                                                          |
| -------------------- | ----------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `@kolu/port-scan`    | a subtree's processes + listening ports               | linux `/proc`; darwin a C libproc helper                                                             |
| padi `memorySampler` | per-pid RSS                                           | only *self*-measurement (`process.memoryUsage()`) plus an RPC hop to kaval for kaval's own RSS — no true per-pid read exists yet |
| `socketHolder` (in `surface-daemon-supervisor`) | which pids hold a unix socket **path** | `/proc/net/unix` + fd readlinks; darwin `lsof`                                                       |
| daemon supervisor    | "is this pid still ours", and since when              | `kill(pid, 0)` liveness only — start-time identity is not read at all today                          |
| **drishti**          | process inspection                                    | hand-rolled `lsof`                                                                                   |

### The phase tree — track prefix `OSF`

| phase                        | delivers                                                                                                                                         | needs       |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | ----------- |
| **OSF1 — the binary**        | `snapshot --roots --procs --ports` on both platforms · versioned TSV + `--json` · the mandatory `unreadable` section · the scar-tissue suite · `osfacts/` + subflake wiring | —           |
| **OSF2 — kolu's port sensor adopts it** | `@kolu/port-scan` invokes the baked osfacts binary; the C helper and the linux `/proc` parse are **deleted**<Footnote>The done-criterion names the path: padi's `portSampler` → `@kolu/port-scan` → the osfacts binary, on both platforms, with `packages/port-scan/native/` and the TS `/proc` parse gone — the port e2e must pass *through the new path*, not beside it.</Footnote> | OSF1        |
| **OSF3 — memory & age facets** | `--mem` + `--start-time`; `memorySampler` gains a true per-pid read (the RPC hop to kaval is deleted); the supervisor gains start-time identity   | OSF1        |
| **OSF4 — socket-holders**    | the second verb ships; `socketHolder` deletes its `/proc/net/unix` and `lsof` paths                                                              | OSF1        |
| **OSF5 — drishti & extraction** | drishti migrates wholesale; the directory moves to its own repo and the subflake becomes *the* flake                                          | OSF2–4 stable |

OSF2, OSF3 and OSF4 are independent siblings under OSF1. **The port-forwarding
track needs exactly OSF1 → OSF2** — that pair is the "initial version", and the
other branches can land whenever. Each phase is a consumer deleting its own OS
traversal, independently revertible.

**Out of scope, deliberately:** foreground process (a PTY-fd fact — `tcgetpgrp`
on the pty, so it stays kaval's), anything requiring root, and any
daemon/resident mode. This is a one-shot sampler; if startup cost ever becomes
the problem, the answer is to revisit the operational model, not to hide it
behind a resident process. The same restraint applies outward: no TUI, no
`kill`, no docker verbs — the broad user-facing surface is what made `portls`
and `portview` wrong for embedding, and osfacts stays embeddable by staying
narrow.

## Implementation

**Incubate in the kolu monorepo; extract on the second external consumer.** The
contract will churn hardest while kolu's five readers migrate onto it — each
migration co-evolves the crate and its caller in one PR — and that argues for
one repo until the churn settles.

- **Path: top-level `osfacts/`, not under `packages/`.** `packages/` is the
  pnpm workspace and osfacts is a cargo crate, not a workspace member —
  location is structure, and filing it there would claim a membership it
  doesn't have. The top-level directory *is* the whole future repo:
  `Cargo.toml`, `src/`, `tests/`, the README carrying the comparison table
  above, `default.nix`, `flake.nix`.<Footnote>Precedent: `website/` is exactly
  this shape today — a top-level non-workspace subproject with its own
  `default.nix` and subflake.</Footnote>
- **One `default.nix`, plus a thin zero-input subflake — the vazhi
  pattern.** The canonical build lives in `osfacts/default.nix`
  (`rustPlatform.buildRustPackage`, dependencies vendored via `cargoLock`,
  toolchain from the npins-pinned nixpkgs — **no new flake inputs**, per the
  root flake's zero-input rule). `osfacts/flake.nix` also takes no inputs,
  reusing `nix/each-system.nix`, so `nix run ./osfacts` works standalone from
  day one; the root flake exports `.#osfacts` by importing the *same*
  `default.nix`, so the two paths can never build two
  osfacts.<Footnote>`packages/vazhi/flake.nix` documents this pattern: the
  subflake exists to keep the extraction gap small and visible, not to claim it
  is already zero.</Footnote>
- **Consumers take the binary by baked store path.** padi and drishti reference
  the Nix-built osfacts the way padi ships its C helper today: the path is
  baked at build time and the caller crashes loudly if it is absent — never a
  `PATH` lookup, never an env override.
- **CI while incubated:** the cargo regression suite runs as a kolu CI lane on
  both platforms; it moves with the directory on extraction.
- **The extraction signal is drishti (OSF5).** kolu's readers migrate in-repo;
  the day drishti — a separate repository — takes the dependency, osfacts
  graduates to its own repo. The directory moves wholesale, the subflake
  becomes *the* flake, and the contract does not change.
