**osfacts is a product of its own** — its own README, its own CI, its own
repo-to-be — not a kolu module. One static Rust binary that answers *what does
the OS say about these processes and their sockets*, scoped to exactly what you
asked, honest about what it could not read, in about ten milliseconds. The
binary and kolu's port-sensor adoption shipped in <PrLink pr={1996} />;
drishti's adoption attempt
([srid/drishti#122](https://github.com/srid/drishti/pull/122)) is what wrote
the rest of the phase tree below.<Footnote>Every measurement in this note comes
from the <PrLink pr={1982} /> candidate sweep — the note is where that week's
conclusions live on after the scratchpads that produced them are
gone.</Footnote>

The creed, one line per word — also the [repo
README](https://github.com/juspay/kolu/blob/master/osfacts/README.md)'s
opening:

- **Scoped** — cost tracks the *ask* (`--roots` walks a subtree), never the host.
- **Attributed** — every snapshot carries the full pid→ppid table, so a
  grandchild listener walks back to its root.
- **Honest** — what it could not read is *reported*, never silently dropped.
- **Versioned** — schema version first; a mismatched consumer fails loudly
  instead of parsing a half-understood shape into zero rows.
- **Fast** — ~10 ms per snapshot, because interactive callers poll at
  seconds scale. This budget is the requirement that explains every rejection
  in the comparison table.

## The contract

**One verb, composable facets, first-class scoping** — every user story is the
same verb with different facets, never a consumer-shaped flag or mode:

| who                             | wants to know                                         | runs                                                      | comes back                                                                                                             |
| ------------------------------- | ----------------------------------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| kolu's port sensor, every ~5 s  | which ports this terminal's subtree listens on        | `osfacts snapshot --roots 4242 --procs --ports`           | pid table + listener rows with raw addresses; unreadable pids listed, so a blind terminal renders *blind*, not *empty* |
| drishti's inspector             | every process, with identity, launch details, memory, age, and CPU% | `snapshotHost(bin, { procs, uid, cwd, status, argv, mem, startTime, cpuTime })` | the real host process set — not pid 1's incomplete subtree — with raw uid, cwd, state/nice/threads, full argv, RSS, start time, and cumulative CPU microseconds |
| kolu's daemon supervisor        | is this pid still mine, and since when                | `osfacts snapshot --pids 991 --start-time`                | a start time to compare against the recorded one                                                                       |
| padi's socket takeover          | which pids hold this unix socket                      | `osfacts socket-holders /run/user/1000/padi.sock`         | the holder pids, or none                                                                                               |
| drishti's host dashboard        | how the machine itself is doing                       | `osfacts host --cpu --mem --load --net --disk`            | cumulative counters + gauges, one versioned schema                                                                     |
| a human at any shell            | all of it, readable                                   | `osfacts snapshot --json \| jq`                           | the same facts as JSON                                                                                                 |

- **Scoping is the headline.** `--roots` walks the given pids' subtrees,
  `--pids` takes an exact set, no flag means host-wide. Cost then tracks the
  *ask*, not the host — the property no surveyed tool has and the one the
  measurements say matters most.
- **Facets** so a consumer pays only for what it reads: `--procs`, `--ports`,
  `--mem`, `--start-time`, `--cpu-time`, `--uid`, `--cwd`, `--status`, and
  `--argv`. `socket-holders` and `host` are
  separate verbs because they answer different questions (a path, not a pid
  set; the machine, not a process).
- **One versioned schema.** TSV on the hot path (`V<TAB>2` first, tagged rows),
  `--json` for humans and one-offs.
- **Raw address bytes, never a `wildcard` boolean.** Consumers keep exactly one
  classifier. Two predicates that must agree about `::ffff:0.0.0.0` is precisely
  how they come to disagree.
- **Cumulative counters, never rates.** CPU% and bytes/s are consumer-side
  diffs between two snapshots; a one-shot sampler never sleeps.<Footnote>This
  is why `procs` costs ~30 ms even at its lowest setting: it sleeps to compute
  a rate nobody asked it for.</Footnote>
- **A MANDATORY `unreadable` section.** Every pid that could not be inspected is
  *reported*, with its errno — the policy of what is fatal stays in the
  consumer, the only layer that knows which pids it asked about.<Footnote>The
  sudo lesson made structural: when an unreadable pid was silently dropped, one
  `sudo` password prompt emptied the Ports section for every terminal on the
  host; when it threw indiscriminately, one foreign-uid descendant did the
  same.</Footnote>

| process facet | tagged TSV row | JSON field | unreadable facet | semantics |
| --- | --- | --- | --- | --- |
| `--procs` | `P pid ppid name` | `procs` | `proc` | short display name and parent identity |
| `--mem` | `M pid rss_bytes` | `memory` | `mem` | resident bytes at snapshot time |
| `--start-time` | `S pid start_unix_us` | `startTimes` | `start_time` | process identity instant in Unix microseconds |
| `--cpu-time` | `C pid cpu_time_us` | `cpuTimes` | `cpu_time` | cumulative user + system time; CPU% is a consumer-side diff |
| `--uid` | `UID pid uid` | `uids` | `uid` | real uid; username resolution belongs to the consumer |
| `--cwd` | `CWD pid cwd_json` | `cwds` | `cwd` | current directory; JSON in the final TSV field preserves delimiters |
| `--status` | `STAT pid state nice threads` | `statuses` | `status` | one-character state, signed nice, nullable thread count (`-` in TSV) |
| `--argv` | `ARGV pid argv_json` | `argv` | `argv` | the full vector, distinct from the short name; JSON preserves tabs, newlines, and NULs |

Darwin's process table is public even when its task accounting is not.
`kern.proc` gives an ordinary caller pid, ppid, real uid, state, nice, start
time, and a short command name for foreign processes; `proc_pidpath` adds the
executable path, whose basename keeps long names from being cut to `p_comm`'s
16 bytes. RSS and cumulative CPU time still come from task APIs that return
`EPERM` across uid boundaries.<Footnote>`/bin/ps` looks unprivileged from the
shell, but the binary is setuid root and Apple signs it with the private
`com.apple.system-task-ports.read` entitlement. Its source calls
`task_read_for_pid` for the protected half ([reader](https://github.com/apple-oss-distributions/adv_cmds/blob/main/ps/tasks.c),
[entitlement](https://github.com/apple-oss-distributions/adv_cmds/blob/main/ps/entitlements.plist)).
So foreign `U mem` and `U cpu_time` rows are real blindness for an ordinary
osfacts binary, while `U proc`, `U uid`, and `U start_time` rows would be false
blindness.</Footnote>

Host `HCPU` rows add a nonempty model name and nullable MHz to the cumulative
per-core counters. The frequency is honestly absent on Apple Silicon rather
than represented by zero. `HDISK` carries both `freeBytes` (`bfree`) and
`availableBytes` (`bavail`) so the consumer chooses its used-space definition
without inheriting a hidden semantic change.

## Why not an existing tool

Every candidate was **measured, not surveyed**, and each fails on the contract
above rather than on packaging — a packaging gap is an errand, not an
architecture verdict.<Footnote>Earlier drafts listed "not packaged for darwin"
against osquery and "not in nixpkgs" against portls. Both struck: anything
merely absent from nixpkgs could be packaged in an afternoon, so packaging
never counts as a disqualifier.</Footnote> The repo README carries this same
table:

| candidate            | disqualifier                                                                                                                                                                                                                                              |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `osquery`            | **the wrong operational model**: a resident fleet-telemetry agent with a SQL surface, measured at ~378 ms per query and ~158 MB — built for querying thousands of machines every few minutes, not one machine every five seconds on a 10 ms budget         |
| `procs`              | **discards the bind address** — loopback and wildcard collapse to one row                                                                                                                                                                                 |
| `portls`             | no PPID, no process table — a listener cannot be walked back to its root                                                                                                                                                                                  |
| `rustnet`            | interactive capture TUI, needs packet-capture privilege                                                                                                                                                                                                   |
| `portview`           | **listener rows only, no process table** — a `shell → npm → node` server cannot be walked back to its terminal. No subtree scoping either: its single-port query is a host-wide scan plus a filter<Footnote>portview is also the strongest evidence *for* building this: it measures **9.9 ms on darwin** against our former C helper's 10.6 ms on the same box by the same method, in Rust, in a single pass. Single-pass Rust matches C — the language was never the constraint, the double enumeration was. That measurement is what settled osfacts on Rust.</Footnote> |
| `sysinfo`+`listeners` | wrapping the two crates enumerates the process list **twice**: 23 ms darwin / ~100 ms linux against 10 ms for a single pass — and `listeners` shipped the v4-mapped decode bug [we fixed upstream](https://github.com/GyulyVGC/listeners/pull/57)<Footnote>The ~50-line darwin address decode from that fix is vendored into osfacts with its regression fixtures; upstream is pinned in CI as a drift oracle. The repo README's Testing section owns the detail.</Footnote><Footnote>Disqualified as the process/socket *engine* — not banned outright. OSF7's darwin network counters use `sysinfo`'s network module (target-gated to macos, `default-features = false`, `network` feature only): one function, taken to delete an unsafe hand-computed `if_data` byte overlay after CodeQL flagged it — the same remove-a-defect-class clause that admitted `serde`. The measured disqualifier (a host-wide process double-walk) doesn't apply to a single sysctl read, and the live-oracle lane's monotonic-counter check is the drift detector for the dependency.</Footnote> |
| `lsof` / `netstat`   | `lsof` measured 93 ms; macOS `netstat` is **intermittently blind** — success and zero rows in one sampling window, 29 rows in the next, same boot                                                                                                          |

## Adoption — kolu and drishti

Inside kolu the OS used to be inspected in five places, each with its own
hand-rolled reader, its own error policy, and its own platform split — five
answers to one question. All five collapse into calls to the one binary, and a
full-source sweep confirmed the list is exhaustive.<Footnote>The sweep covered
every package including `@kolu/surface`. The one near-miss: `surface-remote`'s
`groupAlive` probe (`process.kill(-pid, 0)` — process-*group* liveness inside a
SIGTERM→SIGKILL escalation timer). Deliberately not a consumer: group liveness
is not in the fact set, and forking a snapshot binary inside an escalation
timer is the wrong operational model.</Footnote>

| consumer                                        | asks                                     | path                                                                                                                       |
| ----------------------------------------------- | ---------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| padi port scan                                  | a subtree's processes + listening ports  | **shipped** — `osfacts-client` (OSF2, <PrLink pr={1996} />); the C helper, TS `/proc` readers and `@kolu/port-scan` deleted |
| padi `memorySampler`                            | per-pid RSS                              | OSF3 — today only *self*-measurement plus an RPC hop to kaval                                                              |
| daemon supervisor                               | "is this pid still ours", and since when | OSF3 — today `kill(pid, 0)` liveness only                                                                                  |
| `socketHolder` (in `surface-daemon-supervisor`) | which pids hold a unix socket **path**   | OSF4 — today `/proc/net/unix` + fd readlinks; darwin `lsof`                                                                |
| **drishti**                                     | process inspection + host telemetry      | OSF3 · OSF6 · OSF7 — first attempt [srid/drishti#122](https://github.com/srid/drishti/pull/122)                            |

**Drishti's first adoption attempt hit two walls, and they named the missing
phases.** [srid/drishti#122](https://github.com/srid/drishti/pull/122) moved
process identity and listeners onto the contract, then deployment as an
ordinary SSH user turned red: 41 system processes came back readable as `P`
rows but `U … EACCES` for their fds, so every one of them rendered
listener-blind — honest, but useless for a whole-host inspector (OSF6). And
[srid/drishti#123](https://github.com/srid/drishti/issues/123) inventories the
native host-telemetry readers the contract doesn't cover at all — `/proc`
gauges, `vm_stat`, `sysctl`, `netstat -ib`, Node `os` calls, `statfs` (OSF7).

The later dropped-info audit found the quieter third wall: pid 1 is not a
portable synonym for the host process set (Linux's `kthreadd` tree is its own
root), and the first contract omitted uid, cwd, state/nice/threads, full argv,
CPU model/frequency, and `bfree`. PR <PrLink pr={2011} /> closes that set in
the same V2 contract. `osfacts-client` now exposes `snapshotHost` directly;
Drishti can delete its native readers without narrowing or sentinelizing the
facts it used to show.

### The phase tree — track prefix `OSF`

| phase                            | delivers                                                                                                                                                                                                              | needs             |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------- |
| **OSF1 — the binary**            | `snapshot --roots --procs --ports` on both platforms · versioned TSV + `--json` · the mandatory `unreadable` section · the scar-tissue suite — **shipped in <PrLink pr={1996} />**                                     | —                 |
| **OSF2 — kolu's port sensor**    | padi invokes the baked osfacts binary through `osfacts-client`; C helper, TS `/proc`, and `@kolu/port-scan` deleted — **shipped in <PrLink pr={1996} />**                                                              | OSF1              |
| **OSF3 — process detail facets** | `--mem` + `--start-time` + `--cpu-time` + `--uid` + `--cwd` + `--status` + `--argv`: kolu gains true per-pid RSS and start identity; drishti regains credentials, cwd, state/nice/threads, full argv, age, and cumulative CPU microseconds. The client adds a host-wide entry point so Linux roots outside pid 1 are not dropped — **shipped in <PrLink pr={2011} />** | OSF1              |
| **OSF4 — socket-holders**        | the second verb ships; `socketHolder` deletes its `/proc/net/unix` and `lsof` paths                                                                                                                                    | OSF1              |
| **OSF6 — unattributed listeners** | a listener no readable pid claims is *emitted* with explicit unattributed status (and its owning uid on linux) instead of dropped — the fix for #122's privilege regression — **shipped in <PrLink pr={2011} />**<Footnote>Linux already parses the world-readable `/proc/net/tcp{,6}` table — address, port, uid, inode — and today discards any LISTEN row no scoped fd readlink claims; emitting it is honesty, not new privilege. Two points the phase must pin: under a narrow `--roots`, an unclaimed socket may simply belong to an out-of-scope process, so the row says *unclaimed*, never *unowned*; and darwin's only fd-walk-free enumeration is the `pcblist` sysctl behind `netstat` — the source measured intermittently blind — so the silent-empty detection scar rides this phase.</Footnote> | OSF1              |
| **OSF7 — host facets**           | the `host` verb: load, memory + swap, uptime, per-core cumulative CPU with model and nullable MHz, per-interface cumulative counters, root-fs total/free/available bytes — drishti deletes its native telemetry readers ([srid/drishti#123](https://github.com/srid/drishti/issues/123)) — **shipped in <PrLink pr={2011} />**<Footnote>Semantics to preserve, per the issue: cache-aware available memory, swap used/total, cumulative per-interface byte counters, per-core CPU deltas, honest CPU metadata absence, and distinct `bfree`/`bavail` disk meanings. Cumulative per the creed — rates are consumer-side diffs between snapshots; the tool never sleeps.</Footnote> | OSF1              |
| **OSF5 — drishti & extraction**  | drishti's migration relands whole — every native reader deleted, fail-fast baked path — and the directory graduates to its own repo<Footnote>The directory moves wholesale: `osfacts/` already carries its own README, `default.nix`, a zero-input subflake, and `client-ts/` (`osfacts-client` — no `@kolu` scope, Node builtins only) precisely so extraction is a move, not a redesign. The subflake becomes *the* flake and the contract does not change.</Footnote> | OSF3 · OSF6 · OSF7 |

OSF3, OSF4, OSF6 and OSF7 are independent siblings under OSF1; OSF5 closes the
track. Each phase is a consumer deleting its own OS traversal, independently
revertible.

**Out of scope, deliberately:** foreground process (a PTY-fd fact — `tcgetpgrp`
on the pty, so it stays kaval's), anything requiring root — OSF6 is the best
honest answer *without* privilege, not an escalation — and any daemon/resident
mode. This is a one-shot sampler; if startup cost ever becomes the problem, the
answer is to revisit the operational model, not to hide it behind a resident
process. The same restraint applies outward: no TUI, no `kill`, no docker
verbs — the broad user-facing surface is what made `portls` and `portview`
wrong for embedding, and osfacts stays embeddable by staying narrow.
