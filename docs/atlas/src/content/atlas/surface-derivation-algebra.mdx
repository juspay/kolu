The derivation algebra ships in W5's phase-1 surface refactor. One idea: **a derived member is a declaration** — you state what it derives from and how; the framework owns the wiring, the seeding, the dedup, and the reconnect story. Ground trees for every `file:line` cite: kolu `origin/master`, drishti master. Two working words: a **tick** is one producer microtask flush (precedent: `createTickCoalescer`, `packages/surface/src/server.ts:281-312`), and each deriver owns its own flush; **the wire has no shared frame** — each member travels its own channel at its own latency.

## The problem, in one cell

padi's urgency cell is a pure function of the `terminals` collection — computed today by **five** write seams that must each call `publishUrgency` (`packages/padi/src/terminalEndpoint/metadata.ts:110-112`, called at `:104`), a separate removal-path refold (`:129-132`), a prose invariant (`:28-35`), and a separate boot seed (`servePadi.ts:180`). Forget one seam and the badge silently lies. The same hand-wiring repeats across both trees: kolu-server's onState cells (`packages/server/src/index.ts:842-853`), four samplers (`index.ts:881`, `index.ts:797-810`, `packages/padi/src/hostInventory.ts:331`, `packages/padi/src/memorySampler.ts:61`), the already-extracted `pipeSessionStateToCell` (`connectionPipe.ts:36-64`) with its private error policy, drishti's three poll reconciles in one function (`agent main.ts:262-330`) with a hand-held dedup (`main.ts:90-106`) and a hand delta bus (`main.ts:211-221`), and drishti's drifted registry clone (`packages/app/src/server/hostMapRegistry.ts`, clockOffset hardcoded `0`). The declaration idea deletes all of it.

## The lineage, in three names

The primitives already map onto reflex ([the attention primer's table](surface-attention-101.html); [why four primitives, not one](/surface/why-surfaces/#why-four-primitives-not-one)). `fmap`: a derived value is a function of another. `foldDyn`: a value is an accumulation, its carried state owned by the machinery. `Incremental`: a keyed map whose changes travel as patches. The appendix maps everything else.

## The combinators, from their hand-rolls

### `foldCollection` — the urgency fix

Declare the cell as a stateless fold of its sibling collection; every write seam arms the refold structurally.

```ts
/** Declare a cell as a STATELESS fold of a sibling collection in the SAME
 *  implementSurface deps. Wire semantics:
 *  - SEED: fold(readAll()) at wiring — current truth, never a default.
 *  - TRIGGER: foldCollection OWNS ITS OWN microtask flush (same shape as
 *    createTickCoalescer, server.ts:281-312), armed by the collection's
 *    WRAPPED upsert/remove (server.ts:1585-1600). It does NOT share the
 *    deltas coalescer: that coalescer exists only when the collection opts
 *    into `deltas` (server.ts:1526-1542, collectionHasDeltas
 *    define.ts:229-235), and the headline consumer's terminals collection
 *    declares verbs ["keys","get"] (padi surface.ts:606) — no deltas, no
 *    coalescer. Every write seam — including removals — arms the fold
 *    structurally; "no seam decides" stops being prose.
 *  - PUBLISH: through the cell's equals/onWrite/store.set/bus.publish
 *    path; dedup at the cell's spec equals (urgencyEqual stays).
 *  - RECONNECT: an ordinary cell — store snapshot then deltas.
 *  - FAIL-FAST: a throwing fold escapes the flush and crashes the process.
 *  - ONE WRITER: the boot check rejects mutation verbs incl. test__set.
 *  `from` is boot-checked; unknown sibling key throws at wiring. */
export function foldCollection<K, T, V>(opts: {
  from: string; // sibling collection key in the same spec
  fold: (entries: ReadonlyMap<K, T>) => V;
}): DerivedCellDeps<V>;
```

Dies: `publishUrgency` and its calls (`metadata.ts:110-112`, `:104`), the removal refold (`:129-132`), the prose invariant (`:28-35`), the separate seed (`servePadi.ts:180`). Survives: `recomputeUrgency` (`urgency.ts:23-38`) as the `fold`; `urgencyEqual` (`servePadi.ts:179-182`, `urgency.ts:44-50`) on the spec.

### `observableSource` and `pollSource` — the sources, named

Frames arrive two ways — pushed by a callback, or read on a tick. Two adapters turn both into the one upstream shape every deriver accepts (`UpstreamSource`, `project.ts:109-112`).

```ts
/** Adapt a callback/push observable into the ONE upstream shape every
 *  deriver accepts (UpstreamSource, project.ts:109-112). `install` runs
 *  once per subscription; uninstall on abort. NO snapshot synthesized — a
 *  push-only source's first frame arrives when the source speaks; until
 *  then a derived cell holds its `initial` (the one writer's declared
 *  default). */
export function observableSource<F>(
  install: (emit: (frame: F) => void) => () => void,
): (opts: { signal?: AbortSignal }) => Promise<AsyncIterable<F>>;

/** Poll-on-event upstream for CELL-shaped derivations — the cell twin of
 *  the stream {read, install} deps (server.ts:1171-1199), REUSING
 *  pollOnEvent's scheduling (server.ts:540-561). First frame = read() (a
 *  genuine snapshot); then re-read per event tick. NO isEqual — dedup is
 *  the target cell's spec `equals`, the algebra's one gate (pollOnEvent's
 *  stream-side isEqual exists only because streams HAVE no spec gate).
 *  `onReadError` default = stderr; initial-read errors always propagate
 *  (no snapshot yet ⇒ nothing honest to serve); later read failures follow
 *  the stateless-pump rule: log, skip, keep polling. */
export function pollSource<F>(opts: {
  read: () => Promise<F>;
  install: (onEvent: () => void) => () => void;
  onReadError?: (err: unknown) => void;
}): (opts: { signal?: AbortSignal }) => Promise<AsyncIterable<F>>;
```

Dies: the `padiSession.onState` hand-wire (`index.ts:842-853`) becomes two derived cells over one `observableSource` (`mapConnectionToPadiLink`, `padiLink.ts:37-49`, survives as the map); `pipeSessionStateToCell` (`connectionPipe.ts:36-64`, live via `hostFanout.ts:191`) becomes `deriveCell(observableSource(...), projectConnection, DEFAULT_CONNECTION)` — `seedConnectionCell` stays (a seeded store is legitimate deps), and its catch-and-keep-consuming (`connectionPipe.ts:53-63`) is **promoted** into `deriveCell`'s per-frame policy, one law where three spellings lived; the four samplers (`index.ts:881`, `index.ts:797-810`, `hostInventory.ts:331`, `memorySampler.ts:61`) become `pollSource` declarations, none growing a local isEqual.

### `scanCell` — when the fold needs memory

drishti's W5 alerts hysteresis ("crossed 80 to raise, fell below 70 to clear") is undecidable from the current sample — carried state — and is the **committed** consumer: both W5 phases ship as one campaign under the paired-PR rule (`.claude/rules/surface.md`). Durability is a visible choice: padi's MRU feed passes its Conf-backed store (`servePadi.ts:213-218`) and resumes across restarts; alerts passes none, because an alert level must not survive a restart.

```ts
/** Fold an upstream's frames through carried state into a cell. Rides the
 *  cell `connect` seam (server.ts:1120, fired at 1493-1494); every step
 *  result flows through equals/onWrite/store.set/bus.publish — dedup is
 *  the target cell's spec equals, nothing else. accumMaybe semantics:
 *  return the previous state reference to publish nothing.
 *
 *  DURABILITY: the pump seeds carried state from `opts.store` when given.
 *  The store is a constructor argument, not a widened runtime seam: the
 *  deriver constructs and returns the deps INCLUDING the store (a
 *  construction-time fact), and CellStore.get() is synchronous
 *  (server.ts:77-80), so the seed happens at wiring with no window in
 *  which the pump folds over a default and a late read clobbers it.
 *  servePadi passes its Conf-backed activityFeed store
 *  (servePadi.ts:213-218) here; a restart resumes the MRU instead of
 *  clobbering it on first fold. A scan whose state must NOT survive
 *  restarts passes no store — the choice is visible in the declaration.
 *
 *  Error policy (statefulness line): a throwing `step` → onError (default
 *  stderr) + pump STOPS holding last state; pump death → same. Abort-shaped
 *  rejections swallowed (isAbortReason, server.ts:1060).
 *
 *  Demand: drishti's alerts hysteresis scan is a committed simultaneous
 *  consumer — both W5 phases ship as one campaign under the paired-PR rule
 *  (.claude/rules/surface.md) — and scanStream + deriveCell are
 *  implemented on this one loop (one teardown/abort/error home).
 *  deriveCell(u, map, i) ≡ scanCell(u, (_s, f) => map(f), i) — with the
 *  stateless specialization keeping the continue-on-frame-error policy. */
export function scanCell<F, S>(
  upstream: (opts: { signal?: AbortSignal }) => Promise<AsyncIterable<F>>,
  step: (state: S, frame: F) => S,
  initial: S | ((stored: S | undefined) => S), // stored = opts.store?.get()
  opts?: { store?: CellStore<S>; onError?: (err: unknown) => void },
): DerivedCellDeps<S> & { dispose: () => void };
```

padi's activityFeed (`activity.ts:73-101`) adopts this only if `trackRecentRepo`/`trackRecentAgent` become emitter publishes (open question 5) — they are synchronous, so the buy is one-writer structure, not a race fix. Regardless of timing: the read-path back-write (`activity.ts:50-57`, a getter that writes) is a second writer and gets fixed.

### `scanStream` — a time series with an honest snapshot face

drishti's metric ring needs catch-up: snapshot so far, then live deltas. The hand-roll snapshots **first** and subscribes **after** (`router.ts:198-208`), so a delta born in the gap is lost until reconnect; the framework's `subscribeBeforeSnapshot` (`server.ts:350-363`) closes that window.

```ts
export type ScanMsg<S, D> =
  | { kind: "snapshot"; state: S }
  | { kind: "delta"; delta: D };
/** One wire authority for the scan frame — the stream twin of
 *  collectionDeltasSchema (define.ts:274-287). */
export function scanMsgSchema<S, D>(
  state: ZodType<S>, delta: ZodType<D>,
): ZodType<ScanMsg<S, D>>;
/** ONE process-lifetime pump owns the state: step(state, frame) →
 *  {state, delta}; each delta publishes on an internal channel. EACH wire
 *  subscriber gets subscribeBeforeSnapshot(bus, signal, () => [{kind:
 *  "snapshot", state}]) (server.ts:350-363) — subscribe-BEFORE-snapshot
 *  closes the lost-update window a hand-rolled snapshot-first pump has
 *  (a delta born in the gap is lost until reconnect). Fail-fast: step
 *  throw → onError + pump stops holding state (stateful rule);
 *  subscribers see silence, never fabricated frames. Dedup: none by
 *  design (a time series appends). Consumers: drishti's metric-history
 *  ring, including the W5 alerts campaign's ring. */
export function scanStream<F, S, D>(opts: {
  upstream: (o: { signal?: AbortSignal }) => Promise<AsyncIterable<F>>;
  step: (state: S, frame: F) => { state: S; delta: D };
  initial: S;
  onError?: (err: unknown) => void;
}): StreamHandlerDeps<void, ScanMsg<S, D>> & { dispose: () => void };
```

Dies: the hand ring + bus (`router.ts:108-117`), the snapshot-first subscribe (`router.ts:198-208`), and the sink fusing `system.set` with `recordSample` (`router.ts:279-289`). Survives: `recordSample` (`router.ts:241-245`) as the step, `pushSample` (`common/history.ts:94-103`) as pure logic.

### `pollCollection` and `CollectionSpec.equals` — the most-repeated hand-roll

Poll a keyed source, diff against what you serve, upsert changed, evict vanished — drishti's agent does it three times in one function (`main.ts:262-330`), and kolu's teaching examples hand-roll it four more (fleet-top parts 1–3: `src/server/top.ts:91-102`, `src/daemon/top.ts:93-96`, `src/agent/top.ts:93-96`; remote-process-monitor `src/agent/main.ts:167-187`).

```ts
/** Poll a keyed external source, diff against the served snapshot, upsert
 *  changed keys, evict vanished ones — through the wrapped publishers (the
 *  collection connect seam), so per-key subscribers, keysBus membership
 *  dedup (broadcastKeys, server.ts:1584) and, where the `deltas` verb is
 *  declared, the tick coalescer all fire from ONE declaration.
 *
 *  Wire semantics per tick:
 *  - read() → next: ReadonlyMap<K,T>.
 *  - For each [k, v] in next: publish upsert(k, v) — the per-key gate is
 *    the TARGET COLLECTION's spec `equals`; pollCollection carries NO
 *    equality predicate of its own (the diff's equality IS the member's
 *    declared equals, one visible gate). With no equals declared the gate
 *    defaults to Object.is per key — freshly-allocated equal values
 *    republish, which is the honest default (drishti's networkInterfaces
 *    deliberately upserts unconditionally) and the incentive to declare
 *    equals (drishti's processes declares its MUTABLE_PROCESS_FIELDS-based
 *    predicate as the spec equals in the paired PR).
 *  - For each served key not in next: remove(k). remove-then-upsert-equal
 *    within one tick still publishes (membership changed; last-op-wins
 *    pending map, server.ts:284-311).
 *  - Deltas verb declared ⇒ one coalesced {upserts,removes} frame per
 *    tick, subscribe-before-snapshot on the framework path.
 *  - First tick runs immediately (populate within one scan); read failure
 *    after the first successful tick follows the stateless-pump rule (log
 *    via onReadError, skip tick, keep polling); a failing FIRST read
 *    propagates (nothing honest to serve). */
export function pollCollection<K, T>(opts: {
  read: () => Promise<ReadonlyMap<K, T>>;
  install: (onTick: () => void) => () => void; // cadence owner: interval, event, or both
  onReadError?: (err: unknown) => void;
}): CollectionFamilyDeps<K, T> & { dispose: () => void };

// CollectionSpec.equals — ships with pollCollection (live demand:
// drishti's processChanged, agent main.ts:90-106):
interface CollectionSpec<K, T> { equals?: (a: T, b: T) => boolean }
// Gates the wrapped upsert's per-key publish AND coalescer enqueue
// (server.ts:1585-1600), mirroring the cell gate (server.ts:198-207).
// remove-then-upsert-equal within one tick still publishes (membership
// changed; the last-op-wins pending map already models this).
```

Dies: `processChanged` as a hand-held write-site dedup (`main.ts:90-106`) — it becomes the processes collection's spec `equals`; the hand `snapshotDeltaBus` + `processesSnapshot` stream (`main.ts:211-221`, publish at `:295`) — the collection already declares the `deltas` verb (`common/surface.ts:249`) and the framework path serves the same wire shape without the lost-update window; the seven hand-rolls rewrite on the declaration. Paired-PR consequence: drishti's agent-written collections expose wire `upsert`/`delete` today (`common/surface.ts:249, 258`); as derivation targets the boot check rejects those, so the pair narrows them to `["keys","get","deltas"]` — one-writer becomes wire-true for drishti too.

### The boot checks — what becomes unspellable

**One writer.** `implementSurface` rejects, at wiring, any derived member whose resolved verbs (`resolveCellVerbs` `define.ts:206` / `resolveCollectionVerbs` `define.ts:223`) include `set`, `patch`, `upsert`, `delete`, or `test__set` (`define.ts:54`, `:260-261` — a wire mutation like any other); tests reset a derived member by writing its source. Non-derived cells are exempt: padi's `session` (`surface.ts:595-599`, verbs `["get","test__set"]`) keeps its named imperative writers.

**No declared cycles.** The `from`-declared sibling graph (`foldCollection` / `combineCells` / `gateEvent` / `scanCollection`) is walked at wiring; a cycle is a boot error. Free-form upstreams (`scanCell` over an arbitrary iterable) are invisible to the walk; their documented semantics are **equals-gated fixpoint termination** — a value-converging loop quiesces at the equals gate, a non-converging one is a declared-graph bug (livelock). Reach: open question 10.

## The laws, stated once

1. **One writer.** A derived member with a second writer is two authorities racing — the urgency disease. Wire-read-only, boot-enforced, `test__set` included.
2. **Dedup solely at the target member's spec gate** — cell `equals` (`server.ts:198-207`, `1469-1474`) or collection `equals` (phase 1). A private predicate inside a deriver would be a second, invisible gate; `pollSource` and `pollCollection` carrying none is the rule applied.
3. **Snapshot-then-delta everywhere.** A derived member is indistinguishable from an ordinary one: cell store replay; `subscribeBeforeSnapshot` for scan streams; the collection deltas snapshot.
4. **Seed from truth.** [Mirrors never fabricate](surface-attention-101.html) — a fold starting from a default publishes a value nobody asserted. Only push-source holds use the declared default, the one writer's property.
5. **Fail-fast, on the statefulness line.** A **sync in-tick fold** that throws is a producer defect mid-flush: it escapes and **crashes**. An **async stateless pump** (`deriveCell`, `registryFromFamily`'s `resolve`, `pollCollection`'s tick read) logs the frame's failure and **keeps consuming, holding the last published value** — frames are independent, the next one self-heals, nothing is fabricated by continuing. An **async stateful pump** (`scanCell`, `scanStream`) **stops, holding last state** — its carried state missed a frame, so continuing would fabricate. `onError` defaults to stderr, never invisible. `deriveCell` (`project.ts:236-280`) splits accordingly: pump death → stop holding last value (a dead iterator can't be consumed); per-frame failure → skip and continue. Escalation of a stopped stateful pump is open question 7.

## What the wire refuses — no shared frame

Per-member channels share no frame, so "at the same moment" is unsayable — and that one fact decides the whole absent family. **Switching** (`switch`/`switchHold*`/`coincidence`/Dynamic `join`): a switching occurrence must carry an Event as its value, but a wire frame is Zod-schema'd data (`define.ts:245-265`); the only serializable stand-in is a channel handle — a capability with dead epochs after reconnect, no definable snapshot obligation, and a second writer on "which stream is current"; and the promptly trichotomy needs the shared frame that isn't there. What survives is first-order: the switching **index travels as data** (a per-key `get` held open on an absent key is `switchHold never`'s idle state, `server.ts:382-417`) and the client re-subscribes — `scopedByEntry` (`scoped.ts:81-210`) is the switching machinery. **Cross-channel combines** (`Align`/`Zip`/`Apply`, `difference`, wire `zipDyn`, wire `attach`): simultaneity-defined, so intersection is meaningless and every union collapses to interleave (`mergeSources`, deferred); same-process combines are legal (`combineCells`, deferred), client pairing is a Solid memo. The same fact retires `tagPromptlyDyn`: folds always see the post-write value (`store.set` precedes `bus.publish`, `server.ts:198-207`) — uniformly "promptly", no old/new distinction left to spell. Briefly: `PushM`/`PullM` — the server process is the monad; `*Cheap` — a Haskell pull-graph perf contract with no analog; `Query`/`crop`/`SelectedCount` — per-member subscription + AbortSignal already is the query (revisit at range/viewport subscription over a large collection); `maybeDyn`/`factorDyn`/`demux` — client memos and Solid `<Show>`/`<Switch>`.

### Deferred — cataloged, trigger named

### The open questions

The calls still open — what a review of this note rules on.

1. **Typed sibling references.** `foldCollection`/`combineCells`/`gateEvent`/`scanCollection` name siblings by string key, boot-checked (existence + verbs + cycles). Compile-time `from` means threading `keyof` through the deps builder — the second type materialization `projectSurface` avoids for TS union-budget reasons (`project.ts:288-290, 62-72`). Is boot-time throw enough, or is a keyof-only generic affordable?
2. **The tick — refold suppression.** `foldCollection` owns its flush. With `CollectionSpec.equals` in phase 1, should a flush in which *every* same-tick upsert was equals-suppressed skip the refold entirely, or is one spec-equals-gated cell publish per armed tick cheap enough? Measure on the ~150ms composed-terminals firehose before adding the skip.
3. **`scanCell` durability — migration.** The signature is fixed (store param; seed from `store.get()`); the remaining question is version skew: a persisted `S` whose shape changed across a deploy. Does the `initial(stored)` function form (caller-owned migration/validation, fail-fast on unparseable) suffice, or do persisted scans need a declared versioned-migration seam?
4. **The `registryFromFamily` wrapper's home.** The combinator deletes serveHostMap's cache/fire/reconcile and drishti's clone; `causeFor` enrichment (`serveHostMap.ts:109-113`), the #1716 belt (`:259-265`), and `offsetOf` injection (`:40-44, 85-95`) compose into `resolve`. Does the composed wrapper stay in surface-remote (shared with drishti), or does drishti import only the projection? Either kills the clone; the package boundary needs an electricity-test ruling.
5. **The activityFeed restructure.** `scanCell` subsumes padi's activityFeed only if `trackRecentRepo`/`trackRecentAgent` become emitter publishes — is that churn worth it now, or does it wait, with only the read-path back-write (`activity.ts:50-57`, a mutating read) fixed immediately?
6. **The metadata write-seam collapse.** The connect seam ships with `pollCollection` regardless. Does padi's registry expose the one `onChange` that collapses the five `publishComposedTerminal` seams, or does that path keep its convention with only the urgency rider deleted?
7. **Fail-fast — visibility of a stopped stateful pump.** The doctrine line is ruled (sync in-tick = crash; async stateless = log-skip-continue; async stateful = log-stop-hold). Remaining: should a *stopped* stateful pump escalate beyond stderr — e.g. flip the liveness gate (`define.ts:143`) so the freeze is visible on `health()` — given the history with frozen-but-live-looking members (#1034)?
8. **Cross-surface zip.** Hard-rule it client-side forever (no transactional frame on the wire), or leave the deferred `combineCells` open to a cross-surface variant with documented eventual consistency if demand ever names one?
9. **`scanMsgSchema` vs `collectionDeltasSchema`.** Unify `ScanMsg` with `CollectionDeltasMsg` (a keyed scan is a collection; an unkeyed one isn't) or keep distinct authorities? Unifying lets `scanStream` consumers reuse the collection client fold; it also blurs "collection = keyed, patchable" (`define.ts:75-87`) for a member with no keys.
10. **The cycle rule's reach.** The boot cycle check covers only `from`-declared edges; `scanCell` over an arbitrary upstream iterable is invisible to it. Is "equals-gated fixpoint termination + a documented livelock-is-a-bug rule" enough for the free-form subset, or should scanCell-over-a-sibling-cell get a declarative `from` spelling so its edge joins the checked graph?
11. **`pollCollection` cadence composition.** `install` owns the cadence (interval, event, or both — drishti wants interval + immediate first tick; kolu's samplers want event-triggered resample). Is one install seam enough, or do interval-and-event-fused cadences deserve a tiny shared helper so each caller doesn't re-spell "setInterval + onState + fire now"?
