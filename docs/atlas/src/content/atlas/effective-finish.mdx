An agent (Claude Code is the motivating case) can mark its turn **waiting** while
background sub-agents still emit bytes. Raw `waiting` in `finishedIds` is then a
**premature** finish — chime and host-tab mark before the work actually stopped.
The fix is not a second byte-tap state machine in padi. It is:

1. **kaval** reports *meaningful* PTY output (resize repaints excluded at the source),
2. **padi + client** cut over live-dots onto that fact in **one** PR (no dual path),
3. **padi** pure-folds finish from the same edge + waiting episode stamps.

Work items use the **EF** track prefix (new; no Atlas collisions). <PrLink pr={1938} />
closed without merge — design kept, big-bang delivery discarded. This note is the plan
of record; master stays on raw-`waiting` finished until **EF2**.

## The problem

| Symptom | Cause |
| --- | --- |
| Premature “finished” | `finishedIds` = raw agent `waiting` <Cite file="packages/padi/src/urgency.ts" /> |
| Visit finished tile → re-chime | First #1938 design made finish byte-reactive; client resize mute did not travel to padi taps |
| Sticky “all terminals live” | #1938 Phase D stored a Solid **reconcile proxy** as `prev`; removals never applied |

Attention already has one model (<Cite file="docs/atlas/src/content/atlas/agent-attention.mdx" /> / <PrLink pr={1931} />).
This note only makes the **finished** half of that model honest — and, as a
prerequisite, makes **activity** a single source of truth.

## End state

### Facts (one writer each)

| Fact | Writer | Clock |
| --- | --- | --- |
| Meaningful output edge `{ id }` | kaval `onData` funnel (not resize-muted burst) | n/a on the wire |
| `lastMeaningfulArrivalAt[id]` | folding **padi**, on edge **arrival** | padi wall clock |
| `enteredWaitingAt[id]` | padi, on agent-bucket enter `waiting` | padi wall clock |

Never ship kaval absolute timestamps for the fold — the attention model is
recency-free (“nothing cross-host ever compares two hosts' clocks”). Edge on the
wire; stamp at the folder.

### Pure finish fold

```
finished(id) =
  active ∧ bucket = waiting
  ∧ enteredWaitingAt ≠ null
  ∧ now − max(enteredWaitingAt, lastMeaningfulArrivalAt ?? enteredWaitingAt)
      ≥ EFFECTIVE_FINISH_QUIET_MS   // ~5s
```

- **ASKING** (`awaiting_user`) stays **ungated** — blocking, fires at once.
- **Default-excluded** — missing/late stamps only *delay* a finish.
- **Deadline wake** for the “stayed quiet” non-event (timer at next crossing).
- No settle set, no attach observer, no six parallel maps.

### Live activity (same edge, short window)

- Short window: `TERMINAL_IDLE_AFTER_MS` (~1s).
- padi `activity` stream = live id set; client mirrors it for dock/title dots.
- Client **must** copy frames to plain arrays before set-diff (`prev = [...frame]`),
  never hold the store proxy from `reconcile`.
- **No dual path:** after EF1, no padi byte taps for activity, no client
  `noteOutput` / resize-suppress hack.

### What kaval does *not* own

Quiet **windows** (5s finish vs 1s live-dot) stay **consumer policy**. Kaval owns
**which bursts count** (resize-aware filter + throttle), not a single live/quiet
boolean with one internal timer.

## Why not “edge only, consumers later”?

Shipping a kaval stream with **nothing** product-facing on it leaves the old
mechanism in place (padi taps, client attach counters). That is a half-baked dual
path: untestable end-to-end, two truths for “is live,” and a second PR tax to
finish the cutover. **EF1 is one volatility axis — activity ownership — cut over
completely.** Finish is a *different* axis (attention policy) and stays **EF2**.

## Anti-patterns

| Do not | Why |
| --- | --- |
| Dead kaval wire + old padi/client paths left in place | Half-baked dual mechanism; untestable; second PR tax |
| One PR = activity cutover **and** finish fold | Two volatilities; #1938 failure mode (bugs mask each other) |
| Quiet **boolean** with one window in kaval | Complects producer with consumer policy |
| Absolute kaval time for the fold | Breaks recency-free / invites cross-host compare |
| Delete client activity tests in the mirror cutover | Sticky-live shipped silent |
| Ship EF2 without a visit/re-open fence | Known regression class |
| Call the pure fold a “gate v2” and claim deletion | Reviewers cannot tell the machine is gone |

## Minimal hotfix (only if on fire)

If premature finish must land before EF1–EF2: a **sticky-per-waiting-episode**
finished membership (bytes cannot eject until leave-waiting) weakens “resume
after long pause” and is **not** the plan of record — stopgap only, then still
run EF1→EF2.

## Relation to attention

[Agent Attention](agent-attention.html) owns the **rules** (fire once, seen,
host-tab, dock). This note owns (1) **one activity fact** end-to-end and (2) the
**truth of finished** before those rules run. After EF1, live dots tell the truth
about output; after EF2, `finishedIds` means effective quiet.
