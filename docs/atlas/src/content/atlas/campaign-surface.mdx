## Why: the scribe problem

Running kolu's own development as a multi-agent campaign currently uses three
disconnected artifacts:

1. **Atlas notes** — the plans and reasons (this knowledge base). Correct as
   authored, durable files.
2. **The orchestrator dashboard** — a JSON file (`orchestrator-data.js`) the
   coordinator agent *hand-writes after every event*, rendered by a static
   HTML skill asset.
3. **The chat bot** (pesu, per [kolu under any chat app](chat-native-agents-and-kolu.html)) —
   planned to render a "who-needs-me board" into a thread.

The dashboard violates kolu's own philosophy twice. The philosophy says the
interface is **auto-detected, zero setup** — *"kolu builds its interface by
observing what users already do… rather than requiring configuration"* — and
that facts like *branch/PR/CI status derive from the terminal's current
working directory*. The hand-written dashboard is configuration wearing a
trench coat: it duplicates state the daemons already observe, so it drifts
(the board goes stale, notes disagree with the board, links break when
terminals re-key), and keeping it honest required a Stop hook whose only job
is to nag the scribe. **The disease is that a derived view is hand-authored;
every sync pain is a symptom.**

The fix is the split the chat-native note already names: **observe flows out
raw; act flows in through one door.** Applied fully:

| Layer | Carries | Authored or observed |
| --- | --- | --- |
| **Atlas note** | the plan: phases, design, rationale, post-mortem | **authored** — deliberately, once |
| **Board** | the state: which lane is where, right now | **observed** — derived at view time, written by no one |
| **Chat thread** | the same board, socially | **mirrored** — rendered from the board, never a copy |

The join needs no configuration because the campaign already follows one
naming convention: **a lane's worktree = its branch = its PR**, and a
design-bearing lane's branch names its note slug. A convention the
coordinator already works by — exactly the shape of "recent repos track `cd`
events": the system observes what the workflow already does.

## The Board — a third right-panel tab

The right panel today has two tabs: `inspector` and `code` (the wire schema
literally says `activeTab: "inspector" | "code"`). The Board is the third —
campaign state where the campaign runs, beside the terminals it describes.

Everything in that mock is **already observed** by the running system, today:

| Element | Source (existing) |
| --- | --- |
| the lanes | kolu's terminals; each terminal's cwd names its worktree |
| the colored dot | padi's agent sensors — working / asking-you / idle (the `padi-tui wait` buckets) |
| the sub-line | the same sensors' detail (which agent, what state, how long) |
| worktree → branch → PR chip | the cwd→branch derivation the README names, joined to the forge PR for that branch<Footnote>The server already derives branch/PR/CI status from a terminal's cwd for the terminal chrome — the Board reuses that machinery, it does not add a second poller.</Footnote> |
| CI chip | the same PR's checks |
| ▤ note chip | branch name ↔ note slug (the naming convention); links into the Code tab |
| shipped | PRs whose branch had a lane, now merged — an archive nobody curates |

**Nobody writes any of this.** The coordinator dispatching a new lane =
creating a worktree and a terminal — which is what makes the lane *appear*.
A PR merging is what flips its chip. An agent finishing is what turns its
dot. The board cannot be stale because there is nothing to update.

## The note side: phases declared, status resolved

A note keeps owning the **structure** — what the phases *are* — but stops
hand-stamping outcomes. `PrLink` (and a small `PhasePill`) resolve the live
PR state at render time in kolu's Code tab:

## The flows

**Dispatch.** The coordinator (the act door — unchanged) cuts
`worktree = branch = lane`, creates a terminal in it, and briefs the agent.
The lane appears on the Board by observation. Zero writes.

**Attention.** An agent flips to *asking-you* → its dot turns amber and the
who-needs-me strip counts it → the notify seam pings (desktop today; the
pesu thread tomorrow — same seam, per the chat-native note). You click the
lane → you are **in the terminal** (the depth kolu owns). Answer, step out.

**Reading the plan.** Every design-bearing lane shows its ▤ note chip →
Code tab opens the note → the note's phase pills show live outcomes. One
click from "what is happening" to "why".

**Shipping.** A PR merges (the human merges — unchanged). Its lane's chip
flips to merged; the note's pill flips identically; the lane retires to
*shipped* when its terminal closes. Nobody announces anything.

**Chat.** pesu renders **this same board** into the thread on demand and
pings on the attention flow — the "mirror of the coordinator" already
specified in the chat-native note. It gains a data source instead of needing
one invented.

**What stays conversational (deliberately off-board).** Gate rulings, CI
venue arbitration, box leases — coordinator knowledge with no observable
substrate. They live in the dialogue and in notes *as decisions*, not on the
board *as state*. Putting them on a board is what created the scribe.

## What this deletes

- `orchestrator-data.js` and the same-turn-update ritual
- the static dashboard HTML skill asset
- the board-freshness Stop hook (#1888) — enforcement of a duty that no
  longer exists
- hand-stamped statuses inside notes (and their drift)
- terminal-UUID note links that die on re-key — the Board links notes
  first-class

## Phases

| Phase | Scope | Deletes |
| --- | --- | --- |
| **P1 — live pills** | `PrLink`/`PhasePill` resolve PR state at render time in the Code tab's note view (small; client + a cached forge lookup) | hand-stamped outcomes in notes |
| **P2 — the Board tab** | a derived campaign collection on the server (terminals ⋈ worktree ⋈ branch ⋈ PR ⋈ CI ⋈ agent-sensor state — reusing the existing cwd-derivation machinery) + the right-panel tab rendering it | the dashboard file, its HTML, hook #1888 |
| **P3 — the thread mirror** | pesu renders the Board + attention pings (the chat-native note's own plan, now with its data source shipped) | nothing — it completes the picture |

<Callout kind="warn" title="Philosophy check">
  Every element must pass the two-principle test: **agent-agnostic** (the
  Board watches terminals and forges — it wraps no agent, and a lane running
  codex or opencode renders identically) and **auto-detected, zero setup**
  (if a Board element needs someone to *write* state for it, it is designed
  wrong — redesign it to observe, or move it to a note as a decision).
</Callout>
