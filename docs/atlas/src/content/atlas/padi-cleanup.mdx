### L26 — kill the overloaded null/sentinel hacks (fix + lint, one PR)

*Status: implemented — DRAFT PR, srid merges · Lens: architecture-first-principles (illegal-states-unrepresentable) + hickey (a null doing two jobs complects two states) · Gate: none (kolu-internal; any `@kolu/surface*` hit is drishti-gated)*

**Outcome (the sweep governs the verdict).** A five-agent repo-wide sweep — prioritizing padi, the server re-serve/session surfaces, `surface-daemon-supervisor`, and the client — read ~40 nullable/sentinel/optional sites *in context* and classified each. The finding is honest and uniform: **zero overloaded nulls remain anywhere in the tree.** The class L26 was born to kill was already retired by the very surface-hosting + padi refactors that spawned this entry — the code now narrates its own prior de-overloadings (`ProcessMemory` three-arm union, `KavalProbe` honest-null, `RestoreTarget`, `Known<T>`, and `SurfaceIdentity` itself). So the FIX half was satisfied by prior work; **the deliverable is the guardrail** (the `no-overloaded-null` code-police rule) that stops the class from regressing — exactly the "guardrail that stops it regressing" this entry always framed as the second half. No `@kolu/surface*` hit surfaced either, so there are **no drishti-gated proposals** — that family is where the exemplar was minted and is already clean. This is *not* a blanket anti-null crusade: a single-meaning "absent" is fine and was left alone.

Born from the surface-hosting-simplify debate (2026-07-05): the `SurfaceIdentity` design first used `identity(): T | null` (null = no link) AND `baked: T | null` (null = no build) — **two nulls, two meanings, a reader guessing which** — plus `commit: string | null` conflating dev-mode with a real commit. srid's rule: **a nullable or sentinel that carries more than one meaning is a defect** — replace it with a discriminated sum so every state is a named `kind` the reader must branch on, and impossible states can't be constructed. The identity type became `{ kind:"disconnected" } | { kind:"anonymous"; … } | { kind:"identified"; … }` with a `BuildCommit = { kind:"commit"; sha } | { kind:"dev" }` sub-sum — zero nulls.

**One PR, two halves — the fix and the guardrail that stops it regressing:**

- **Sweep + fix.** Find the same smell repo-wide (prioritize the daemon/session/convergence surfaces: padi, surface-daemon-supervisor, the re-serve). Known seeds the debate surfaced: the L3 convergence kit's `buildId === ""` = "off-nix" sentinel is being killed by the surface-hosting PR itself (srid ruled it must not survive the identity refactor) — so it is NO LONGER an L26 seed; L26 sweeps the *other*, scattered `null`/`""`/optional-as-state instances; any `X | null` where `null` answers two different questions (absent-vs-error, disconnected-vs-empty, not-yet-vs-never).
