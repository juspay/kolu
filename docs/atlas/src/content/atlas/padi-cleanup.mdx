**The cleanup track's scope, as a living ledger** *(unnumbered — it runs in parallel with the numbered phases; srid de-phased it 2026-07-05)*. W2 and W3 ship at pace — a deliberate call. This note holds what that pace defers: refactors, decomplecting, framework-level electricity upstreaming, and deletions. Nothing here is user-visible; that is the point. Every entry names its **lens** (why it's structurally wrong today — [hickey](https://github.com/srid/agency) = things braided together that change separately; lowy = code living on the wrong side of a volatility boundary), its **gate** (what must be true before it's workable), and a **done-when** an implementer can't satisfy by the easy route.

<Callout kind="note" title="How to execute (the working protocol)">
The track ships as a **few substantial refactor campaigns** (srid, 2026-07-09: fewer, deeper refactors — not thirty tiny PRs). Each campaign is one genuinely deep, coherent refactor of one area, **one PR on a fresh branch off master**, that absorbs its L-entries *as side effects of doing the area properly* — an entry is never the unit of shipping, only of scope-accounting. One commit per coherent move inside the PR keeps review clean; a pure-motion move (renames, file moves) is its own commit so rename detection reviews it. The implementing agent: (1) reads each absorbed entry plus the files it names — the entry gives the shape, the code gives the truth; if they disagree, **message the coordinator before proceeding** (kolu terminal `c769cfcd`, two-step send: `kaval-tui send c769cfcd "<msg>"` then a separate `--key Enter`; prefix `[Lx]`); (2) honors the campaign's gate — a `drishti` gate means paired srid/drishti PRs green against final kolu HEAD per `.claude/rules/surface.md` (a campaign bundles ALL its drishti-gated moves under one coordination); (3) never merges — undraft + summary, srid decides. UX must be byte-identical for every campaign (no-pixel-delta is the track's invariant); the e2e suite + the seal test are the net. The invariant's dual is the sorting rule: **a feature — any user-visible behavior change — never rides a refactor campaign**; it ships as its own PR (L24 is the ledger's one instance).
</Callout>

### L28 — `clockNow` graduates to a framework-reserved member *(rung 1's dedup landed inside W6; rung 2 is what remains)*

*Status: rung 1 SHIPPED inside W6's pair (merged 2026-07-09); rung 2 absorbed by **campaign 1** (complete the primitives) · Lens: lowy (the clock requirement is framework electricity stranded in padi's app-level control core) · Gate: drishti pair PR (surface/surface-remote API touch) — the campaign's own pairing covers it*

This is the old "control core graduates to the universal daemon preamble" idea, taken at its smallest useful member.

**Where:** `packages/surface/src` (the reserved-member seam beside `system.identity`) · `packages/surface-remote/src/{measureClockOffset,session,serveHostMap}.ts` (fold the measurement into admit; retire the injected hook or default it).

**Done when:** a fresh consumer gets clock-honest `EntryStatus.connected` with zero clock code of its own — no `offsetOf` to remember, no `clockNow` to hand-serve; drishti's `offsetOf: () => 0` stub deletes; paired drishti PR green.

### L26 — kill the overloaded null/sentinel hacks *(SHIPPED — #1744, merged 2026-07-09)*

*Status: SHIPPED — the `no-overloaded-null` code-police rule + the sweep's verdict landed as <PrLink pr={1744} /> · Lens: architecture-first-principles (illegal-states-unrepresentable) + hickey (a null doing two jobs complects two states) · Gate: none bit (no `@kolu/surface*` hit surfaced)*

**Outcome (the sweep governs the verdict).** A five-agent repo-wide sweep — prioritizing padi, the server re-serve/session surfaces, `surface-daemon-supervisor`, and the client — read ~40 nullable/sentinel/optional sites *in context* and classified each. The finding is honest and uniform: **zero overloaded nulls remain anywhere in the tree.** The class L26 was born to kill was already retired by the very surface-hosting + padi refactors that spawned this entry — the code now narrates its own prior de-overloadings (`ProcessRss` three-arm union, `KavalProbe` honest-null, `RestoreTarget`, `Known<T>`, and `SurfaceIdentity` itself). So the FIX half was satisfied by prior work; **the deliverable is the guardrail** (the `no-overloaded-null` code-police rule) that stops the class from regressing — exactly the second half this entry always framed. No `@kolu/surface*` hit surfaced either, so there are **no drishti-gated proposals** — that family is where the exemplar was minted and is already clean. This is *not* a blanket anti-null crusade: a single-meaning "absent" is fine and was left alone.

Born from the surface-hosting-simplify debate (2026-07-05): the `SurfaceIdentity` design first used `identity(): T | null` (null = no link) AND `baked: T | null` (null = no build) — **two nulls, two meanings, a reader guessing which** — plus `commit: string` with `""` conflating dev-mode with a real commit. srid's rule: **a nullable or sentinel that carries more than one meaning is a defect** — replace it with a discriminated sum so every state is a named `kind` the reader must branch on, and impossible states can't be constructed. The identity type became `{ kind:"disconnected" } | { kind:"anonymous"; … } | { kind:"identified"; … }` with a `BuildCommit = { kind:"commit"; sha } | { kind:"dev" }` sub-sum — zero nulls.

**One PR, two halves — the fix and the guardrail that stops it regressing:**

- **Sweep + fix.** Find the same smell repo-wide (prioritize the daemon/session/convergence surfaces: padi, surface-daemon-supervisor, the re-serve). Known seeds the debate surfaced: the L3 convergence kit's `buildId === ""` = "off-nix" sentinel is being killed by the surface-hosting PR itself (srid ruled it must not survive the identity refactor) — so it is NO LONGER an L26 seed; L26 sweeps the *other*, scattered `null`/`""`/optional-as-state instances; any `X | null` where `null` answers two different questions (absent-vs-error, disconnected-vs-empty, not-yet-vs-never). Grep seeds: `: string | null`, `=== ""`/`!== ""` as a meaning-bearing check, optional `?:` fields a reader treats as a state, `!`/`as any` around a maybe-absent value. Inventory with an Explore agent (classify each hit: honest single-meaning null = fine · overloaded = fix); propose the sum-type replacements to the coordinator; fix the overloaded ones as discriminated unions. **NOT a blanket anti-null crusade — a single-meaning "absent" is fine; the target is `null` doing two jobs.**
- **Code-police rule** (see `.agency/code-police.md`), e.g. `no-overloaded-null`, so the class can't come back: flag on a PR diff (a) a `T | null`/`T | undefined` whose null is tested for **two distinct meanings** (≥2 sites with divergent handling, or a name/comment implying two absence-reasons); (b) a string/number **sentinel** (`""`, `-1`, `"none"`) standing in for a state that has a real name elsewhere; (c) an optional field a consumer treats as an on/off **state**. Guidance: prefer a `{ kind: … }` union; cite `SurfaceIdentity` as the canonical exemplar.

**Done when:** no `null`/`""`/optional in the prioritized surfaces carries more than one meaning (each such state is a discriminated `kind`); the "honest single-meaning" survivors recorded here with that verdict; the lint ships in the code-police ruleset, fires on a seeded two-meaning fixture, stays quiet on an honest single-meaning one, and documents the `SurfaceIdentity` before/after. *(If the sweep is large, the FIX may land in per-package tranches, but the lint ships with the first tranche and the entry closes only when the sweep is done + lint green.)*

**Survivors — the near-misses, recorded with their verdicts.** These are the sites whose *declared* type or comment looks two-meaning but which the sweep ruled honest single-meaning (the rest of the tree is uncontested):

- `packages/server/src/daemonInventory.ts` `boundHost: string | null` — doc calls it "the SINGLE source for both 'is this a remote bind?' and the dialog label". **Survivor:** `null` = "local binding" (one meaning), string = the remote host; folded to the `DaemonBinding` `{kind:"local"} | {kind:"remote"; host; localScan}` sum one line into its *sole* consumer, zero divergent read sites. Pushing the sum to the seam only relocates the env-derived (`KOLU_PADI_HOST`) null check — the async `localScan` must stay in the consumer — so no illegal state is removed.
- `packages/integrations/anyagent/src/agent-adapter.ts` `contextTokens: number | null` (and `startedAt`) — comment names two *origins* ("no telemetry" vs "no assistant turn yet"). **Survivor:** two *causes*, one *effect* (render "—") at every read site; no reader disambiguates. Becomes a hit only if a UI ever wants "n/a" vs "loading…" shown differently — the `no-overloaded-null` rule's `_Allowed_` clause records exactly this boundary.
- `packages/padi/src/sessionRestore.ts` `resumeIds?: string[]` — `undefined` = resume all, `[]` = resume none. **Survivor:** deliberate documented tri-state; the *absent* value answers one question (no opt-in filter → all).
- `packages/shell-quote/src/index.ts` `token: string | null` — `null` = "between tokens", `""` = "an empty token in progress". **Survivor:** the *correct* two-state encoding needed to round-trip `shellJoin`; collapsing them would be the bug. Two states, two names — not an overload.

The already-discriminated sums that would otherwise be these overloads — `ProcessRss`, `KavalPresence`/`PadiPresence`, `SessionState`/`ClosedInfo`, `SocketProbe`, `TranscriptWatching`, `readPadiMemoryOnce`'s value·absent·error split — are the "after" of prior de-overloading; the sweep confirms the pattern is applied, not missing.
