**The principle is still that a test lives at the lowest layer that can honestly assert it. The correction is that “a lower test exists” does not prove it asserts the same thing.** Kolu currently has **58 feature files, 530 Gherkin declarations, and 546 expanded executions**: 541 in default Linux CI and 540 on Darwin. This note no longer promises a retirement count. It first makes the suite measurable and makes silent coverage loss detectable; candidate retirements are re-audited afterward, one exact scenario revision at a time.

## Why classification alone was not enough

The earlier review grouped scenarios by prose and nearby unit tests. A perfection pass found four ways that could delete unique coverage:

- The Code-tab `local` / `branch` / `browse` Outline matrix drives different data sources and view-versus-diff dispatch. Sampling each mode once does not prove every behavior across all three paths.
- The Markdown “rich render” scenarios check computed list-marker CSS, the real per-terminal image route, asynchronous Shiki loading, repaint, and generated copy-button DOM. Parser tests do not own those browser facts.
- `fileSearch.test.ts` proves path projection, while the hollow-directory regression lives later in Pierre tree reconciliation. The easier lower test can stay green while the actual defect returns.
- A test title in a ledger proves presence, not effect. A replacement can be collected yet use the wrong fixture, swallow the relevant failure, or never cross the declared defect surface.

These are one defect shape: **evidence attached to a nearby behavior instead of to the seam that failed**. The repair is an executable chain from scenario identity to replacement and survivor, plus a counterfactual test that demonstrates what breaks.

## EG0 — the non-destructive foundation

EG is the E2E-graduation track. EG0 changes no feature and retires no browser execution.

| Mechanism | Source of truth | Enforced property |
|---|---|---|
| Scenario inventory | `packages/tests/scenario-inventory.json` | Each revision fingerprints backgrounds, steps, tags, data tables, doc strings, and expanded Examples values. New revisions append; CI compares historical records with the merge base, so an old record cannot be edited or removed in the deleting change. |
| Coverage ledger | `packages/tests/coverage-ledger.yaml` | Every revision absent from the live suite has exactly one landed row naming the promise, real defect surface, destination layer, replacement, and current survivor. |
| Replacement proof | `packages/tests/governance/ledger.ts` | Replacement and counterfactual test names must resolve through Vitest collection. The counterfactual names the break it introduces; review still verifies that it crosses the declared real seam. |
| Attempt timing | Cucumber message stream → `reports/e2e-timing.json` | Every attempt is retained with status, wall duration, step duration, retry verdict, final-attempt totals, and per-feature totals. A passing retry cannot erase the failed attempt's cost. |
| Baseline report | `governance/baseline.ts` | At least five samples on both Linux and Darwin; median and IQR for E2E, unit, daemon, pipeline critical path, attempts, and retries. |

The initial census is pinned in `packages/tests/baseline-census.json`. The inventory contains 530 current immutable revisions. `ci::e2e-governance` runs on both platforms beside the browser lane.

**User-visible delta:** none. This is test infrastructure.

**Manual acceptance:** run `just test-e2e-governance`, then `just test-quick features/smoke.feature:4`; the first prints 58/530/546/541/540, and the second leaves `packages/tests/reports/e2e-timing.json` containing one real execution and every attempt. Change an Examples value without appending the new revision, or remove an inventory record, and the governance check must fail.

**Why EG0 is separate:** replacement tests must land before their E2E deletion so bisection can distinguish “coverage added” from “browser proof removed.” EG0 is the prerequisite that makes that sequence enforceable; it cannot itself authorize a deletion.

## The honest destination layers

| Layer | CI lane | Owns | Does not replace |
|---|---|---|---|
| L1 pure | `unit` | Parsers, reducers, projections, policy, state machines | I/O or rendered behavior |
| L2 component | `unit` with happy-dom | Render-from-state, attributes, ARIA, synthetic-trigger paint | Layout, real focus, xterm, or real wire delivery |
| L3 fork-free integration | `unit` and the daemon rerun | Real temp directories, SQLite, watchers, short-lived Git, in-process channels | Long-lived PTYs/processes |
| L4 real-process integration | serial `daemon` | Real PTYs, daemons, process lifetime, SSH | Browser composition |
| L5 browser E2E | parallel `e2e` | The whole user-visible path | Nothing |

An L2 test replaces an E2E only when the original stimulus was already synthetic or the promise is purely render-from-props. An L3/L4 test keeps the named defect surface real: a fake adapter cannot replace a watcher/adapter/sensor regression.

## Re-audit after EG0

There is no target count. For each proposed retirement:

1. Name the exact immutable revision and user promise.
2. Reproduce the historical defect or a faithful counterfactual at the lowest honest layer.
3. Land that replacement first and prove Vitest collects it on every declared platform/lane.
4. Name an independent current L5 survivor that still walks the user path.
5. Delete the E2E only in a later change with a landed ledger row.
6. Measure the whole pipeline critical path, not merely the E2E lane; restore the browser proof if coverage or runtime evidence fails.

The hard-keep boundary remains deep links, ports, printed URLs, mobile gestures and soft keyboard, reconnect, xterm behavior, canvas geometry/WebGL, canonical focus and chord journeys, worktree composition, and any other path whose promise emerges only from real browser/system composition. A known flake is fixed separately, never laundered as a graduation.

The next plan may contain a conservative core and conditional candidates, but its count is an output of ledger-complete proofs—not an input and never a quota.
