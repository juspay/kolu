**One conversation ↔ one kolu terminal** (for pesu later). **CT1+CH1** is the
kolu-native face first: a **live timeline of human + AI messages across every
agent on every connected host** — Twitter-style fleet skim, not a per-tile
Inspector archive. Tools stay on the PTY; click a card to open that terminal.

pesu is the XS bridge only; config is env/systemd next to pesu, not the web app.

## Components

| Component | Process | Job in this design |
| --- | --- | --- |
| **Xyne Spaces** | XS cloud | Threads, identity, @mention/DM delivery |
| **XS apps platform** | part of XS | Signed webhook out; app API in |
| **pesu** | daemon beside kolu (`packages/pesu`) | Webhook + binds + padi client + XS API |
| **padi** | per-host workspace daemon | `lifecycle.*`; **forward-only `transcriptChat`** |
| **kaval** | PTY daemon | Live PTYs |
| **agent CLI** | child in PTY | Session files on disk (JSONL / SQLite) |
| **kolu PWA** | browser | Multi-host map; **Feed** merges chat streams; tiles = depth |

```
hosts (padi each) ──transcriptChat (forward)──► kolu client ──merge──► Feed timeline
                                                      │
XS ◄──pesu (later)── same chat filter, one thread ↔ one terminal
```

pesu dials padi with `@kolu/padi/dial` (like `padi-tui` / `kolu mcp`) — not
through kolu-server.

## Surface primitives (why CT1 is a stream)

| Primitive | Fit for the fleet feed? |
| --- | --- |
| **`streams`** | **Yes — CT1.** Per terminal `{ id, after? }`, **forward-only** chat deltas. Optional cheap `{ kind: "live", cursor }` hello — **not** history snapshot. |
| **`procedures`** | Export only (`transcript.exportHtml`). Not the live path. |
| **`events`** | No backlog; wrong for continuous feed. |
| **`cells` / `collections`** | Terminals stay the entity set; messages are a time-ordered fan-in on the client, not a second collection keyspace. |

**Client consume (CH1):**

- For **each connected host**, for **each terminal with an agent** (or lazy as
  agents appear), subscribe `transcriptChat` on that host’s padi surface.
- **Tag** every event with `{ hostKey, terminalId, agentKind, … }`.
- **Merge** into one timeline by arrival / agent timestamp (good enough for a
  social feed; not a ledger).
- Hard reload → empty feed; streams resume **forward only**.

**Re-serve:** stream members **`delta`** (fail-through), same class as
`terminalAttach` / `activity`.

**Rejected:** poll exportHtml; snapshot last *N* on subscribe; full list each
frame; unbounded multi-day buffer without a ring.

## Bind state (pesu-local)

```
threadId  →  { terminalId, authorUserId, hostKey? }
```

Create-on-miss, author gate (v1 allowlist), persist beside pesu — not kolu conf.

## Interaction: first message (pesu)

| Step | What |
| --- | --- |
| 1–2 | User DMs/@mentions bot; XS webhook (HMAC) |
| 3 | 200 immediately; work async |
| 4–8 | Author gate → `lifecycle.create` + agent argv + first `sendInput` |
| 9–10 | Store bind; ack + deep link |

Agent only sees PTY input.

## Interaction: later user messages (pesu)

Webhook → bind lookup → author gate → `sendInput` on that terminal.

## Interaction: agent → Feed / pesu (transcript stream)

| Step | What |
| --- | --- |
| A | Agent appends session files |
| B | padi incremental parse; chat filter (`user` / `assistant` only — same as export chat mode) |
| C | `streams.transcriptChat` — **forward-only** deltas |
| D | **kolu Feed** merges all hosts; **PE1** posts bound terminal to XS |

Hard reload: **no history snapshot**. Full past → export.

## APIs (pesu ↔ XS / padi)

**XS → pesu:** `APP_MENTIONED`, `DIRECT_MESSAGE` (HMAC).  
**pesu → XS:** `postMessage`, `updateMessage`, `agentProgress`, `user/info`.  
**padi:** `lifecycle.create` / `sendInput`; **`transcriptChat` stream**;
`transcript.exportHtml` unchanged for archive.

### CT1+CH1 — one PR: multi-host message timeline

<Phase id="CT1+CH1" name="streams.transcriptChat + global Feed (Twitter-style, all hosts)" status="next" />

**One PR.** Product: a **live, read-only timeline of human + AI messages from
every agent on every connected host** — skim the fleet, click into depth.
Same chat filter as **Export → Chat log**. Not Inspector Conversation. Not a
write path. Not history rehydration on reload.

#### What the user gets

You run agents on **local** and a **remote** host. Open **Feed** (chrome
control next to dock / inspector — global, not per-tile). Cards stream in as
agents speak. Each card shows host · terminal · role · text. Click → focus
that host + terminal (existing deep-link / attend path). Tiles stay real PTYs.

Hard reload → Feed empty → only **new** messages after reload. Want the past →
export that terminal’s chat log.

#### UI prototype (real chrome)

Grounded in shipped shell: top **chrome bar** (`data-testid="chrome-bar"`)
with **host strip** + control cluster (dock · inspector · …); left **dock**;
canvas tiles; Feed as a **global panel** (sibling of dock/inspector, not a
right-panel Inspector section).

<FleetFeedMockup />

| You do | What happens |
| --- | --- |
| Connect two hosts | Feed subscribes on **both** padi surfaces |
| Agents emit chat lines | Cards appear in one scroll (newest orientation TBD — Twitter-up or log-down) |
| Click a card | Focus that host + terminal on the canvas |
| Mute / filter (v1 light) | Optional: this host only · needs-you only — noise control |
| Hard reload | Feed empty; forward-only again |
| Open Inspector / Compose | Unchanged — write path not this PR |

#### Why this instead of Inspector chat log

| Inspector log (rejected for CH1) | Fleet Feed (this PR) |
| --- | --- |
| One terminal | All agents × hosts |
| Buried in per-tile chrome | Global skim (dock’s text channel) |
| Weak for multi-host | Cross-host by construction |
| Feels like a second chat app in the panel | Feels like attention **with words** |

#### Wire (CT1) — live forward only

```
input:  { id: terminalId, after?: Cursor }
output: chat-filtered deltas only
```

- Filter = export **chat** mode (`user` + `assistant`) — **one** definition.
- **No** history snapshot on subscribe or hard reload (slow on long sessions).
- Continue from file/DB offset / `after` cursor.
- First frame: optional `{ kind: "live", cursor }` — **not** last-*N* dump.
- Forwarding: **`delta`**.
- Subscribe-driven per terminal (or host fan-in that still only runs for
  live agents); client merges hosts.

`exportHtml` stays the archive path.

#### Memory

| Rule | Detail |
| --- | --- |
| **Append while open** | Only events received this Feed session; optional ring if open for hours |
| **Hard reload** | Empty; forward-only resume |
| **Virtualize** | Recycle card DOM |
| **Per-host dispose** | Dropping a host drops its subs + its cards from the live buffer |

#### Backend cost

| Forbidden | Cost |
| --- | --- |
| Re-export full transcript per tick / per subscribe | **O(S)** / ~**O(S²)** lifetime |

| Required | Cost |
| --- | --- |
| Append watch + debounce + parse **Δ** only | **O(Δ)** per tick |
| Subscribe / hard reload | **O(1)** w.r.t. session size *S* |
| Shared producer per terminal, fan-out to Feed | **O(Δ)** once, not × clients |

Same shape as the Claude **session watcher** (append + debounce + incremental),
not **export loaders** (`readFileSync` whole JSONL). See watcher
`TRANSCRIPT_DEBOUNCE_MS` / `TAIL_BYTES` vs `loadClaudeCodeTranscript` full read.

#### Done when (this one PR)

- Two hosts, two agents: **new** human/AI lines appear in **one** Feed.
- Click card → correct host + terminal focused.
- Chat filter matches export chat mode.
- Hard reload does **not** re-scan sessions or snapshot history.
- Backend incremental O(Δ); tiles remain PTYs; Compose unchanged.

### PE0 — pesu inbound

<Phase id="PE0" name="XS webhook → create terminal + sendInput" status="todo" needs={["CT1+CH1"]} />

#### Prior art — PR #1810 (do not merge; port the leaf)

[#1810](https://github.com/juspay/kolu/pull/1810) (`pesu-b0`) implemented the
**old** B0: thread → **existing coordinator by title**, FIFO drive loop,
growing reply via loaders. **Superseded.** Do not merge. New PE0 PR; **port**
the XS leaf.

| Port | Why |
| --- | --- |
| `webhook.ts` + HMAC tests | Same XS events |
| `xyneApi.ts` + fake XS tests | postMessage / user/info |
| `config.ts` fail-fast env | No default secrets |
| `log.ts` | Always-on visibility |
| Allowlist + visible decline | Author gate |
| `nix run .#pesu` | Deploy shell |

| Leave behind | Why |
| --- | --- |
| `coordinator.ts` title bind + drive | PE0 **creates** a terminal |
| Campaign orchestrator as the door | One thread ↔ one agent terminal |
| Growing-reply as B0 outbound | PE1 + Feed use the chat stream |

**Implement:** webhook → gate → create-on-miss → `sendInput` → ack. Dial padi
like `padi-tui`.
