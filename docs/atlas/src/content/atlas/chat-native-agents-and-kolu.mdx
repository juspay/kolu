**One chat thread ↔ one kolu terminal.** First message to the bot creates both.
User text goes into the terminal; agent **messages** (not tools/edits) come back
into the thread from the transcript.

**pesu** is a small daemon beside kolu. It is the only thing that talks to both
sides. Config lives next to pesu (env / systemd) — not in the kolu web app.

## The three parties

| | Owns | Talks via |
| --- | --- | --- |
| **Xyne Spaces** | identity, threads, who may write | apps platform (webhook + app API) |
| **pesu** | thread → terminal map, the pipe | webhook server · XS API client · kolu client |
| **kolu** | PTY, agent, files, transcript | lifecycle create · input · transcript events |

<Svg svg={wire} caption="Xyne Spaces and kolu never talk to each other. pesu is the only bridge." />

## Traffic

**Xyne Spaces → pesu**  
Signed webhook on mention / DM: *who said what, in which thread*.

**pesu → kolu**  
- first message: create terminal + agent; store `threadId → terminalId`  
- later messages (author only): write text into that terminal  

**kolu → pesu**  
New `assistant` events from the live transcript (same filter as chat-log export).

**pesu → Xyne Spaces**  
`postMessage` / `updateMessage` into the thread. Optional deep link to the
terminal in kolu.

That's the whole protocol. No fleet board, no coordinator, no second bot.
