Kolu renders each host as a browser-style tab — click to switch, `+` to add over
ssh, `✕` to drop. <Cite file="packages/client/src/host/HostSelectorStrip.tsx" /> It's
a *good* start: the metaphor needs no manual, health is legible before you switch,
and the strip degrades to an overflow menu as it narrows. But it's stuck on two
axes. It **looks** like a toolbar bolted above the canvas — hard borders, flat
fills, an opaque band with a seam. And it never leaves the **tab-row box**: every
idea is still "a row of tabs." This note fixes the first cut on both — craft, then
paradigm.

## The bar today

Three hosts as tabs. Each carries a connection dot, the name, a fixed-width
**Padi · Kaval** slot (so a sick remote shows red *before* you switch), an optional
amber **awaiting** count, and — for guests — a remove `✕`. A click writes
`activeHost` and the canvas re-keys; no reload.<Footnote>The switch is a synchronous
signal write — `setActiveHost(props.host)` in <Cite file="packages/client/src/host/HostSelectorStrip.tsx" />; `useEntry(activeHost)` re-keys the per-host canvas. Nothing reflows because every tab reserves the same daemon-slot width whether active or not.</Footnote>

Three problems the first cut left standing:

- **It reads as a toolbar, not part of the workspace.** Opaque fill, hard border, a
  visible seam against the canvas. Nothing about it says "this *is* the canvas's
  frame."
- **It never leaves the tab-row box.** Every host is a rectangle in a row; add enough
  and it overflows into a `⋯` menu. The row is the ceiling.
- **Switching is mouse-only, and the keyboard tier is taken.** `⌘1–9` is positional
  *terminal* switch, `Ctrl+Tab` cycles terminals, `⌘T`/`⌘N` make one — hosts get
  nothing.<Footnote>Confirmed in <Cite file="packages/client/src/input/actions.ts" />: the `switchTo1…9` block binds `{ key: String(i), mod: true }` to dock-row terminal switch, and `Ctrl+Tab` (`shiftOptional`) cycles terminals. The palette (<Cite file="packages/client/src/commands.tsx" />) registers no host action. So a host keyboard path can't borrow the number row — that tier belongs to terminals.</Footnote>

## Make the box beautiful

Before changing the paradigm, fix the *craft* — same tab metaphor, but it stops
looking bolted-on. Four moves: **frost the band** so the canvas grid shows through
(it becomes a lens over the workspace, not a lid); give each host its **own hue** —
a coloured focus ring on the dot and, on the active tab, a soft hue underglow — so a
host feels like a *place*, not a label; **dissolve the seam** by letting the active
tab's belly bleed into the canvas (the connected-tab metaphor done right — no border
line between "active host" and "its canvas"); and **cross-fade on switch** (150 ms
hue + belly slide) so hopping hosts feels like moving, not repainting.

## Out of the box · the host as a room

Now leave the row. A host isn't a document you tab between — it's a **place** you're
*inside*. So drop the tab strip and let the active host own the whole window: its hue
washes the canvas edges in a soft halo, and identity collapses to **one** thing — a
**presence pill** floating at the top ("you are in `srid@zest`"). Click it (or `⌘K`)
and it **blooms** into a vertical list of rooms, each in its own hue, that you
*teleport* between with a full-window hue cross-fade. No row to overflow: ten hosts
is a scroll, not a `⋯` menu.

## Out of the box · the host map

The second paradigm leans all the way into what kolu already is: an infinite canvas
with a **camera per host**. So make switching *navigation of one continuous space*.
`⌘K` (or a pinch/zoom-out past the canvas edge) pulls the camera back to a **host
map** — every host a live-preview card of its real tiles in miniature, laid out
spatially, the active one lifted, an awaiting one glowing amber. Pick one and the
camera **flies in**. Switching stops being "click a tab" and becomes "fly to a
place."

## The interaction underneath

Whatever the surface — polished tabs, room bloom, or host map — the *keyboard* story
is the same, and it isn't a new invention: kolu **already** ships this exact pattern
for workspaces. `⌘⇧K` opens the workspace switcher, which is literally
`commandPalette.openGroup("Search workspaces")` <Cite file="packages/client/src/useActionContext.ts" /> —
a scoped palette group, not a bespoke modal. Host switching mirrors it one-for-one:
`⌘⇧H` (**H for host**) → `commandPalette.openGroup("Switch host")`, fuzzy-matched and
**sorted by who's awaiting you**; `Enter` picks. `⌘⇧H` is free and follows the
`Mod+Shift+<letter>` convention the codebase already names for exactly this.<Footnote><Cite file="packages/client/src/input/actions.ts" /> line 281 calls out "the `Mod+Shift+<letter>` convention used by `openWorkspaceSwitcher`," and a grep confirms no `KeyH` / `⌘⇧H` binding exists in `actions.ts` or `prohibitedKeybinds.ts`. ## What I'd ship, and where it wires in

The moves stack, they don't compete. **Ship the craft first** (§2) — frosted band,
per-host hue, seam dissolve, cross-fade — because it's pure CSS on the strip that
exists and it makes every later paradigm look right. **Then the palette switcher**

visual but the riskiest (it removes the always-visible attention channel; it needs
the orb rail to be honest). None of it invents host state: the switch stays one
