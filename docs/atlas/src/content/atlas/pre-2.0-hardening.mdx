## Tier 1 — block the tag

| Issue | Why it blocks | The fix |
| --- | --- | --- |
| <Issue n={1334} /> + <Issue n={1375} /> | **prod-safety.** An agent `/be` run disrupted production `kolu.service`; a local `vitest` forked 30+ daemons and OOM-reaped prod kaval. Running kolu's dev *on* kolu can kill prod — the only *dangerous* class here. A tooling-level guard (PR #1338, a `prod-guard` justfile recipe) was already tried and closed unmerged. | One PR, three locks in the product: **(a)** any dev/test run that spawns daemons is forced into a private throwaway state-root — the harness *refuses to start* against the real one; **(b)** the production service marks its daemons, and every dev-side adopt/kill/discover path refuses a marked daemon, loudly; **(c)** the test harness runs its children under a process+memory cap, so a fork-bomb starves itself, not prod. <Issue n={706} /> is the same class; its full leg (VM/container containment) stays deferred. |
| <Issue n={1859} /> | In simple words: one corrupt message makes the wire reader *report* "this connection is over" — but it never actually stops reading. Every later message is still decoded and delivered into a peer the server already closed and stopped counting. A zombie connection: bookkeeping says dead, socket says alive. | On settle, detach the `'data'` listener; on decode failure, destroy the stream — so "the read promise settled" and "the read actually stopped" can never diverge (`stdio-codec.ts:126-135`). Audit `links/stdio.ts` for the same divergence. |
| <Issue n={1754} /> | claude-code live state can lie: stuck "thinking" after the turn completed, never reconciling. A lying dock guts the observe-out UX. **Reproduced** — CI evidence on aarch64-darwin (ollama fast turns: 2.88s turn, indicator stuck `thinking` for the full 60s), and four real-agent e2e scenarios sit descoped waiting on it. | Two known mechanisms, both in the issue: the transcript watcher attaches after the turn's JSONL landed and only tails (fix: **initial full-scan on attach**), and `deriveState` maps only `stop_reason === "end_turn"` to `waiting` (fix: reconcile the emulated stop reasons). Landing both restores the descoped e2e asserts — the regression pin comes free. |
| <Issue n={1177} /> | ~~`awaiting_user` doesn't chime when the prior state was `waiting`~~ **SHIPPED — PR #1894 merged, issue closed.** The attention-*episode* latch: ≤1 chime per notify-class run, episode ended only by a work state; trigger = class-entry OR escalation into the fenced `awaiting` bucket; honest "needs your input" copy. | Done (reproduce-first RED → 3-refuter design gate → full /be gauntlet). |
| <Issue n={1763} /> | boot wedge — a fresh load intermittently sticks at "Connecting to local…" and terminal-create wedges. The `scopedByEntry` non-member warn was **ruled out** (benign per-boot transient); the live wedge did not reproduce across a fault-injection campaign. | **Mechanism pinned (code-grounded, on the issue):** the connect overlay is held by any of three loading legs but its only timeout escape is coupled to the daemon leg — a hung membership leg (no `activeScope()` ⇒ the anchor is never stamped) or a hung session/terminalKeys leg has *no escape at all*. Fix: one boot deadline anchored at app start, outside the per-host scope, escaping on *any* stuck leg — gated on the fault-injected repro in the issue's §5. |
