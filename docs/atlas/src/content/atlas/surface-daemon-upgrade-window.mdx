## The window the framework created and then ignored

`@kolu/surface-daemon` sells durability: a daemon that survives its supervisor's deploys. Durability *creates* the mixed-version window — a new-build supervisor talking to an old-build daemon through shared artifacts (pid gate, unix socket, state files) — and today the framework stops at detection primitives while every consumer discovers the window's edges by hand. kolu found the cost in production: a gate-format change made the new reader *refuse* the legacy gate shape, so the recycle path had no pid to SIGTERM and **Restart kaval silently did nothing**.<Footnote>The <PrLink pr={2011} /> incident: the parked branch's `pidGate.ts` moved to a two-field `pid\tstartUnixUs` gate whose reader "accepts exactly this build's two-field identity; it never interprets the retired one-field pid shape" — a legacy gate parsed as `unsupported-format`, `gatePid()` returned `undefined`, and Restart no-oped. No test could catch it: every test in the repo boots both daemon generations from one checkout. The full adoption is parked on branch `osfacts-kolu-adoption` (tip `dc104661`), kept reachable because drishti pins commits on that history.</Footnote>

The framework is further along than the issue's framing suggests. Since <PrLink pr={1674} />, `surface-daemon-supervisor` already owns the convergence kit — `ConvergenceIdentity` (ordered `contractVersion`, match-only `build`), `ConvergencePolicy<Cap>`, the pure `decide()` table, `BuildDrainFence`, `converge()`, and the endpoint machine with its `incompatible` state and gateless-squatter recovery. What kolu still hand-rolls, and what this plan graduates, is precisely bounded:

1. **The drain skeleton** — `drainAndAwaitExit` in `packages/server/src/padi/padiConvergence.ts:103`: arm the exit-observer *before* firing the drain RPC, race exit against a ceiling, ground truth is the process exiting — never the RPC resolving.
2. **Drain admission** — the remote arm's instance-keyed budget (`remotePadiBinding.ts` `admitDrain`): a different daemon instance after our drain means *another supervisor is fighting us* → give up loudly; the same instance past the budget → adopt stale. The framework's boolean fence is a degenerate case of this.
3. **The post-drain story as typed states** — the remote arm's `adopted-stale` / `skew-refused` / `unconverged` discriminated union (`packages/common/src/surface.ts:387`) is app-typed, and its cross-supervisor verdict isn't even an arm: it lives in a `crossSupervisorDetail` sidecar flag with one set site, six clear sites, and a checked-first ordering hazard in `computeEntryFailedDetail`. The local arm can't express adopt-stale at all because `decide()` collapses a fence-spent adopt to a bare `adopt` (the gap named at `padiBinding.ts:738-741`).
4. **The ssh arm itself** — `remotePadiBinding.ts` bypasses `converge()` entirely and hand-spells the enactment switch over a raw `decide()`. Drishti's daemon is remote-only, so this is not an edge case to tolerate: it is the second consumer's *main* path.
5. **The window tests** — <PrLink pr={2027} />'s yesterday-daemon fixture, shared-artifact watchdog, and previous-release e2e live in `packages/padi/src/upgradeWindow/`, guarding kolu's window with machinery that is ~60–100% generic per file.

### The API in one example

What a *new* consumer writes after UW1+UW2 — a fictional `pulse` daemon, both halves, complete except for its own surface cells. This is the note's contract for what the phases must add up to:

```ts
// ── daemon side: runs inside the durable process ──────────────────────────
import {
  daemonMain, daemonProcessMain, readBakedIdentity, controlCoreFragment,
} from "@kolu/surface-daemon";

const ident = readBakedIdentity("PULSE"); // PULSE_BUILD_ID / PULSE_COMMIT_HASH, baked by nix
daemonProcessMain({
  name: "pulse-daemon",
  run: () => daemonMain({
    gatePath: join(stateDir, "pulse.pid"),
    socketPath: join(stateDir, "pulse.sock"),
    anchor: () => stateDir,
    lifetime: { kind: "idleTimeout", ms: 60 * 60_000, isIdle: () => liveConnections === 0 },
    router: implementSurface(pulseSurface, {
      // the frozen fragment: hello + drain, readable at ANY version skew
      ...controlCoreFragment({
        surfaceVersion: PULSE_CONTRACT_VERSION,
        buildId: ident.staleKey, commit: ident.navigableCommit,
        stateRoot: stateDir, startedAt: bootInstant,
        onDrain: persistStateThenStop,
      }),
      /* …pulse's own cells and procedures… */
    }),
    log,
  }),
});

// ── supervisor side: runs wherever the app supervises from ────────────────
import {
  createEndpoint, converge, survivableSpawnDriver, type ConvergencePolicy,
} from "@kolu/surface-daemon-supervisor";

const POLICY: ConvergencePolicy<"drainable"> = {
  capability: "drainable",
  onContractSkew: { kind: "drain-newer-else-refuse" },
  onBuildMismatch: { kind: "drain-and-replace" },
  drainBudget: { maxAttempts: 2, onGiveUp: "adopt-stale" }, // unspellable for "not-drainable"
};

const endpoint = createEndpoint({
  gatePath, socketPath,
  policy: POLICY,                              // fixed at construction — no boot-method trio
  baked: { contractVersion: PULSE_CONTRACT_VERSION, build: daemonBuild(myBakedId) },
  driver: survivableSpawnDriver({ binPath, args: ["--daemon"], env, unitPrefix: "pulse" }),
  connect: () => connectPulse(socketPath),     // the app's typed handshake — its soul
  log, onStatus,
});

const outcome = await converge(endpoint);      // probe → decide → drain/adopt/spawn, typed
if (outcome.anomaly) showOnEntry(outcome.anomaly);
// anomaly: adopted-stale | skew-refused | unconverged | cross-supervisor — never a silent no-op
```

A connector-shaped consumer (drishti's ssh arm, kolu's remote padi) swaps `converge(endpoint)` for `convergeAdmit(...)` with the *same* policy object; the decision table, drain skeleton, and budget are shared, only the enactment differs.

## Drishti — the durable per-host agent

Today drishti's agent is the textbook ephemeral `serveOverStdio` consumer: every ssh dial provisions the parent-pinned nix build and spawns a fresh process, so agent state dies per reconnect and the parent's 30-minute metric ring dies per deploy.<Footnote>Correcting the issue's framing: history does *not* die with the tab — since drishti's SR-track work it lives in a per-host ring in the parent (`router.ts`), replayed to any browser. What kills it is a parent restart (every home-manager deploy) and host removal; agent-side alert hysteresis and rate baselines die on every reconnect.</Footnote> Also today, *skew is impossible by construction* — spawn-per-dial means agent ≡ parent build. The durable daemon makes skew the steady state, which is exactly why drishti is the right second consumer: frequent deploys, two parent platforms, remote-only supervision, and a real cross-supervisor topology.

The design, with the author's decisions baked in:

- **One flag-dispatched binary.** `drishti-agent --stdio` becomes the front (`frontDaemonOverStdio`, `spawnDaemon: reExecAsDetachedDaemon` with `--daemon`); `--daemon` runs `daemonProcessMain` + `daemonMain` serving the existing agent router over a unix socket. The parent's wire is unchanged — the front relays bytes, so `sshConnector`, `makeSession`, and `pumpRemoteSurface` keep their exact shapes; the session upgrades to `DaemonSession` to expose `convergence()` and `renew()` on the host-map entry.
- **Paths and lifetime — everything under the state dir, deliberately.** Gate, socket, and ring all live in `${XDG_STATE_HOME:-~/.local/state}/drishti/` (`agent.pid`, `agent.sock`, `history.ring.json`), which is also the daemon's `anchor`. *Not* `$XDG_RUNTIME_DIR`: on a default systemd host, closing the user's **last** ssh session makes logind remove `/run/user/$UID` entirely — unlinking the socket and gate while the detached daemon survives, leaving an invisible orphan no framework recovery can find and a successor racing it for the ring file. A state-dir socket persists across reboots as a stale file, which the pid gate and the endpoint's socket-accepting probe already classify correctly. Lifetime: `idleTimeout` 60 minutes with zero live socket connections — twice the history retention, so any reconnect that could still see useful history finds the daemon alive, and hosts you stop monitoring self-clean.
- **The ring moves into the daemon, and onto disk — with its window discipline stated.** The parent-local ring and `metricHistory` stream move agent-side (the snapshot-then-delta schema already lives in agent-shared `surface.ts`); the daemon persists the ring to `history.ring.json` (explicit `v` field) every 30 s and on drain, via the repo-canonical temp-file+rename atomic write. Load discipline, named because the default would be the banned collapse-to-empty: a ring with an **unknown `v`** (rollback: an older successor reading a newer generation's file) or unparseable content is *preserved untouched* (corrupt files moved aside, never deleted) and surfaced as a typed `history-unavailable` state on the host-map entry — never a silently empty chart. Both dispositions get covering tests (a planted `v+1` ring; a truncated ring). History now survives reconnects, parent deploys, daemon renewals, and crashes — and drishti exercises all three artifact seams: gate, socket, state file. Alert hysteresis becomes durable as a side effect of living in the daemon.
- **Identity and convergence.** The agent surface gains a contract version (`AGENT_SURFACE_VERSION = "1.0"`) and serves the UW2 `controlCore` fragment (the frozen key set of the fragment footnote above — `stateRoot` is the daemon's state dir). Parent policy: `drainable`, contract skew `drain-newer-else-refuse`, build mismatch `drain-and-replace`, `drainBudget: { maxAttempts: 2, onGiveUp: "adopt-stale" }` — all via `convergeAdmit`. Drishti-side convergence code is the policy declaration and the app-edge link-state projection; nothing else.<Footnote>The two-parent mixed-pin window, traced: the user deploys the Linux machine, the macOS machine still runs yesterday's pin. Each parent wants its own build; builds don't order (Pin 2), so there is no "right" winner. The surviving-adopts budget bounds the fight to at most `maxAttempts` drains per parent per boot; the first parent to observe a foreign respawn of a lineage it drained parks in `cross-supervisor`, and with `onGiveUp: "adopt-stale"` *both* parents keep monitoring through whichever build won — one of them wearing a typed anomaly naming the fight — until the pins converge. The alternating-drain scenario is pinned as a framework unit test in UW1, not left to topology luck.</Footnote>
- **Operational edges, named.** The provisioning GC root must outlive the dial for the daemon's lifetime (today's root covers the ephemeral case; `nix-collect-garbage` deleting a running daemon's closure is a UW3 bug to prevent). Laptop-wake `recheckAll` must adopt, not respawn — the front's adopt path gives this for free, and the adopt e2e must include the field-realistic sequence: connect, **close the last ssh session**, reconnect, adopt with the ring intact. Drishti's `drv-stability` CI node inverts from optimization to convergence signal: accidental agent-drv churn now means fleet-wide daemon renewals (history handoff makes this survivable, but the node stays required). Off-nix dev parents adopt whatever runs, per the existing `off-nix` decide row.

### UW4 — capstone: the gate change that bricked, re-landed window-compatible

`surface-daemon`'s gate becomes versioned identity under a **tolerant-reader law**, stated once and pinned forever: *the first token of a gate file is the holder's pid, in every generation, and a reader extracts it from any shape — unknown trailing fields are ignored, never a refusal*. The writer emits `${pid}\t${startUnixUs}\n`; a legacy one-field gate reads as `{ pid, startUnixUs: undefined }` — a valid, older gate whose holder can be signaled. This is explicitly *not* the parked branch's design: `dc104661`'s reader refuses any shape but its own (`unsupported-format`), which both re-expresses the #2011 brick against v1 gates and would brick again when a v2 reader meets a future v3 gate — the parked branch is the starting point for the *writer and identity plumbing only*. `acquirePidGate` takes `{ self: ProcessIdentity, readProcessIdentity }` (injected — kolu and drishti both supply osfacts-backed readers; the framework bakes no fallback), and identity comparison uses a declared tolerance on `startUnixUs` (±2 s), because the wall-clock start instant is *derived* from `/proc/stat`'s btime at each read and shifts whole seconds under NTP steps, suspend, and VM pauses — strict equality would misjudge a live daemon as pid-reuse and re-create the brick from the other direction. One boundary case named: a live-identity gate whose socket is not yet accepting is a *booting* holder (the gate-write→socket-listen window), waited on, not reaped. Scope is the gate-identity slice only: the rest of `osfacts-kolu-adoption` (memorySampler via osfacts, V2 facet UI) remains [OSF8's](./os-facts-tool.html), which this phase unblocks — os-facts-tool.mdx's OSF8 row gets a one-line pointer here. **Done when the incident is a red-turned-green test, in both directions:** the graduated fixture plants a legacy *one-field* gate under a current supervisor and recycle succeeds by SIGTERM-ing the recorded pid (the exact <PrLink pr={2011} /> failure); a unit pin feeds the two-field write through the literal legacy parse and extracts the pid (the frozen pid-first token is the rollback contract); a clock-perturbation test shifts the injected reader's `startUnixUs` within tolerance without losing the holder; the previous-release e2e crosses a version boundary where the previous binary still writes one-field gates; both platforms green; drishti pair green at final kolu HEAD (the gate is now shared API).
