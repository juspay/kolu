## The window the framework created and then ignored

`@kolu/surface-daemon` sells durability: a daemon that survives its supervisor's deploys. Durability *creates* the mixed-version window — a new-build supervisor talking to an old-build daemon through shared artifacts (pid gate, unix socket, state files) — and today the framework stops at detection primitives while every consumer discovers the window's edges by hand. kolu found the cost in production: a gate-format change made the new reader *refuse* the legacy gate shape, so the recycle path had no pid to SIGTERM and **Restart kaval silently did nothing**.<Footnote>The <PrLink pr={2011} /> incident: the parked branch's `pidGate.ts` moved to a two-field `pid\tstartUnixUs` gate whose reader "accepts exactly this build's two-field identity; it never interprets the retired one-field pid shape" — a legacy gate parsed as `unsupported-format`, `gatePid()` returned `undefined`, and Restart no-oped. No test could catch it: every test in the repo boots both daemon generations from one checkout. The full adoption is parked on branch `osfacts-kolu-adoption` (tip `dc104661`), kept reachable because drishti pins commits on that history.</Footnote>

The framework is further along than the issue's framing suggests: since <PrLink pr={1674} />, the supervisor already owns the convergence kit — identity types, policy, the pure `decide()` table, `converge()`, the endpoint machine.<Footnote>Specifically: `ConvergenceIdentity` (ordered `contractVersion`, match-only `build`), `ConvergencePolicy&lt;Cap&gt;`, `BuildDrainFence`, and the endpoint's `incompatible` state plus gateless-squatter recovery.</Footnote> What kolu still hand-rolls, and what this plan graduates, is precisely bounded:

1. **The drain skeleton** — arm the exit-observer *before* firing the drain RPC, race exit against a ceiling; ground truth is the process exiting, never the RPC resolving.<Footnote>`drainAndAwaitExit` at `packages/server/src/padi/padiConvergence.ts:103`, shared today by copy between the local endpoint arm and the remote ssh arm.</Footnote>
2. **Drain admission** — the remote arm's instance-keyed budget: a different daemon instance after our drain means *another supervisor is fighting us* → give up loudly; the same instance past the budget → adopt stale.<Footnote>`admitDrain` in `remotePadiBinding.ts`. The framework's boolean `BuildDrainFence` is a degenerate case of this budget.</Footnote>
3. **The post-drain story as typed states** — the remote arm's anomaly union is app-typed, its cross-supervisor verdict lives in a sidecar flag with an ordering hazard, and the local arm can't express adopt-stale at all.<Footnote>The union at `packages/common/src/surface.ts:387`; the `crossSupervisorDetail` sidecar has one set site, six clear sites, and a checked-first hazard in `computeEntryFailedDetail` (`remotePadiBinding.ts:381`). The local gap — `decide()` collapsing a fence-spent adopt to a bare `adopt` — is named in code at `padiBinding.ts:738-741`.</Footnote>
4. **The ssh arm itself** — `remotePadiBinding.ts` bypasses `converge()` entirely and hand-spells the enactment switch over a raw `decide()`. Drishti's daemon is remote-only, so this is the second consumer's *main* path, not an edge case.
5. **The window tests** — <PrLink pr={2027} />'s fixture, watchdog, and previous-release e2e guard kolu's window from `packages/padi/src/upgradeWindow/`, with machinery that is ~60–100% generic per file.

### The API in one example

What a *new* consumer writes after UW1+UW2 — a fictional `pulse` daemon, both halves, complete except for its own surface cells. This is the note's contract for what the phases must add up to:

```ts
// ── daemon side: runs inside the durable process ──────────────────────────
import {
  daemonMain, daemonProcessMain, readBakedIdentity, controlCoreFragment,
} from "@kolu/surface-daemon";

const ident = readBakedIdentity("PULSE"); // PULSE_BUILD_ID / PULSE_COMMIT_HASH, baked by nix
daemonProcessMain({
  name: "pulse-daemon",
  run: () => daemonMain({
    gatePath: join(stateDir, "pulse.pid"),
    socketPath: join(stateDir, "pulse.sock"),
    anchor: () => stateDir,
    lifetime: { kind: "idleTimeout", ms: 60 * 60_000, isIdle: () => liveConnections === 0 },
    router: implementSurface(pulseSurface, {
      // the frozen fragment: hello + drain, readable at ANY version skew
      ...controlCoreFragment({
        surfaceVersion: PULSE_CONTRACT_VERSION,
        buildId: ident.staleKey, commit: ident.navigableCommit,
        stateRoot: stateDir, startedAt: bootInstant,
        onDrain: persistStateThenStop,
      }),
      /* …pulse's own cells and procedures… */
    }),
    log,
  }),
});

// ── supervisor side: runs wherever the app supervises from ────────────────
import {
  createEndpoint, converge, survivableSpawnDriver, type ConvergencePolicy,
} from "@kolu/surface-daemon-supervisor";

const POLICY: ConvergencePolicy<"drainable"> = {
  capability: "drainable",
  onContractSkew: { kind: "drain-newer-else-refuse" },
  onBuildMismatch: { kind: "drain-and-replace" },
  drainBudget: { maxAttempts: 2, onGiveUp: "adopt-stale" }, // unspellable for "not-drainable"
};

const endpoint = createEndpoint({
  gatePath, socketPath,
  policy: POLICY,                              // fixed at construction — no boot-method trio
  baked: { contractVersion: PULSE_CONTRACT_VERSION, build: daemonBuild(myBakedId) },
  driver: survivableSpawnDriver({ binPath, args: ["--daemon"], env, unitPrefix: "pulse" }),
  connect: () => connectPulse(socketPath),     // the app's typed handshake — its soul
  log, onStatus,
});

const outcome = await converge(endpoint);      // probe → decide → drain/adopt/spawn, typed
if (outcome.anomaly) showOnEntry(outcome.anomaly);
// anomaly: adopted-stale | skew-refused | unconverged | cross-supervisor — never a silent no-op
```

A connector-shaped consumer (drishti's ssh arm, kolu's remote padi) swaps `converge(endpoint)` for `convergeAdmit(...)` with the *same* policy object; only the enactment differs.

## Drishti — the durable per-host agent

Today drishti's agent is the textbook ephemeral `serveOverStdio` consumer: every ssh dial provisions the parent-pinned nix build and spawns a fresh process, so agent state dies per reconnect and the parent's 30-minute metric ring dies per deploy.<Footnote>Correcting the issue's framing: history does *not* die with the tab — it lives in a per-host ring in the parent, replayed to any browser. What kills it is a parent restart (every home-manager deploy) and host removal; agent-side alert hysteresis and rate baselines die on every reconnect.</Footnote> Also today, *skew is impossible by construction* — spawn-per-dial means agent ≡ parent build. The durable daemon makes skew the steady state, which is exactly why drishti is the right second consumer: frequent deploys, two parent platforms, remote-only supervision, and a real cross-supervisor topology.

The design, with the author's decisions baked in:

- **One flag-dispatched binary.** `--stdio` becomes the front (`frontDaemonOverStdio` + `reExecAsDetachedDaemon`); `--daemon` runs the daemon serving the existing agent router over a unix socket. The parent's wire is unchanged — the front relays bytes — so `sshConnector`, `makeSession`, and `pumpRemoteSurface` keep their shapes; the session upgrades to `DaemonSession` to expose `convergence()` and `renew()`.
- **Everything under the state dir, deliberately.** Gate, socket, and ring live in `${XDG_STATE_HOME:-~/.local/state}/drishti/`, which is also the daemon's `anchor` — *not* `$XDG_RUNTIME_DIR`.<Footnote>On a default systemd host, closing the user's **last** ssh session makes logind remove `/run/user/$UID` entirely — unlinking socket and gate while the detached daemon survives, leaving an invisible orphan no framework recovery can find and a successor racing it for the ring file. A state-dir socket persists across reboots as a stale file, which the pid gate and the endpoint's socket-accepting probe already classify correctly.</Footnote> Lifetime: `idleTimeout` 60 minutes with zero live connections — twice the history retention, so any reconnect that could still see useful history finds the daemon alive, and abandoned hosts self-clean.
- **The ring moves into the daemon, and onto disk — with its window discipline stated.** The ring and `metricHistory` stream move agent-side; the daemon persists `history.ring.json` (explicit `v` field) every 30 s and on drain, via the repo-canonical atomic write. A ring with an unknown `v` or unparseable content is *preserved untouched* and surfaced as a typed `history-unavailable` state — never a silently empty chart.<Footnote>The unknown-`v` case is the rollback window: an older successor reading a newer generation's file — the #2011 shape (identifiable-but-refused) would otherwise reappear as a silent empty. Corrupt files are moved aside, never deleted. Both dispositions get covering tests: a planted `v+1` ring and a truncated ring. History then survives reconnects, parent deploys, daemon renewals, and crashes — and drishti exercises all three artifact seams: gate, socket, state file. Alert hysteresis becomes durable as a side effect of living in the daemon.</Footnote>
- **Identity and convergence.** The agent surface gains `AGENT_SURFACE_VERSION = "1.0"` and serves the `controlCore` fragment. Parent policy: `drainable`, `drain-newer-else-refuse` / `drain-and-replace`, `drainBudget: { maxAttempts: 2, onGiveUp: "adopt-stale" }` — all via `convergeAdmit`. Drishti-side convergence code is the policy declaration and the app-edge link-state projection; nothing else.<Footnote>The two-parent mixed-pin window, traced: one machine deployed, the other on yesterday's pin. Builds don't order (Pin 2), so there is no "right" winner. The surviving-adopts budget bounds the fight to `maxAttempts` drains per parent per boot; the first parent to observe a foreign respawn of a lineage it drained parks in `cross-supervisor`, and with `onGiveUp: "adopt-stale"` *both* parents keep monitoring through whichever build won — one wearing a typed anomaly naming the fight — until the pins converge. The alternating-drain scenario is pinned as a framework unit test in UW1, not left to topology luck.</Footnote>
- **Operational edges, named.** The provisioning GC root must outlive the dial for the daemon's lifetime; laptop-wake `recheckAll` must adopt, not respawn; drishti's `drv-stability` CI node inverts from optimization to convergence signal.<Footnote>GC root: today's root covers the ephemeral case; `nix-collect-garbage` deleting a running daemon's closure is a UW3 bug to prevent. Wake: the front's adopt path gives adopt-not-respawn for free, and the adopt e2e must include the field-realistic sequence — connect, **close the last ssh session**, reconnect, adopt with the ring intact. drv-stability: accidental agent-drv churn now means fleet-wide daemon renewals (history handoff makes this survivable, but the node stays required). Off-nix dev parents adopt whatever runs, per the existing `off-nix` decide row.</Footnote>

## Phases

Four PRs, strictly sequenced — each later phase consumes API the earlier one creates. Standing obligations: every phase updates the paired `website/src/content/surface/ref-*.mdx` reference pages in the same PR, and every phase posts an odu-impact verdict.<Footnote>odu consumes neither package at its current pin — `odu serve` (the parent note's S2 tenant) is unshipped — so verdicts are expected `none` or `adoption-opportunity` for now; the obligation exists precisely so the ledger catches the moment that changes.</Footnote>

### UW1 — the supervisor kit completes: drain, admission, anomaly, both transports

**TL;DR:** Framework: the convergence kit becomes whole — one `converge`/`convergeAdmit` pair over one decision table, drain and admission included, every skew outcome a typed state. Consumers: kolu's three arms shed ~300 lines of hand-rolled convergence; policy moves to endpoint construction. Users: nothing visibly changes — except states that were silent (adopt-stale locally, cross-supervisor) now surface in the host UI.

What lands: `drainAndAwaitExit` (framework-run in both enactments), the policy-declared Cap-gated drain budget (surviving adopts, replacing `BuildDrainFence`), `adopted-stale`, the four-arm `ConvergenceAnomaly`, `convergeAdmit`, the boot-method trio going internal; kolu's local and remote padi arms migrate in the same PR.

**Done when:** `remotePadiBinding.ts` no longer touches `decide()` directly nor defines its three hand-rolled converge functions, and the `crossSupervisorDetail` sidecar plus its checked-first hazard are **deleted**; kaval's call site passes no budget and constructs no fence; the `adoption-padi-upgrade` VM arm still greps its breadcrumb green; a unit arm pins the previously-inexpressible local `adopted-stale`; the two-parent alternating-drain scenario is a framework unit test proving the fight terminates in `cross-supervisor`.<Footnote>Plus: `daemonSession.ts`'s convergence-vocabulary prose updated. No drishti pair yet (drishti consumes neither package); odu-impact verdict required.</Footnote>

**Manual QA:**
- Boot the PR build over a production padi left by master (`kolu` normally, then relaunch from the PR checkout): the server log shows the `padi build change on boot … draining the survivor once` breadcrumb, terminals and kaval survive, scrollback intact.

### UW4 — capstone: the gate change that bricked, re-landed window-compatible

**TL;DR:** Framework: the pid gate becomes versioned identity (pid + start-instant, killing pid-reuse misidentification) under a **tolerant-reader law** — *the first token of a gate file is the holder's pid, in every generation; unknown trailing fields are ignored, never a refusal.* Users: Restart works across every upgrade and rollback boundary — the #2011 brick becomes inexpressible. Kolu: unblocks [OSF8](./os-facts-tool.html).

What lands: the two-field writer (`${pid}\t${startUnixUs}\n`), the tolerant reader (a legacy gate reads as `{ pid, startUnixUs: undefined }` — a valid, older gate whose holder can be signaled), `acquirePidGate` taking an injected `readProcessIdentity` (kolu and drishti supply osfacts-backed readers), identity comparison with a ±2 s tolerance on `startUnixUs`, and the booting-holder case named.<Footnote>Why not the parked branch's design: `dc104661`'s reader refuses any shape but its own, which both re-expresses the #2011 brick against v1 gates and would brick again when a v2 reader meets a future v3 gate — the parked branch is the starting point for the *writer and identity plumbing only*. Why the tolerance: the wall-clock start instant is *derived* from `/proc/stat`'s btime at each read and shifts whole seconds under NTP steps, suspend, and VM pauses — strict equality would misjudge a live daemon as pid-reuse and re-create the brick from the other direction. The booting-holder case: a live-identity gate whose socket is not yet accepting is a holder in the gate-write→socket-listen window — waited on, not reaped. Scope: the gate-identity slice only; the rest of `osfacts-kolu-adoption` (memorySampler via osfacts, V2 facet UI) remains OSF8's, which this phase unblocks — os-facts-tool.mdx's OSF8 row gets a one-line pointer here.</Footnote>

**Done when the incident is a red-turned-green test, in both directions:** the graduated fixture plants a legacy one-field gate under a current supervisor and recycle succeeds by SIGTERM-ing the recorded pid (the exact <PrLink pr={2011} /> failure); a unit pin feeds the two-field write through the literal legacy parse and extracts the pid (pid-first is the frozen rollback contract); a clock-perturbation test shifts `startUnixUs` within tolerance without losing the holder; the previous-release e2e crosses a version boundary where the previous binary still writes one-field gates; both platforms green; drishti pair green at final kolu HEAD.

**Manual QA:**
- The incident, replayed: run **master** kolu (old one-field gate), quit the server (kaval survives), launch the **PR build**, hit Restart kaval — it must actually restart (gate pid found through the legacy shape). This exact sequence bricked in #2011.
- The rollback: run the **PR build** (two-field gate), quit, relaunch **master**, Restart kaval — still works (old reader's `parseInt` stops at the tab; pid-first is the contract).
- Clock shake: on a test host, `sudo date -s '+3 sec'` (or suspend/resume) while a daemon runs, then Restart — the holder is still recognized (tolerance), not treated as pid-reuse.
- Same two sequences on a drishti-monitored host for the agent daemon (the gate is shared API now).
