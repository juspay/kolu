## The window the framework created and then ignored

`@kolu/surface-daemon` sells durability: a daemon that survives its supervisor's deploys. Durability *creates* the mixed-version window — a new-build supervisor talking to an old-build daemon through shared artifacts (pid gate, unix socket, state files) — and today the framework stops at detection primitives while every consumer discovers the window's edges by hand. kolu found the cost in production: a gate-format change made the new reader *refuse* the legacy gate shape, so the recycle path had no pid to SIGTERM and **Restart kaval silently did nothing**.<Footnote>The <PrLink pr={2011} /> incident: the parked branch's `pidGate.ts` moved to a two-field `pid\tstartUnixUs` gate whose reader "accepts exactly this build's two-field identity; it never interprets the retired one-field pid shape" — a legacy gate parsed as `unsupported-format`, `gatePid()` returned `undefined`, and Restart no-oped. No test could catch it: every test in the repo boots both daemon generations from one checkout. The full adoption is parked on branch `osfacts-kolu-adoption` (tip `dc104661`), kept reachable because drishti pins commits on that history.</Footnote>

The framework is further along than the issue's framing suggests. Since <PrLink pr={1674} />, `surface-daemon-supervisor` already owns the convergence kit — `ConvergenceIdentity` (ordered `contractVersion`, match-only `build`), `ConvergencePolicy<Cap>`, the pure `decide()` table, `BuildDrainFence`, `converge()`, and the endpoint machine with its `incompatible` state and gateless-squatter recovery. What kolu still hand-rolls, and what this plan graduates, is precisely bounded:

1. **The drain skeleton** — `drainAndAwaitExit` in `packages/server/src/padi/padiConvergence.ts:103`: arm the exit-observer *before* firing the drain RPC, race exit against a ceiling, ground truth is the process exiting — never the RPC resolving.
2. **Drain admission** — the remote arm's instance-keyed budget (`remotePadiBinding.ts` `admitDrain`): a different daemon instance after our drain means *another supervisor is fighting us* → give up loudly; the same instance past the budget → adopt stale. The framework's boolean fence is the degenerate case of this.
3. **The post-drain story as typed states** — the remote arm's `adopted-stale` / `skew-refused` / `unconverged` discriminated union (`packages/common/src/surface.ts:387`) is app-typed; the local arm can't even express adopt-stale because `decide()` collapses a fence-spent adopt to a bare `adopt` (the gap named at `padiBinding.ts:738-741`).
4. **The ssh arm itself** — `remotePadiBinding.ts` bypasses `converge()` entirely and hand-spells the enactment switch over a raw `decide()`. Drishti's daemon is remote-only, so this is not an edge case to tolerate: it is the second consumer's *main* path.
5. **The window tests** — <PrLink pr={2027} />'s yesterday-daemon fixture, shared-artifact watchdog, and previous-release e2e live in `packages/padi/src/upgradeWindow/`, guarding kolu's window with machinery that is ~60–100% generic per file.

## Drishti — the durable per-host agent

Today drishti's agent is the textbook ephemeral `serveOverStdio` consumer: every ssh dial provisions the parent-pinned nix build and spawns a fresh process, so agent state dies per reconnect and the parent's 30-minute metric ring dies per deploy.<Footnote>Correcting the issue's framing: history does *not* die with the tab — since drishti's SR-track work it lives in a per-host ring in the parent (`router.ts`), replayed to any browser. What kills it is a parent restart (every home-manager deploy) and host removal; agent-side alert hysteresis and rate baselines die on every reconnect.</Footnote> Also today, *skew is impossible by construction* — spawn-per-dial means agent ≡ parent build. The durable daemon makes skew the steady state, which is exactly why drishti is the right second consumer: frequent deploys, two parent platforms, remote-only supervision, and a real cross-supervisor topology.

The design, with the author's decisions baked in:

- **One flag-dispatched binary.** `drishti-agent --stdio` becomes the front (`frontDaemonOverStdio`, `spawnDaemon: reExecAsDetachedDaemon` with `--daemon`); `--daemon` runs `daemonProcessMain` + `daemonMain` serving the existing agent router over a unix socket. The parent's wire is unchanged — the front relays bytes, so `sshConnector`, `makeSession`, and `pumpRemoteSurface` keep their exact shapes; the session upgrades to `DaemonSession` to expose `convergence()` and `renew()` on the host-map entry.
- **Paths and lifetime.** Socket `$XDG_RUNTIME_DIR/drishti/agent.sock` (fallback `/tmp/drishti-$UID/`), gate `agent.pid` beside it; state dir `${XDG_STATE_HOME:-~/.local/state}/drishti/` is the daemon's `anchor`. Lifetime: `idleTimeout` 60 minutes with zero live socket connections — twice the history retention, so any reconnect that could still see useful history finds the daemon alive, and hosts you stop monitoring self-clean.
- **The ring moves into the daemon, and onto disk.** The parent-local ring and `metricHistory` stream move agent-side (the snapshot-then-delta schema already lives in agent-shared `surface.ts`); the daemon persists the ring to `history.ring.json` (explicit `v` field, samples older than retention dropped on load) every 30 s and on drain. History now survives reconnects, parent deploys, daemon renewals, and crashes — and drishti exercises all three artifact seams: gate, socket, state file. Alert hysteresis becomes durable as a side effect of living in the daemon.
- **Identity and convergence.** The agent surface gains a contract version (`AGENT_SURFACE_VERSION = "1.0"`) and serves the UW2 `controlCore` fragment (`hello` carrying `surfaceVersion` / `buildId` / `startedAt` / `stateDir`, plus `drain`). Parent policy: `drainable`, contract skew `drain-newer-else-refuse`, build mismatch `drain-and-replace`, admission instance-keyed on `startedAt` — all via `convergeAdmit`, zero drishti-side convergence logic.
- **Operational edges, named.** The provisioning GC root must outlive the dial for the daemon's lifetime (today's root covers the ephemeral case; `nix-collect-garbage` deleting a running daemon's closure is a UW3 bug to prevent). Laptop-wake `recheckAll` must adopt, not respawn — the front's adopt path gives this for free. Drishti's `drv-stability` CI node inverts from optimization to convergence signal: accidental agent-drv churn now means fleet-wide daemon renewals (history handoff makes this survivable, but the node stays required). Off-nix dev parents adopt whatever runs, per the existing `off-nix` decide row.

## Phases

Four PRs, strictly sequenced — each later phase consumes API the earlier one creates. Standing obligations: every phase updates the paired `website/src/content/surface/ref-*.mdx` reference pages and snippet files in the same PR (`.claude/rules/surface-reference.md`), and every phase posts an odu-impact verdict — `odu serve` consumes both packages at its loose pin, so verdicts apply from UW1, before the drishti pairing gate does.

### UW1 — the supervisor kit completes: drain, admission, anomaly, both transports

`surface-daemon-supervisor` gains `drainAndAwaitExit`, `createDrainBudget` (replacing `BuildDrainFence`), the `adopted-stale` outcome, the `ConvergenceAnomaly` union, and `convergeAdmit`; kolu's local and remote padi arms migrate onto them in the same PR. **Done when:** `remotePadiBinding.ts` no longer calls `decide()` directly nor defines `admitDrain`/`convergeNewerContract`/`convergeBuildMismatch`; the `adoption-padi-upgrade` VM arm still greps its breadcrumb green; and a new unit arm pins the previously-inexpressible local outcome — a fence-spent (budget-exhausted) adopt on the *local* arm surfaces `adopted-stale` through `padiBinding.ts`'s `convergence()` instead of `null`. No drishti pair (drishti consumes neither package yet); odu-impact verdict required.

### UW2 — identity fragment + the upgrade-window testlib

`surface-daemon` gains the frozen `controlCore` fragment + `probeDaemonIdentity`, and the `./upgrade-window.testlib` subpath per the table above; padi's `controlCore.ts` migrates onto the fragment; `recycleForeignGate` and `socketContractMismatch` move to the supervisor's suite; kolu's `upgradeWindow/` dir shrinks to registrations and kolu-specific tests, with `supervisor.pid` registered. **Done when:** `packages/padi/src/upgradeWindow/` contains no generic machinery (the fixture, matchers, harness, and watchdog factory are imported from the subpath); `dialPadiHello`'s observable behavior is unchanged (existing hello tests green); the `ci::upgrade-window` node is green on both platforms via the graduated harness. No drishti pair; odu-impact verdict required.

### UW3 — drishti adopts: the durable agent, paired era begins

The kolu-side PR extends `.claude/rules/surface.md` paths to `packages/{surface-daemon,surface-daemon-supervisor}/**` (the pairing rule and odu-verdict requirement now cover them permanently) plus whatever small framework needs adoption surfaces. The paired drishti PR implements the design above: daemon mode + front, on-disk ring + agent-side `metricHistory`, contract version + control core, `convergeAdmit` policy, artifact registry + watchdog + previous-release e2e in drishti CI, GC-root lifetime fix, wake-adopts verification. **Done when the proof path is hit, not the feature around it:** drishti's e2e drives a *real* mixed-build window over ssh — a previous-build agent daemon survives, the current parent's `convergeAdmit` executes `drain-and-replace` on the build axis through the framework's `drainAndAwaitExit`, and the successor serves history re-seeded from `history.ring.json` — and separately, a reconnect within the idle window adopts the surviving daemon through `frontDaemonOverStdio` with the ring intact. Both PRs green, drishti pinned to final kolu HEAD.

### UW4 — capstone: the gate change that bricked, re-landed window-compatible

`surface-daemon`'s gate becomes versioned identity: writes `${pid}\t${startUnixUs}\n`, reads **both** shapes — a legacy one-field gate parses as `{ pid, startUnixUs: undefined }`, meaning *a valid, older gate whose holder can be signaled*, never an unreadable refusal; `acquirePidGate` takes `{ self: ProcessIdentity, readProcessIdentity }` (injected — kolu and drishti both supply osfacts-backed readers; the framework bakes no fallback). The parked branch is the starting point, not the design. Scope is the gate-identity slice only: the rest of `osfacts-kolu-adoption` (memorySampler via osfacts, V2 facet UI) remains [OSF8's](./os-facts-tool.html), which this phase unblocks — os-facts-tool.mdx's OSF8 row gets a one-line pointer here. **Done when the incident is a red-turned-green test:** the graduated fixture plants a legacy *one-field* gate under a current supervisor and recycle succeeds by SIGTERM-ing the recorded pid (the exact <PrLink pr={2011} /> failure); the previous-release e2e crosses a version boundary where the previous binary still writes one-field gates; both platforms green; drishti pair green at final kolu HEAD (the gate is now shared API).
