## What this is about

`@kolu/surface-daemon` gives you a daemon that survives its supervisor's deploys. Nice. But think about what that means: after a deploy, the *new* supervisor is talking to *yesterday's* daemon, through files on disk they both think they understand — the pid gate, the socket, the session files. That's the **mixed-version window**. Durability creates it. The framework currently pretends it doesn't exist, so every app that adopts a durable daemon discovers the window the hard way.

kolu discovered it in production. We changed the gate file format; the new code refused to read the old format; so when you clicked "Restart kaval", the restart code couldn't find the old daemon's pid, couldn't kill it, and did *nothing*. Silently. No test caught it, because every test in the repo builds both sides from the same checkout — the two sides can never disagree in CI, only in real life.<Footnote>The gory details: the parked branch's `pidGate.ts` moved to a two-field `pid\tstartUnixUs` gate, and its reader "accepts exactly this build's two-field identity; it never interprets the retired one-field pid shape." So a legacy gate parsed as `unsupported-format`, `gatePid()` returned `undefined`, and Restart no-oped. The whole adoption is parked on branch `osfacts-kolu-adoption` (tip `dc104661`), kept alive because drishti pins commits on that history.</Footnote>

The fix isn't "be more careful." The fix is making the window a first-class thing the framework owns: version skew shows up as *typed states*, never silence; replacing an old daemon is a *protocol*, not five hand-rolled functions; every file both generations touch is *versioned and inventoried*; and the tests that catch this stuff ship *with the framework*, so the next consumer gets them for free.

Half of this already exists. <PrLink pr={1674} /> put the convergence kit in the supervisor package: identity types, policy, a pure decision table, `converge()`.<Footnote>Namely: `ConvergenceIdentity` (contract versions order, build ids only match — nix store hashes have no "newer"), `ConvergencePolicy&lt;Cap&gt;`, `decide()`, `BuildDrainFence`, and the endpoint state machine with its `incompatible` state and squatter recovery.</Footnote> What kolu still hand-rolls — and what this plan moves into the framework — is exactly five things:

1. **The drain skeleton.** Start watching for the process to exit *before* you send the drain RPC, then race the exit against a timeout. The truth is the process exiting, never the RPC returning.<Footnote>`drainAndAwaitExit` at `packages/server/src/padi/padiConvergence.ts:103`. The local arm and the ssh arm each have a copy.</Footnote>
2. **Drain admission.** How many times do you try before giving up? And if the daemon you drained comes back as a *different* instance — that means another supervisor respawned it, and you should back off instead of fighting.<Footnote>`admitDrain` in `remotePadiBinding.ts`, keyed on daemon instance. The framework's boolean `BuildDrainFence` is the trivial case of this.</Footnote>
3. **Typed outcomes.** "I adopted a stale daemon", "I refused a skewed one", "another supervisor owns this" — these are states the UI should show, not log lines. Today they're an app-side union with a bolted-on side flag, and the local arm can't even express "adopted stale".<Footnote>The union lives at `packages/common/src/surface.ts:387`. The cross-supervisor fact isn't an arm — it's a `crossSupervisorDetail` flag with one set site, six clear sites, and a must-check-first ordering hazard. The local gap (`decide()` collapses a fence-spent adopt to plain `adopt`) is named in a comment at `padiBinding.ts:738-741`.</Footnote>
4. **The ssh arm.** `remotePadiBinding.ts` skips `converge()` entirely and hand-writes the whole enactment over raw `decide()`. Drishti's daemon is remote-*only*, so this can't stay a kolu hack.
5. **The tests.** <PrLink pr={2027} /> built a fixture that fakes "yesterday's daemon", a watchdog over shared files, and an e2e that builds the previous release for real. All of it sits in `packages/padi/src/upgradeWindow/`, guarding only kolu.

### Hello world

Here's what a *new* consumer writes once UW1+UW2 land — a made-up `pulse` daemon, both halves, complete except for its own cells. This example is the contract; the phases have to add up to it:

```ts
// ── daemon side: runs inside the durable process ──────────────────────────
import {
  daemonHome, daemonMain, daemonProcessMain, readBakedIdentity, controlCoreFragment,
} from "@kolu/surface-daemon";

const ident = readBakedIdentity("PULSE"); // PULSE_BUILD_ID / PULSE_COMMIT_HASH, baked by nix
const home = daemonHome({ app: "pulse", placement: "state" }); // durable ⇒ state dir, never /run
daemonProcessMain({
  name: "pulse-daemon",
  run: () => daemonMain({
    home,                        // gate, socket, anchor — all derived inside the spine
    lifetime: { kind: "idleTimeout", ms: 60 * 60_000, isIdle: () => liveConnections === 0 },
    router: implementSurface(pulseSurface, {
      // the frozen fragment: hello + drain, readable at ANY version skew
      ...controlCoreFragment({
        surfaceVersion: PULSE_CONTRACT_VERSION,
        buildId: ident.staleKey, commit: ident.navigableCommit,
        stateRoot: stateDir, startedAt: bootInstant,
        onDrain: persistStateThenStop,
      }),
      /* …pulse's own cells and procedures… */
    }),
    log,
  }),
});

// ── the policy IS the consumer's entire convergence surface ────────────────
// baked folds into the policy: who I am + how I converge, stated once, read by
// both enactments. (UW1 human-negotiated contract.)
const POLICY: ConvergencePolicy<"drainable"> = {
  capability: "drainable",
  baked: { contractVersion: PULSE_CONTRACT_VERSION, build: daemonBuild(myBakedId) },
  onContractSkew: { kind: "drain-newer-else-refuse" },
  onBuildMismatch: { kind: "drain-and-replace" },
  drainBudget: { maxAttempts: 2, onGiveUp: "adopt-stale" }, // unspellable on "not-drainable"
};

// not-drainable consumer (kaval): drainBudget is UNSPELLABLE (type error) —
// today's inert-fence ritual is DELETED, not renamed.
const KAVAL_POLICY: ConvergencePolicy<"not-drainable"> = {
  capability: "not-drainable",
  baked: { contractVersion: PTY_HOST_CONTRACT_VERSION, build: daemonBuild(kavalBakedId) },
  onContractSkew: { kind: "recycle" },
  onBuildMismatch: { kind: "nudge-human" },
};

// ── endpoint arm (local supervisor) ──────────────────────────────────────
const endpoint = createEndpoint({
  home: daemonHome({ app: "pulse", placement: "state" }), // SAME call — disagreement impossible
  policy: POLICY,                              // fixed here — boot-method trio goes INTERNAL
  probe: (socketPath) => probePulse(socketPath),
  driver: survivableSpawnDriver({ binPath, args: ["--daemon"], env, unitPrefix: "pulse" }),
  connect: (socketPath) => connectPulse(socketPath), // the framework hands you the path
  log, onStatus,
});

const outcome = await converge(endpoint);    // the ONLY boot verb
showOnEntry(outcome.anomaly);
// anomaly?: adopted-stale | skew-refused | unconverged | cross-supervisor
// each arm carries evidence; absence = converged clean. link-failed is NOT
// a framework arm (session-owned; consumers union it in app-side).

await recycle(endpoint, { capture, drain, reattach });  // the ONLY replace verb

// ── connector arm (ssh — SAME policy object, no endpoint) ────────────────
const verdict = await convergeAdmit({
  running: identityFrom(hello),              // what the dial found
  policy: POLICY,
  budget,                                    // per-boot memory; survives adopts
  drain: () => client.control.drain(),       // fire-the-verb plug only
  awaitExit: (signal) => pollHelloGone(signal), // framework races exit vs ceiling
  ceilingMs: 6000,
  log,
});
// verdict: adopt | replaced | refuse — same anomaly type as the endpoint arm
```

Commitments in that example: (1) policy object = whole surface, no fence object, no admit hook, no boot-method choice; (2) endpoint public verbs are exactly `converge` + `recycle`; (3) `convergeAdmit` takes plugs (fire + observe), the framework owns the race/ceiling/budget/cross-supervisor memory; (4) one anomaly type across both arms.

## Drishti: the second user

Today drishti's agent is spawned fresh on every ssh dial and dies with the link. That means agent-side state dies on every reconnect, and the parent's 30-minute metric ring dies on every deploy of the parent.<Footnote>Small correction to the issue text: history doesn't die with the browser tab — it lives in a ring in the parent process and replays to any browser. What kills it is restarting the parent (i.e. every home-manager deploy). The agent-side losses per reconnect are the alert hysteresis and the rate baselines (first tick after respawn shows zero rates).</Footnote> It also means version skew is currently *impossible* — every dial spawns the parent's own pinned build. A durable daemon flips that: skew becomes the normal state after every deploy. Which is exactly why drishti is the right second user — frequent deploys, two platforms, remote-only, and the two-laptop cross-supervisor case for free.

The design:

- **One binary, two modes.** `--stdio` becomes the front (`frontDaemonOverStdio`: adopt the running daemon or spawn one, then relay bytes); `--daemon` serves the existing agent router over a unix socket. The parent doesn't change its wire at all — `sshConnector`, `makeSession`, `pumpRemoteSurface` all keep their shapes. The session becomes a `DaemonSession` so the host entry can show `convergence()` and offer `renew()`.
- **All files under `~/.local/state/drishti/`** — gate, socket, ring — via `daemonHome({ app: "drishti", placement: "state" })`, no hand-rolled paths. *Not* `$XDG_RUNTIME_DIR`.<Footnote>Because on a stock systemd host, logind deletes `/run/user/$UID` when your last ssh session closes. The socket and gate vanish while the detached daemon keeps running — now it's an orphan nothing can find, racing its successor for the ring file. State-dir sockets go stale across reboots instead, which the pid gate and the socket-accepting probe already handle correctly.</Footnote> Lifetime: exit after 60 minutes with no connections — twice the history window, so any reconnect that could still show useful history finds the daemon alive, and forgotten hosts clean themselves up.
- **The ring moves into the daemon and onto disk.** `history.ring.json`, with a `v` field, written every 30 s and on drain (atomic temp+rename). If a loader meets an unknown `v` or garbage, it *leaves the file alone* and reports a typed "history unavailable" state — never a silently empty chart.<Footnote>The unknown-`v` case is the rollback window: an older daemon reading a newer daemon's file. Starting empty there would be the #2011 pattern all over again — recognizable-but-refused turning into silence. Corrupt files get moved aside, never deleted. Both cases get tests: a planted `v+1` ring and a truncated one. Net result: history survives reconnects, parent deploys, daemon upgrades, and crashes — and drishti exercises all three shared-file kinds: gate, socket, state file.</Footnote>
- **Identity and convergence.** The agent surface gets a contract version (`"1.0"`) and serves the fragment. The parent's policy: drainable, `drain-newer-else-refuse` / `drain-and-replace`, budget `{ maxAttempts: 2, onGiveUp: "adopt-stale" }`, all through `convergeAdmit`. The only convergence code drishti writes is that policy object and the link-state projection at the edge.<Footnote>The two-laptop story, since it's drishti's bread and butter: you deploy laptop A, laptop B still runs yesterday's pin. Builds don't order, so neither is "right". The budget caps the fight at `maxAttempts` drains per laptop per boot; the first laptop that sees a lineage it drained come back under a foreign instance parks in `cross-supervisor`; and because both chose `adopt-stale`, both keep monitoring through whichever build won — one of them showing a labeled anomaly — until the pins converge. The alternating-drain scenario gets a framework unit test in UW1; we don't leave livelock to luck.</Footnote>
- **Sharp edges, named.** The nix GC root has to outlive the dial for as long as the daemon runs (or `nix-collect-garbage` deletes the running daemon's closure). Laptop wake must adopt, not respawn — the front gives that for free, but the e2e has to prove it through the nasty case: close the *last* ssh session, then reconnect. And drishti's `drv-stability` CI check changes meaning: an accidental agent-drv change used to cost a cache miss, now it costs a fleet-wide daemon restart.

## The plan

Six PRs. UW0 opens — small and behavior-free. UW1 → UW2 → UW3 → UW4 is a strict chain — each needs the previous one's API. UW5 needs only UW2 and can land any time after it, in parallel with the rest. Every phase updates the surface reference docs in the same PR and posts an odu-impact verdict.<Footnote>odu doesn't consume either package yet — `odu serve` (the parent note's S2) hasn't shipped. So verdicts will be `none` or `adoption-opportunity` for a while; the point of posting them anyway is that the ledger catches the exact moment that changes.</Footnote>

### UW0 — daemonHome: where a daemon's files live, decided once

**TL;DR:** a daemon's on-disk home — directory, gate, socket, extra files — comes from one framework call instead of per-app path algebra, and **all three daemons ride it**: kaval and padi delete their hand-rolled path derivation and call `daemonHome`, with the paths proven byte-identical by test. The call forces the one decision that actually matters (durable state dir vs session-scoped runtime dir) and returns registry entries for every file it names, so the shared-file inventory is fed by construction.

Lands: `daemonHome({ app, placement: "state" | "runtime", instance? })` in `surface-daemon` — creates the dir `0700`, verifies ownership (fail-fast on a non-private dir), returns `dir` / `gatePath` / `socketPath` / `file(name)` / `artifacts`.<Footnote>Placement semantics: `"state"` → `~/.local/state/<app>/` ($HOME only — ignores `$XDG_STATE_HOME` so launch contexts cannot split identity); `"runtime"` → `$XDG_RUNTIME_DIR/<app>/` with the `/tmp/<app>-$UID` fallback. A held gate whose co-located socket is **dead** is reclaimed; a missing socket while the PID is live is treated as still-starting (gate-first fence). The doc comment carries the rule this API exists to enforce: a daemon that must outlive user sessions — anything supervised over ssh — takes `"state"`, because logind deletes the runtime dir with the user's last session.</Footnote> And `daemonHome` is a **framework primitive, not an upstreamed helper**: the spine speaks it — `daemonMain`'s spec and the supervisor's endpoint accept a `DaemonHome` and derive gate/socket from it, so loose path strings disappear from consumer call sites (overrides like an env-var socket path are absorbed into the home's construction, not sprinkled at call sites). The `instance` mode carries padi's digest-keyed namespacing (`padi-<digest>/`, kaval's dir off the same digest), built for its real consumers: **kaval and padi swap their derivation for `daemonHome` in this PR**. Nothing moves on disk — golden tests assert every derived path is byte-identical to today's, and the discovery functions (`discoverKavalDaemons`, `resolveRunningPadiSocket`, kaval-tui autodiscovery) keep their signatures, consuming `daemonHome` internally. The `SharedArtifact` type lands here too (UW2's matcher machinery consumes it); the hello-world snippets and the fleet-top example adopt it as reference consumers.

**Done when:** unit tests pin `0700` creation, the non-private-dir refusal, and both placements; golden tests pin every kolu path (kaval gate/socket/dir, padi gate/socket/state paths, manifest, logs) byte-identical to the pre-swap derivation; `socketPath.ts` / `stateRoot.ts` contain no path algebra `daemonHome` owns; discovery signatures unchanged, kaval/padi e2e green; the fleet-top part-2 example and website snippets build on it; reference docs updated. No drishti pair (nothing external consumes yet); odu verdict required.

**Manual QA:** pure absence-of-change. Run master kolu, quit, run the PR build: surviving padi and kaval are found and adopted, Restart works, and `ls` of the daemon dirs shows the same files at the same paths as before.

### UW4 — re-land the gate change, without the brick

**TL;DR:** the gate file gains a second field (process start time — kills pid-reuse misidentification), governed by one law: **the first token of a gate file is the pid, in every generation, and readers ignore anything after it.** Restart then works across every upgrade *and* rollback boundary. This unblocks [OSF8](./os-facts-tool.html).

Lands: the two-field writer (`${pid}\t${startUnixUs}\n`); the tolerant reader (a one-field legacy gate is simply an older gate — pid usable, start time unknown); `acquirePidGate` taking an injected `readProcessIdentity` (kolu and drishti supply osfacts-backed readers); start-time comparison with ±2 s tolerance; and the mid-boot holder case (gate written, socket not yet listening → wait, don't reap).<Footnote>Why not just un-park the branch: `dc104661`'s reader refuses every shape but its own. That both replays the #2011 brick against old gates and sets up the next one — a v2 reader meeting a v3 gate. So the parked branch donates its writer and identity plumbing, not its reader. Why the tolerance: the start instant is derived from `/proc/stat` btime at read time, and NTP steps / suspend / VM pauses shift it by whole seconds — strict equality would misread a live daemon as pid-reuse and brick from the other direction. Scope: gate-identity only; the rest of `osfacts-kolu-adoption` (memorySampler via osfacts, facet UI) stays OSF8's, which this unblocks — os-facts-tool.mdx gets a one-line pointer.</Footnote>

**Done when the incident is a red-turned-green test, both directions:** the fixture plants a legacy one-field gate under a current supervisor and recycle SIGTERMs the right pid (the literal #2011 case); a unit test feeds the two-field write through the legacy parser and gets the pid back (pid-first is the frozen rollback contract); a clock-shift test stays within tolerance without losing the holder; the previous-release e2e crosses a boundary where the previous binary still writes one-field gates; both platforms green; drishti pair green at final kolu HEAD (the gate is shared API now).
