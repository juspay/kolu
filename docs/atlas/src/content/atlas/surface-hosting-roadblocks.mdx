The agent's inventory found: **neither drishti nor odu calls `identity()` today** — the only `identity()` reader is kolu-server's padi arm, off padi's own control-core hello. (They *may* consume `@kolu/surface-daemon` — it's not forbidden; it's just a fact of the current code that they don't, and that no one but kolu reads identity.) That one fact drives the answers.

## 1. Why "universal hello" can't ride this refactor

First, the test the whole argument hinges on — and **what it's for**:

```ts
// odu's lane surface has exactly three members, and a test locks that set:
test("laneSurface members", () => {
  expect(memberNames(laneSurface)).toEqual(new Set(["progress", "logLine", "result"]));
});
```

<Callout kind="note" title="What this test is FOR (it's the point of the whole roadblock)">
A surface is a **contract between two processes** — one `implementSurface`s it (the server), another holds a client (the consumer) — often on different machines or different deploys. **The set of members IS that contract.** If a member is silently added, removed, or dropped by a refactor, the two sides drift: the consumer asks for a member the server no longer serves, or misses a new one, and it fails at runtime, across a wire, hard to trace.

This test **freezes the exact member set**. Any change to it fails the test — and that failure is the *feature*: it forces a human to look and say "yes, I meant to change this contract" (bump the version, update the consumer). It makes contract changes **deliberate and reviewed, never accidental.**

So: adding a universal identity member would trip **every** such test in the repo — which is exactly correct, because it genuinely changes every contract. That's the proof it's a *behavior change*, not a rename.
</Callout>

"Universal hello" means the framework makes **every** surface serve an identity member — `defineSurface` injects a reserved one into all of them:

```ts
function defineSurface(members) {
  return implement({ ...members, system: { live, identity } }); // `identity` is NEW (live already exists)
}
// now laneSurface has FOUR members, and the test above FAILS:
//   Set(["progress","logLine","result","system"]) ≠ Set(["progress","logLine","result"])
```

That trips every set-equality test, changes every surface's type/variance, and moves the seal. It's a real feature (`system.live` proves the pattern) — just its **own PR**, not part of a behavior-preserving refactor.

**So for THIS refactor, identity lives where padi already serves it — the daemon arm.** The two options, named plainly (this is what "(a)/(b)" referred to):

```ts
// OPTION A — identity() on the BASE Session role:
const s = makeSession({ connectOnce: sshConnector({ host }) }); // drishti / odu path
s.identity();  // → null.  forever.  (that far end serves no hello yet)   ← the silently-absent smell

// OPTION B — identity() on the DAEMON sub-role only (proposed):
interface DaemonSession<Client> extends Session<Client> {
  identity(): SurfaceIdentity | null;  // ← from control.core.hello(), which padi serves TODAY
  convergence(): DaemonConvergence | null;
  readonly preservation: PreservationStrategy;
  renew(): Promise<void>;
}
// base Session has no identity() → a plain ssh session physically CAN'T return null-forever.
```

**Option A** puts `identity()` on the base role now, so every non-daemon session answers `null` forever — the exact smell we killed elsewhere — and it *still* needs the universal-hello feature later to become non-null. It buys nothing. **Option B** is clean now and graduates cleanly: when the universal-hello PR lands, `identity()` simply *moves up* from `DaemonSession` to `Session`, and nothing is null-forever because by then every server answers.

> **srid's universal-hello ruling stays the destination.** This only sequences it: **Option B now · universal hello as its own follow-up PR · then identity graduates to the base role.** — needs your explicit yes.

## 2. Fleet verbs go on `Session` (your call — and it's cleaner)

You asked why `reconnect()`/`recheck()` can't just be on `Session`. **They can, and they should** — for the same reason the role is `Session` not `ReconnectingSession`: *every* session reconnects (a one-shot is a dial, not a session), so the manual triggers of that universal capability belong on the role, not bolted on as an intersection.

```ts
interface Session<Client> {
  pin(): Promise<Client>;
  currentClient(): Promise<Client> | null;
  isDestroyed(): boolean;
  onState(cb): () => void;
  markConnected(): void;
  destroy(): void;
  reconnect(): void;   // force a redial now — universal to sessions
  recheck(): void;     // re-probe liveness now — universal to sessions
}
```

This drops the awkward `Session & { reconnect; recheck }` intersection the note had. The only nuance it leaves: **whether a REGISTRY surfaces `registry.reconnect(host)` is still a per-registry choice** (S2) — the *session* always has the method, but the registry exposes a fleet verb only when built with `controls` (drishti's fleet does; kolu's future pool need not). The `controls` callback is now a trivial passthrough:

```ts
buildHostRegistry({
  buildEntry: (host) => ({ session: makeSession({ connectOnce: sshConnector({ host }) }), handler }),
  controls: { reconnect: (s) => s.reconnect(), recheck: (s) => s.recheck() }, // trivial now
});
// controls supplied ⇒ registry.reconnect(host)/recheckAll() EXIST (typed). Omitted ⇒ they don't.
```

(One honest cost: `reServeSurface` consumes `Session` and now carries two methods it never calls — harmless, since they're *guaranteed present*, not optional-maybe-absent. The registry's own minimal slot stays `DestroyableSession { destroy() }`, unchanged.)

## 3. The name: `SurfaceIdentity` (your call — and it's the better one)

You proposed `SurfaceIdentity`, reasoning "this is only used for surfaces, and a surface's implementor is by definition a server." **Agreed — it's better than `ServerIdentity`**, and the universal-hello destination is why: under universal hello, identity is literally a **member of every surface** (`system.identity`). So the value is *"the identity a surface carries"* — named for the framework's core noun, not the implementation detail that there's a server behind it. It also dodges the overloaded word "server" (kolu-*server* means something else entirely).

```ts
// @kolu/surface
interface SurfaceIdentity {
  contractVersion: string;
  startedAt: number;
  buildId: string;        // the build's content hash — convergence CURRENCY (staleKey)
  commit: string | null;  // human-navigable source commit — a DISTINCT field, never merged
}
```

Lives in **`@kolu/surface`** (the base package) so it's already home when universal hello ships. The colliding `kolu-common ServerIdentity` (the PWA identity) is kolu's to rename — the framework name is perfect; the app moves.
