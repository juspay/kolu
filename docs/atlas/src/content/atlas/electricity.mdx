<Callout kind="good" title="What counts as electricity">
Löwy's receptacle — hide the volatility behind a socket you plug into. Three tests at once: ① **domain-agnostic** — no terminal/canvas/git/xterm leaks into the interface; ② **encapsulates a real volatility** — an axis the system actually *varies* along (transport, reconnect, GPU-context loss, persistence), not a stable 3-line `===`; ③ **graduates** — ships as `@kolu/*` and a *different* app plugs in. The proof of ③ is real, not aspirational. [`@kolu/surface`](https://kolu.dev/blog/surface-framework/) is **kolu's own** client↔server transport first — and it has since picked up a **second consumer** in [srid/drishti](https://github.com/srid/drishti) (a fleet process-monitor; browser ↔ Bun ↔ ssh-agent) that vendors it from this repo and declares its own per-host schema with none of kolu's domain. The second consumer isn't the *point* of the extraction — it's the *proof* it was real electricity: surface never noticed the domain changed.
</Callout>

<Callout kind="danger" title="How a session mis-identifies electricity — three traps, learned the hard way">
The live example: asked to add back/forward to the Code-tab preview, a session proposed extracting a **history stack**. Wrong three ways, each caught only by re-asking the test above — and the solid-browser extraction ([archived](./archived-notes.html)) is the corrected end-to-end.

- **Naming an organ, not the concept.** A history stack is a *transformer* — a working part *inside* a larger thing. The electricity was the **browser** (location + history + link-nav + render-host); history is one chamber of it. Test: *is the name self-describing standalone?* "history" → history **of what?**; "browser" → obvious. If you must append "…of X" to explain the name, you've named a part, not the receptacle.
- **A module in `client/src/` is not electricity.** Location *is* structure (Hickey): a generic-looking helper living inside the app is **part of the app**, however agnostic the code reads. Electricity is its **own package**, the dependency arrow pointing *out* — `client → @kolu/x`, never back. (`createSharedRoot` sits in `client/src` marked "publish?" — a leaf *awaiting* graduation, **not** a precedent for calling in-app modules electricity.)
- **Agnostic ≠ electricity — apply test ② honestly.** A clean, reusable, agnostic primitive that hides only a *bounded algorithm* (a stack, a debounce, an `===`) is a **leaf** (`nonempty`/`html-escape`-tier), not a receptacle. "I found a tidy generic module" is the feeling that *precedes* the mistake. Ask what **volatility** it actually encapsulates — what axis of *change* (transport, GPU-context loss, sandboxing, reconnect) — before reaching for `@kolu/`.
</Callout>

> **"Decompose based on volatility"** — Löwy's directive: encapsulate each area *likely to change* behind a stable interface, rather than split a system by what it *does*. "Electricity" is *his own* example, and the source of our term: *"the electricity that powers a house … is highly volatile: power can be AC or DC; 110 volts or 220 volts … produced by solar panels … a generator … or plain grid connectivity … All that volatility is encapsulated behind a receptacle … all the user sees is an opaque receptacle."* The body does the same — blood-pressure, salinity, and pulse volatility *"encapsulated behind the service called the heart."* An *electricity*, in kolu, is one such volatility lifted into its own `@kolu/*` package; a *receptacle* is the socket a consumer plugs into. — Juval Löwy, [*Software System Decomposition*](https://www.informit.com/articles/article.aspx?p=2995357&seqNum=2), ch. 2 of *Righting Software*.

<Callout kind="good" title="surface-app's stale-tab gate — what graduates, what stays a socket the consumer plugs in">
The restart axis already lived in `createServerLifecycle` (`restartCloseCode` + the `transport:"open"\|"closed"` discriminant), so <PrLink pr={1231} /> only had to graduate the **shared** pieces and leave the **per-socket** ones behind. The split is the whole test ① at work — none of the graduated parts knows a terminal from an ssh-agent.

**Graduates** (the second consumer shares the *identical* partysocket + oRPC stack, so the volatility is genuinely common): the `pid`/`4001` constants and a runtime-free `rejectStaleProcess(claimedPid, liveId): boolean`; `serverIdentity()` **returning** its minted `processId` so the gate compares against the SAME id `identity.info` reports (drishti otherwise mints a *second* `randomUUID()` and the gate never matches); and — the F1 reversal of the prior "keep it per-consumer" — `retireSocket`, whose two reverse-engineered side-effects (`close()` flips partysocket's `_shouldReconnect`; a **throwing** `send` makes oRPC's `ClientPeer` *reject* pending instead of letting `maxEnqueuedMessages:Infinity` grow) bind to internals drishti has byte-for-byte. It takes a structural `{ close; send }`, not a `PartySocket`, so it never drags the concrete type across the boundary.

**Stays the consumer's socket to plug in:** the socket *builder* (drishti's `makeSocket` cold-start deadlines, its `wsUrlFor` query) and the per-runtime `pid` read off the request (kolu's Node `IncomingMessage`, drishti's Bun Fetch-`URL`) — surface-app emits the id, never the URL. The client's last-known id stays a per-consumer mutable on purpose: the lifecycle's `serverProcessId()` deliberately reports `undefined` on a stale close (the only id on hand is the *dead* process), but the `pid` echo must keep re-presenting that dead id to get re-rejected — two different facts, not one projected twice, so the URL thunk owns its own `lastServerProcessId`.

**Then it graduated too (<PrLink pr={1234} />, surface-connection — [archived](./archived-notes.html)).** Reading drishti's *actual* post-#1231 source — not assuming it — overturned the "stays the consumer's socket" line above: both consumers hand-roll the *identical* partysocket construction and `pid`-echo threading (drishti's "Bun Fetch-`URL`" runtime is in fact the same `ws` stack as kolu). So the socket builder and the echo *did* graduate, as `createSurfaceSocket` + `createProcessIdEcho` in `@kolu/surface-app/connect`. The "two different facts" insight is **preserved inside the echo** — `createProcessIdEcho` still re-presents the dead id, distinct from `serverProcessId()` — it just isn't hand-rolled per consumer anymore. What genuinely stays per-consumer narrowed to **lifecycle ownership** (kolu's `rpc.ts` vs drishti's `<SurfaceAppProvider>`) and **socket topology** (one socket vs per-host + admin sharing one echo). Same lesson as the F1 `retireSocket` reversal: the boundary is set by what's *actually* duplicated, found by reading source, not by what looked per-consumer at first.

**And then the last per-consumer step graduated as well (<PrLink pr={2133} />).** Two rounds of "what's actually duplicated?" had narrowed the app's job to one line — feed `echo.remember` from the lifecycle's `onProcessId` — and a third consumer ([olai#61](https://github.com/juspay/olai/pull/61)) proved that one line was still one too many: it kept only `.client` from `connectSurface`, so no reconnect carried a `pid`, the server's gate never rejected anything, and the wire's `retired` state was unreachable. The lesson is about the *kind* of line, not its length. A receptacle may not leave a **load-bearing** step in the consumer's hands, however small — because "small" is exactly what gets dropped, and a dropped handshake step fails silently by construction (the mechanism it feeds simply never fires). So the echo feeds itself: `createSurfaceSocket` probes the framework-reserved `system/identity` member on every open, and the member grew the `processId` it had been missing — which also deleted `serverIdentity()`, `rejectStaleProcess`'s second argument, and surface-app's duplicate `identity.info`, three shapes that existed only to keep two ids in step. What is left for a consumer is the one thing a receptacle genuinely cannot decide — *what the user sees when the tab is dead* — and it is a **required** option rather than a returned value, because the earlier rounds also showed that a value handed back to be used is a step that can be skipped.

**One droppable value survived that round, and the SAME consumer dropped it (<PrLink pr={2160} />).** `connectSurface` still handed back a transport-only `status` beside a `client.health()` an app could simply never call — two inputs to one indicator, one of them optional. olai rendered the first and skipped the second, so a `documents.keys` stream that had died drew as a directory with nothing in it, **under a green light**; a three-AI Löwy debate on olai's own tree named it the second of three unfinished kolu sockets ("a receptacle that reads 110 or 220 depending on whether you also brought a voltmeter is not a receptacle"). The fix is the same shape as the echo's, one layer up: the seams fold the two facts themselves and hand back ONE `readout` — `connecting · live · degraded · reconnecting · retired`, with `needsReload` and the NAMES of whatever stopped. Note what did *not* graduate, because it is the same domain-blindness line the `liveWhen` callout below draws: the framework owns which state is TRUE and refuses to learn what any of them is CALLED — "the files on disk reach this page" is olai's sentence, in olai's `status.ts`, which shrinks to a wording table on the pin bump. Two universal rules ride with the truth (pending does not degrade; only `retired` needs a reload) precisely because they are *not* app policy — every app that hand-rolled them got them right, which is the tell that they were the receptacle's to hold.
</Callout>

<Callout kind="good" title="liveWhen — predicate-as-data: the fold graduates, the meaning plugs in">
The sharpest proof the receptacle stays domain-blind is the verb it *refuses to learn*. `client.health().live` is the full conjunction — transport-live ∧ every readiness cell's predicate — yet `@kolu/surface` core never knows what "connected" *means*. The **fold is the receptacle**: a generic `CellSpec.liveWhen?: (value) => boolean` marks a cell a readiness gate, and core AND-reduces that cell's verdict into `live` (`registry.enrollReadiness`) without ever naming a state literal. The **volatile knowledge rides the cell as data** — `surface-nix-host`'s `connectionCell` declares `liveWhen: (v) => v.state === "connected"`, and the ssh vocabulary (the predicate, the four-state enum) stays *there*, beside the schema. It's the runtime sibling of `CellSpec.equals` / `resolveCellVerbs`: core owns the mechanism, the plug owns the meaning — the receptacle is domain-agnostic, the volatility plugs in as data. So every surface mirrored through `mirroredSurface` carries its mirror-liveness leg *by construction* — no consumer hand-ANDs `connection.state === "connected"`, and no widget can paint a dot green from raw cell state. **Location is structure** in the un-obvious direction too: the `=== "connected"` *can't* migrate into core without dragging ssh's domain across the boundary, so the split isn't a convention you keep — it's load-bearing.
</Callout>

<Callout kind="warn" title="Re-evaluating @kolu/artifact-sdk — its electricity framing shifted (open; resolve outside this PR)">
"Anchoring" (the original <PrLink pr={922} /> framing) now under-describes the
package. It holds **two** volatilities: (1) the **anchoring core** (`core/` — W3C
quote extract/re-find/highlight; pure and agnostic, speaks only
`Range`/`Document`/`ShadowRoot`), and (2) the **sandboxed-iframe parent↔frame
bridge** (`client/bridge.ts` + `iframe/` — opaque-origin postMessage with
`event.source` identity as the only trust boundary). The bridge is the *harder*
volatility, and it has quietly accreted clients: comments (selection →
`SelectMsg` → highlights), then **in-frame navigation** (`observeIframeNavigation`),
then **back/forward input** (`observeIframeHistory`, <PrLink pr={1191} />). The
lens-debate in <PrLink pr={1191} /> already reframed the package's *stated*
identity to "the in-iframe sandbox bridge, with comments as one client" — but
that was a docs fix, not a decomposition.

**The open question (work it outside this PR):** is "talk to code inside an
opaque-origin sandboxed frame" one sound receptacle — a transport-grade
volatility with comments / navigation / input as interchangeable clients — or a
topic-bundle that should split the agnostic **anchoring core** from the **bridge
transport**? Note the smell that prompted this: the back/forward client landed in
this package only by *physical necessity* (the one script inside the sandbox is
this one), which is exactly the "easy to put it here" the three traps above warn
against. Flagged, not decided.
</Callout>
