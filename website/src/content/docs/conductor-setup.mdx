Every piece of work [the Conductor](/conductor) opens starts with one form. You
say how it runs, what happens when CI goes green, and which agent CLI (the
harness) and model run the planner and the implementor.

## What it asks

| Question | What you choose |
| --- | --- |
| **Mode** | Full: a planner, your approval, an implementor and review rounds. Trivial: one implementor. |
| **Planner**, **Implementor** | The harness that runs each agent, and the model it runs on. |
| **On green** | What to do when CI passes: merge the pull request, or hand it to you. |

The host is not in the form: it is part of the work itself. When your request
does not name the machine, the Conductor asks in its reply, because a path like
`~/code/app` can exist on several machines.

A question your request already answers is not asked. Each question takes one
answer, and the whole form is settled with one press of **Answer**.

## Where the harnesses and models come from

kolu offers both, not the Conductor, and starts each agent on exactly what you
chose.

- The harnesses are the ones this kolu carries.
- The models are the ones that harness offers on the work's host, asked of the
  host as the form is drawn. A long list has a search box.
- Claude Code and Codex cannot list their models. For those you get the models
  you have run before, and a box to type one.
- That box takes one model id: one word, no spaces. Anything else is refused
  with a line saying why.

## One press repeats your last setup

Every question comes with your last answer already selected, read off your
saved works. For a model that is the same role's own last model with that
harness, falling back to the other role's model with it. A setup you are happy
with is one press of **Answer**.

## When kolu refuses an answer

- A host whose coding agents are switched off, still arriving, failed to land,
  or older than this kolu needs is named, with what to do about it, before any
  harness question is asked.
- An answer is checked where it is recorded. A harness this kolu does not carry,
  or a model the host did not list, is refused there, so a work never holds a
  setup it cannot start.
- The pair is checked again when the agent starts. kolu refuses in words that
  say which answer and why, rather than starting the agent on something else.
- A saved answer kolu no longer offers is asked again when the work opens. The
  question says what the old answer was, and why it is not on offer now.
