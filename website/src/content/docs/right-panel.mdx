Every tile has a **right panel** with two tabs: an **Inspector** and a
[**Code**](/code-tab) tab. The panel follows whichever **pane** has focus, the
tile's main terminal or any split, so it is always about the terminal you are
looking at.

A work in the [Conductor](/conductor) shows some of the same parts in its
[details](/work-card#the-picked-work): the agent card and **Compose** under each
terminal's row, and the branch, pull request, CI and folder once for the work.

## What the Inspector shows

The Inspector reads top to bottom, most urgent first:

| Row | What it carries |
| --- | --- |
| the agent | Its name, what it is working on, and a state chip in that state's [colour](/notifications). |
| under it | The model, how long the agent has been running, its task progress, and how much context it has used. |
| chips | The **branch** (with a worktree glyph when it is one), the **repo**, the pull request, and one chip rolling up CI, such as `✓ 9 passed`. |
| under the chips | The pull request's title and the working directory. |
| the last line | The foreground process and the terminal's colour theme. |

Detail folds away until it is interesting: the per-check list, the repo's root
and worktree paths, and the terminal CLI sit behind expandable summaries. The
CI list opens itself when a check **fails or is still running**, with the
exceptions sorted to the top.

## odu CI

When the checkout uses [odu](https://github.com/juspay/odu) as its CI runner,
and odu's daemon is running on that host, the chip row carries a second rollup
beside the forge's checks. It reads `● odu running`, `✓ odu passed` or
`✕ 2 failed`, with the run's ref. In `abc1234#3` that is the commit's first
seven characters and the run's ordinal.

The readout is about the directory the terminal is in, so `cd` somewhere else
and it follows. The ref carries a `+dirty` marker when the run tested a working
tree, so the verdict is about code that was never committed under that hash.

Behind the chip, a disclosure holds two lists:

| List | Each row |
| --- | --- |
| the latest run's **lanes**, open by default | One `recipe@platform`, failures first, with the attempt number when it took more than one, the duration, and the machine it landed on. |
| the checkout's **recent runs**, newest first | How long the run took, fixed once it has a verdict and ticking while it is still going. |

Each lane carries a timeline bar scaled to the run, so where the bar sits says
when that lane ran.

The summary line states the run's scope: `3 lanes · ci::unit` is one recipe and
its dependencies, not the whole pipeline. A run over the whole pipeline says
nothing extra, and `--no-deps` carries the same qualifier.

### What a click opens

The chip, each lane row and each recent-runs row open what they are about in
odu's own web page. A lane row opens that attempt's log. A lane that has not
started has no log, so its row opens the run.

odu's daemon listens on the machine the terminal runs on, and your browser is
often somewhere else, so the first click forwards that port to you
([port forwarding](/remote-hosts#port-forwarding)). After that the row is an
ordinary link that <kbd>Cmd</kbd>/<kbd>Ctrl</kbd>-click, copy and "open in a new
tab" work on.

Nothing of this appears for a checkout odu does not know, or when odu's daemon
is not running. A daemon that answers with runs this kolu cannot read draws one
`odu CI unavailable` line naming the reason.

## Compose a prompt

Above the Inspector is the **Compose** box. Click into it and it grows into a
textarea with a **Send** button. Write your prompt, then click **Send** or press
<kbd>Cmd</kbd>/<kbd>Ctrl</kbd> + <kbd>Enter</kbd> to put it on the focused pane's input
line.

It inserts, it does not submit: the text lands in the agent's input box for you
to review and send yourself, like [`kaval-tui send`](/kaval). Each terminal
keeps its own draft in your browser, so a half-written prompt survives
switching tiles or reloading.

## Ports the terminal is serving

When something in a terminal starts listening on a TCP port, a **Ports** section
appears with the port number and the command line of the program holding it.
The list comes from the host's own socket table, read every few seconds, so a
port appears because something is listening and goes when that stops.

| The port is bound to | The row offers |
| --- | --- |
| all interfaces on the machine running kolu | **open**, which opens it in a new tab. |
| loopback only, or any port on a remote host | **forward & open**, which makes the port answer on the machine serving this page and opens the tab. |

A forwarded row then carries a `⇄ :<port>` pill naming where it answers, a copy
button for the full address, and a `⨯` that stops forwarding the port.

Click a printed `localhost` URL in the terminal and a card offers the same
**forward & open** for whatever is listening on the host, with the printed path
carried through. [Port forwarding](/remote-hosts#port-forwarding) documents the
card, the <kbd>Cmd</kbd>/<kbd>Super</kbd> + <kbd>K</kbd> path for a port kolu
never saw, and the security note.

### Servers that detached

Some servers leave the terminal that started them: a tool that daemonizes
itself, such as `odu`'s web daemon or anything under `setsid`, keeps serving.

- A detached server stays listed under the terminal that **printed its URL**,
  marked **detached**. After a reload, a server whose URL scrolled far back
  moves to the group below until you scroll back to it. So does a server whose
  URL a [tile that was not live](/tiles#which-tiles-are-live) printed, until you
  next look at that tile.
- A folded **elsewhere on this host** group holds everything else with a story
  on that machine: your other servers, another user's socket a terminal printed,
  and any forwarded port whose server has died.
- A row with a port forwarded stays visible while the group is folded.
- A row served by another terminal names it, and the name takes you there.

## Reach a terminal from a shell

A folded **Attach** section builds the shell command for the terminal you are
looking at. Pick a **pane** (the main one, or any split, each its own PTY with
its own id) and a verb:

| Verb | What it does |
| --- | --- |
| **attach** | Takes the session over. |
| **snapshot** | Dumps its scrollback. |
| **send** | Types a prompt into it. |

One ready-to-copy command line appears, already pinned to this kolu's daemon.
The pane's id sits beside the pickers, copyable on its own.

Underneath, a **Drive one agent from another** callout spells out the send,
wait, snapshot loop. A folded reference covers the rest of
[`kaval-tui`](/kaval) (list · create · kill), [`padi-tui`](/padi)
(status · watch · wait), and the `--socket` argument.

## What the panel remembers

Whether the panel is open belongs to the tile. Moving focus between a tile's
panes never opens or closes it, so the layout does not jump when you click into
a split.

What the panel shows belongs to the pane. Each pane remembers its own tab, its
own Code-tab mode and selected file, and its own back and forward history.
Split a terminal to run an agent in another repo and the chips, directory and
file tree follow whichever pane you click into.

A header line under the tabs names the directory the pane is in, with its repo
root when it is in one, and the split's name when you are reading a split.

All of it rides session restore, so a tile's posture and each pane's selection
survive a reload. A new terminal inherits whether the previous active tile's
panel was open, or the new-terminal default when there was none. The panel
**width** and the Code tab's tree and content split stay global.
