Turn on **Settings → Agents**, open a new terminal and type `claude`. It runs.
So do `codex`, `omp`, `opencode`, `opencode2` and `pi`. You did not install any of
them: kolu put them on the terminal's PATH, from
[agent-distro](https://github.com/juspay/agent-distro), a distribution of coding
agents that kolu pins and ships. Each agent starts with kolu's own plugin loaded,
so it can drive other kolu terminals out of the box.

Agents are **off by default** — on a fresh install and on one that predates the
setting — so kolu changes no terminal's PATH until you ask. Beyond the switch, the
only choice you make is the **profile**: which set of agents and skills you
get. `vanilla` (plain upstream agents, signed in with your own provider) is the
default; other profiles add skills or a provider gateway.

## Pick a profile

Open **Settings** (the gear in the top bar). Two rows set it:

The setting is one for all of kolu — not per host, not per terminal.

## New terminals only, and each one says which

A change applies to the **next new terminal**. A terminal that is already open
keeps exactly the agents it started with: kolu puts the exact build of that
profile on its PATH, so a later profile switch (or a newer build arriving) never
changes a running agent under you.

Every tile shows which it got: a small chip in the tile's title bar with the
profile name and a short hash of the bundle, e.g. `vanilla 3fa9c2d1`. Hover it
for the full path. Two tiles with different chips started with different agents;
**no chip** means agents were off when that terminal started.

## Where they sit on the PATH

With agents on, a new terminal's PATH reads, from the front:

1. kolu's own tools (`kolu`, `kaval-tui`, `padi-tui`),
2. the chosen profile's agents,
3. your own PATH — including anything your shell's dotfiles add.

So the bundled `claude` wins over one you installed yourself. That is on purpose,
and the Settings text says so next to the switch. kolu re-applies this order after
your `.bashrc` / `.zshrc` run, so neither a dotfile that sets `PATH` outright nor
one that puts its own directory first (`export PATH=$HOME/.local/bin:$PATH`, as
Claude Code's own installer writes) undoes it (bash and zsh; other shells get the order at spawn only — see
[Shell integration](/shell-integration)).

To run your own `claude` in a kolu terminal, turn Agents off, or call it by its
full path.

## On other machines

Agents work the same on every host you [add](/remote-hosts), but nothing is
copied over ssh. The first time a host is used with agents on, that host
**downloads them itself**, from agent-distro's binary cache into its own Nix
store. The host's tab shows it while it happens:

> Downloading agents… 1.1 GB of 2.0 GB

When it lands, kolu says "Agents ready on *host*", and the next new terminal
there has them. Terminals opened on that host before then have no agents (and no
chip). The same status shows in Settings for this machine.

The host needs Nix with flakes, and its Nix must be allowed to use agent-distro's
cache (`https://cache.nixos.asia/oss`). If it isn't, the download is skipped —
the host never compiles agents — and the tab shows agent-distro's own message,
for example "cache … not usable; add it to nix.settings substituters /
trusted-public-keys". Fix the host's Nix settings, then turn Agents off and on
again to retry; nothing retries on its own.

The machine running kolu itself needs no download: every profile ships inside
kolu, so switching profile there is instant and works offline.

<Aside type="note" title="Disk">
  A host keeps its downloaded bundle in its own Nix store (and the machine
  running kolu also carries the bundles kolu ships). If you also install
  agent-distro on a host through its Home Manager module, both share the same
  downloaded bundle for the same profile.
</Aside>

## Turning it off

Settings → **Agents** off. From the next new terminal on, on every
host, kolu adds no agents and no plugin variable; your own tools are what run.
Terminals already open keep what they have, and keep their chip, until you close
them.

## What doesn't change

[Agent detection](/agent-detection) works the same either way: kolu watches the
agent running in a terminal, whichever `claude` it is.
