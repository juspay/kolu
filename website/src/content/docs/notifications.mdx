Running several agents, the thing you most need to know is *which one is waiting
on you, and where*. kolu escalates that signal outward — from the dock row, to
the app icon, to an OS notification, across every machine — so an agent that
flips to **awaiting you** finds you even when you're looking elsewhere.

## One vocabulary, everywhere

Three signals, three colours, and the same rendering wherever they appear — dock
row, repo section header, host tab, phone host row:

| Signal | Looks like | Goes away when |
| --- | --- | --- |
| **Needs you** — an agent is blocked on your input | violet count pill · violet row wash · a chip counting **how long it has waited** | you answer it — nothing else clears it |
| **Unread** — an agent finished and you haven't looked | amber count pill · amber row wash · amber badge on the pip | you open that terminal |
| **Working** — an agent is in flight | a plain rust count with a spinner | the agent finishes |

The two you can **act on** wear a pill; the working count deliberately does not.
So a number in a pill always means *there is something to do here*, and
**clicking one takes you to it** — the next terminal blocked on you (or the next
unread), cycling through them on repeat clicks. Clicking never dismisses: the
needs-you count is a live reading of what is actually waiting, so only answering
the agent clears it.

An agent that finishes in the background washes its whole dock row amber — tinted
background, lit leading stripe, bold title. A blocked one washes violet and floats
to the top of its repo section. The vocabulary of states is
[Agent detection](/agent-detection); how the marks compose with the state pip is
[The Dock](/dock).

## Beyond the app

- The **app-icon badge** counts awaiting agents — and it counts them across
  **every connected machine**, not just the one on screen.
- A backgrounded tab gets a **native OS notification** when an agent **effectively
  finishes** (its turn is done *and* the terminal has been quiet for a few
  seconds — so background sub-agents still typing do not chime early; once that
  finished signal has fired, idle statusline ticks do not re-chime), starts
  waiting on you, or **stops to ask you something** — a live question or
  permission prompt reaches you even when the agent was already sitting in its
  post-turn lull, and usually reads *needs your input* rather than *finished*
  (a prompt that settles in right on the heels of a finished turn may still
  carry the *finished* wording — but it rings). (If notifications don't appear,
  see
  [Troubleshooting](/troubleshooting#i-am-not-getting-desktop-notifications).)
- **Clicking the notification** brings kolu forward, and when the agent is on
  another machine it **switches to that host and focuses the exact terminal** —
  one action, no hunting.

<Aside type="note" title="It fires once per attention episode">
  kolu tracks each terminal by its own identity and chimes when it first needs
  you — when it **effectively finishes** (quiet after a waiting turn) or starts
  waiting on you, *or* when a live question lands over an agent that was already
  waiting — then stays quiet until the agent goes fully back to work (a later
  finish is a fresh episode). Idle TUI redraws after finish do not re-chime.
  Switching hosts, or opening and closing terminals, reorders the list but never
  manufactures a phantom alert, and a brief flicker between states as a prompt
  settles won't ding twice — a parked review prompt won't ding again every time
  you return to its machine. Pure resize/reveal repaints never count as work.
</Aside>

## Across machines

The needs-you signal is a first-class part of the [multi-host](/remote-hosts)
story, and it reaches you **the same way on every host** — an agent that finishes
or starts waiting on a *background* machine chimes, shows a backgrounded-tab
popup, and marks that host, exactly as the active machine's does. Each host tab
carries the **full summary for that machine** — how many agents are working, how
many are blocked on you, and how much finished work you haven't opened — read
straight off it (a host whose link drops **dims** its tab rather than dropping the
counts). A tab with an agent waiting on you **washes violet**; one with unopened
finished work washes amber until you switch there.

The summary shows on the tab you're **already on**, too. Being on a machine is no
guarantee you can see a terminal buried in the dock — so the tab tells you what
that host holds regardless, and clicking its violet pill takes you straight to the
agent that's waiting. On a phone, the same three counts ride the host row in the
pull-down sheet — see [kolu on a phone](/mobile).
