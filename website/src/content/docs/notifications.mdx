Running several agents, the thing you most need to know is *which one is waiting
on you, and where*. kolu escalates that signal outward — from the dock row, to
the app icon, to an OS notification, across every machine — so an agent that
flips to **awaiting you** finds you even when you're looking elsewhere.

## On the dock

An agent that finishes in the background marks its dock row with an amber
**unread badge** beside its state pip, and the dock keeps a terminal genuinely
**awaiting you** floating in the needs-you group (a just-finished agent that
isn't blocked drops to idle instead). The vocabulary of states is
[Agent detection](/agent-detection); how the badge composes with the live ring is
[The Dock](/dock).

## Beyond the app

- The **app-icon badge** counts awaiting agents — and it counts them across
  **every connected machine**, not just the one on screen.
- A backgrounded tab gets a **native OS notification** when an agent finishes,
  starts waiting, or **stops to ask you something** — a live question or
  permission prompt reaches you even when the agent was already sitting in its
  post-turn lull, and usually reads *needs your input* rather than *finished*
  (a prompt that settles in right on the heels of a finished turn may still
  carry the *finished* wording — but it rings). (If they don't appear, see
  [Troubleshooting](/troubleshooting#i-am-not-getting-desktop-notifications).)
- **Clicking the notification** brings kolu forward, and when the agent is on
  another machine it **switches to that host and focuses the exact terminal** —
  one action, no hunting.

<Aside type="note" title="It fires once per attention episode">
  kolu tracks each terminal by its own identity and chimes once when it first
  needs you — when it finishes or starts waiting, *or* when a live question lands
  over an agent that was already waiting — then stays quiet until the agent goes
  back to work. Switching hosts, or opening and closing terminals, reorders the
  list but never manufactures a phantom alert, and a brief flicker between states
  as a prompt settles won't ding twice — a parked review prompt won't ding again
  every time you return to its machine.
</Aside>

<Aside type="note" title="A finish waits for the terminal to go quiet">
  Some agents (Claude Code among them) can mark their turn *finished* while
  background sub-agents keep working — the transcript says done, but the terminal
  is still producing output. So a *finished* chime holds until the terminal has
  actually fallen quiet for a few seconds, which keeps a still-working agent from
  pinging early. A *needs your input* prompt is never held back this way — it is
  blocking, so it reaches you at once.
</Aside>

## Across machines

The needs-you signal is a first-class part of the [multi-host](/remote-hosts)
story, and it reaches you **the same way on every host** — an agent that finishes
or starts waiting on a *background* machine chimes, shows a backgrounded-tab
popup, and marks that host, exactly as the active machine's does. Each host chip
shows a live **awaiting-you count** read straight off that machine (a host whose
link drops **dims** its chip rather than dropping the count), and a host where an
agent **finished while you weren't looking** carries a quiet **amber dot** beside
its name until you switch to it — the softer tier of the same "needs you" amber
the awaiting pill speaks. The whole roll-up reaches you on the machine you're
actually looking at. On a phone, the same amber "needs you" pill rides the host
row in the pull-down sheet — see [kolu on a phone](/mobile).
