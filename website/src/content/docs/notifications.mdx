When several agents run at once, you need to know which one is waiting on you,
and where. The mark lands on the dock row, the count on the host tab and the app
icon. An OS notification reaches you when you are looking elsewhere.

## What each agent state means

Every agent's status is shown as one of the same five states, drawn with the same marks wherever
kolu shows agent status:

| State | Mark | What it means |
| --- | --- | --- |
| Thinking | pulsing accent dot | The agent is generating a reply. |
| Tool use | pulsing amber dot | The agent is running a tool. |
| Awaiting you | pulsing alert dot | The agent is blocked on your input: a question, or a permission it needs. |
| Working | spinning teal ring | The agent ended its turn while a task it launched is still running. It is busy, not blocked on you. |
| Waiting | dim dot | The agent is idle and it is your turn. |

Before an agent's first session lands on disk, a terminal shows **starting**,
**ready** or **working**. Starting and ready ask nothing of you, so they raise no
badge or count. [Agent detection](/agent-detection) covers how kolu reads each
state.

## The three counts

The same three counts appear on the dock row, the repo section header, the host
tab and the phone host row:

| Count | Looks like | Goes away when |
| --- | --- | --- |
| **Needs you**, an agent blocked on your input | violet count pill, violet row wash, and a chip counting how long it has waited | you answer it, and nothing else |
| **Unread**, an agent finished and you have not looked | amber count pill, amber row wash, amber badge on the pip | you open that terminal or look at it from the Conductor, that agent starts working again, or the terminal closes |
| **Active**, something is happening in a terminal | a plain rust count with a spinner | everything goes quiet |

The two you can act on wear a pill, so a number in a pill always means there is
something to do here. Clicking a violet count jumps to the next terminal blocked
on you, and cycles on repeat clicks. Clicking never dismisses a count: only
answering the agent clears it.

An agent that finishes in the background washes its whole dock row amber. A
blocked one washes violet and gets a mirrored entry in the dock's pinned
[Needs-you strip](/dock), while the row itself stays where it is. A terminal
[the Conductor is driving](/tiles#a-terminal-the-conductor-is-driving) is never
unread, and any amber mark it had lifts when the Conductor starts driving it.

A terminal is in the background unless it is in front of you, which means one
of these:

- it is the focused tile on the machine you are looking at, with the canvas on
  screen;
- its screen shows in the Conductor, in a [Look](/tiles#look-from-the-conductor)
  or in a picked work's **Terminals** view.

So while the Conductor is on screen, the tile you left focused can be marked and
chime. A Look or a live pane clears the mark and keeps it clear while it shows.

## What a host tab shows

A host tab carries no active count of its own. A rust stripe along its bottom
edge means something on that machine is active, so the tab keeps its size. The
count itself is the **working** row in the popover the connection dot opens.
With reduced motion on, the stripe stops moving. The tab's amber count has no
jump of its own: the tab itself is the button that switches machine.

## What counts as active

The rust count counts an agent thinking, an agent still settling in the moments
after its turn, and a plain shell that is printing. So a dev server that logs a
line every few seconds counts while it prints, and stops a second after it goes
quiet.

## Chimes and OS notifications

- The app-icon badge counts awaiting agents across every connected machine, not
  just the one on screen.
- A backgrounded tab gets a native OS notification when an agent effectively
  finishes (its turn is done and the terminal has been quiet for a few seconds),
  starts waiting on you, or stops to ask you something. Background sub-agents
  still typing do not chime early, and an agent's status line redrawing while it
  sits idle does not chime again.
- A question or permission prompt reaches you even in the agent's post-turn
  lull, and usually reads *needs your input*.
- Clicking the notification brings kolu forward. When the agent is on another
  machine, kolu switches to that host and focuses the exact terminal.
- A terminal [the Conductor is driving](/tiles#a-terminal-the-conductor-is-driving)
  makes no chime and no notification, and gets no unread mark or host-tab count:
  the Conductor is woken about it instead. A terminal you have taken over
  reaches you as any other.

If notifications do not appear, see
[Troubleshooting](/troubleshooting#i-am-not-getting-desktop-notifications).

## After kolu restarts or the page reloads

When kolu restarts or is updated, or you reload the page, while your terminals
keep running, your unread marks come back as they were. This holds for every
host, your own machine and remote ones:

| Before | After |
| --- | --- |
| An agent finished and you had opened it | Read. Nothing rings. |
| An agent finished and you had not opened it | Still unread. Nothing rings again. |
| An agent finished or started asking while kolu was down | Unread. A tab that stayed open chimes once. A page you open afterwards marks it without a chime. |
| An agent quit while kolu was down | No mark. |

Marks are kept per browser, and every kolu tab in that browser shares them:
opening a terminal in one tab clears its mark in the others. Opening a terminal
on your phone does not clear its mark on your laptop.

## What the Conductor rings for

[The Conductor](/conductor) reaches you through the same chime, notification and app badge as a terminal, plus a violet count on its chrome-bar entry. It rings for:

- a question it asked about a [piece of work](/work-card);
- a green pull request handed over for you to merge;
- a question it asked about no work;
- a [memory it proposes](/conductor-memory#when-the-conductor-proposes-something);
- a reply to a message you typed, once you have left the Conductor.

A pull request it merges itself never rings, and neither does a draft: it rings once it is marked ready and green. A message the Conductor writes without being asked, because an agent finished or needs something, does not ring either.

| Rule | What it means |
| --- | --- |
| Once per item | An item is its work, its reason, and the question or the commit that went green. A merge answer that flickers on one commit rings once, and a new commit going green rings again. |
| What it says | The notification is titled with the work and says what is wanted, in the card's own words, such as **Merge PR #700**. Clicking it opens that card and question. |
| In front of you | With the Conductor's tab showing in a focused kolu window, questions, waiting work and memory proposals chime and raise no OS notification. A reply makes no sound at all. |
| Anywhere else | Each chimes and raises an OS notification. |
| After a reload | Waits that were already there never ring again. |

A question about no work rings as **The conductor needs you**, and clicking it opens the conversation. A memory proposal rings as **The Conductor would like to remember something**, with the proposal's title or how many wait; proposals from one turn ring once, and clicking it opens the Memory sheet.

A reply is titled with the piece of work when your message was about one, and clicking it opens that card. Otherwise it says **The Conductor replied**, and clicking it opens the conversation. A reply rings in the browser where the conversation is open.

## Turn the alerts off

The **settings popover** has an **Attention alerts** toggle. Turning it off
silences the chime, the OS notification, and the dock's unread mark for a
background tile. The badge, the counts and the row washes stay, because they
read what is actually waiting. kolu remembers the setting across upgrades.

<Aside type="note" title="It fires once per attention episode">
  kolu chimes when a terminal first needs you: on an effective finish, when it
  starts waiting on you, or when a live question lands over an agent already
  waiting. It then stays quiet until the agent goes fully back to work. A later
  finish is a fresh episode.
</Aside>

## Across machines

The needs-you signal reaches you the same way on every
[connected machine](/remote-hosts). An agent that finishes or starts waiting on a
background host chimes, shows a backgrounded-tab popup, and marks that host.
The terminal itself is marked too: its dock row is amber when you switch there,
and its row in the [command palette](/switcher) shows the same mark from any
machine.

Each host tab carries the full summary for that machine: how many terminals are
active, how many agents are blocked on you, and how much finished work you have
not opened. A host whose link drops dims its tab rather than dropping the counts.
A tab with an agent waiting on you washes violet, and one with unopened finished
work washes amber until you switch there. The summary shows on the tab you are
already on, too.

On a phone, the same three counts ride the host row in the pull-down sheet; see
[kolu on a phone](/mobile).
