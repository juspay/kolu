The **switcher** is kolu's search box. Press <kbd>Cmd</kbd>/<kbd>Super</kbd> +
<kbd>K</kbd> and type a branch, a repo, a host or a command, without first
deciding which drawer to open. Terminals, hosts and commands share one index.

## What opens at the root

| Section | What it lists |
| --- | --- |
| **Recent** | The three warmest terminals, interleaved across every connected host, minus the tile that is already active. |
| **Hosts** | Every machine in the pool, when more than local is configured. Quiet when healthy; `active` only for the canvas host. |
| **Terminals** | The Terminals group (<kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>K</kbd>, where **Mod** is <kbd>Cmd</kbd> on macOS and <kbd>Ctrl</kbd> on Linux and Windows) and New terminal. |
| Command sections | Active Terminal, Canvas, UI and Help, listed separately until you type. |

Warmth is `max(your last visit, server activity)`, so a terminal a background
agent is working in can lead Recent. One seat is always reserved for the
terminal you were last in, and the highlight lands on it, which makes
<kbd>Cmd</kbd>/<kbd>Super</kbd> + <kbd>K</kbd> then <kbd>Enter</kbd> a toggle between your
last two terminals, across hosts.

Type to search every kind at once. Every whitespace-separated word must appear
somewhere in the row's corpus (repo, branch, intent, agent, cwd, host label,
command name). Order does not matter, so `kolu auth` finds the same row as
`auth kolu`.

## Terminals from every connected host

The switcher indexes live tiles on every connected host, not only the machine
whose canvas you are viewing. Splits are omitted at any depth: activating the
parent tile brings them with it. A split whose parent has closed is a tile of
its own, so it is listed here.

- Plain shells appear, with no agent required, using the same state pip language
  as the [dock](/dock).
- Repo identity matches the dock: monogram, repo name, branch.
- Order is fleet-wide `max(visit, activity)`, where a visit is the last time you
  made the tile active. Rows the dock's activity window would hide are dropped
  here too.
- A terminal on another host carries a **host chip**, such as `srid@builder`.
  Selecting it switches the canvas to that host and activates the terminal.

### Browse every host's terminals

<kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>K</kbd> opens **Terminals** with every connected host already listed.
Rows are grouped under host headers (`local · 3 terminals`,
`zest · 6 terminals`). The active host's group is first, rows inside a group are
in recency order, and a host with no terminals still gets a header.

Host scoping is optional. Click a host header, or the dock search icon, to
narrow to that host; the breadcrumb becomes `Commands › Terminals › zest`.
Typing filters the whole list flat across every host. At the root, the same
matching finds terminals without entering Terminals first.

## How results rank

With a non-empty query, hits are ordered by kind first, not by how close the
string match is:

| Priority | Kind | Tie-break |
| --- | --- | --- |
| 1 | Terminals | Warmth — max(last client visit, server/Dock activity) |
| 2 | Hosts | Your [host order](/remote-hosts) |
| 3 | Commands | Existing section order |

So a branch name outranks a host that shares a substring, and both outrank a
command. There are no prefix sigils (`>` for commands, `@` for hosts).

## Where the highlight lands

All three switcher scopes (<kbd>Cmd</kbd>/<kbd>Super</kbd> + <kbd>K</kbd>,
<kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>K</kbd>, <kbd>Mod</kbd> + <kbd>Shift</kbd> +
<kbd>H</kbd>) open with the highlight on the row you were last on that is not
the one you are on now. Press the chord, press <kbd>Enter</kbd>, and you are
back where you just were.

- "Last on" means your own trail: which tile you activated, which machine you
  switched to. A background agent printing output does not count.
- Lists are ordered by warmth, a different number, so the highlighted row is
  often part-way down, below warmer rows.
- The **Hosts** list keeps your host order and never re-sorts. In Terminals
  browse, host headers are fixed and rows inside each host are warmest first.
- A plain command list has no current row, so it opens on its first entry.
- The moment you type, the highlight moves to the top match.
- The rule applies to whichever kind leads the list. When Recent is empty,
  <kbd>Cmd</kbd>/<kbd>Super</kbd> + <kbd>K</kbd> leads with machines, and
  <kbd>Enter</kbd> hops hosts rather than tiles.

## The chords

| Chord / control | Opens |
| --- | --- |
| <kbd>Cmd</kbd>/<kbd>Super</kbd> + <kbd>K</kbd> | Root — search everything |
| <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>K</kbd> | **Terminals** — all hosts' terminals under host headers |
| Dock search icon | **Terminals › active host** — only that machine's terminals |
| <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>H</kbd> | **Hosts** — same host rows as root (switch canvas host) |

The root search is <kbd>Cmd</kbd> on macOS and <kbd>Super</kbd>
elsewhere, because <kbd>Ctrl</kbd> + <kbd>K</kbd> belongs to the shell in your
terminal. The full chord table lives under [Keyboard
shortcuts](/keyboard-shortcuts).

## Scoped views

A chord drills in rather than leaving the switcher. Breadcrumbs show the path.
Backspace on an empty query pops one level back to root, and Escape closes the
surface.

Selecting a terminal row switches host if needed, then activates the terminal.
Selecting a host in the **Hosts** scope switches the canvas to that host with no reload, the
same as the [host strip](/remote-hosts). That scope lists the root's host rows,
in your host order.

Its highlight opens on the host you switched away from, so <kbd>Mod</kbd> +
<kbd>Shift</kbd> + <kbd>H</kbd> then <kbd>Enter</kbd> hops
between the last two machines. Until a tab has switched once there is no such
machine, and the highlight falls back to the first other row. The trail is per
browser tab, and survives a reload of that tab but not a new one.

Host status text is quiet by default:

| Condition | Context text |
| --- | --- |
| Canvas’s current host | `active` |
| Connected, not active | *(none — connected is the default)* |
| Warming / failed / removed | `connecting` / `failed` / `removed` |

The connection dot carries health colour on every row, and reads the
[whole chain](/remote-hosts), so a reachable host whose terminal daemon is down
paints amber here, never green.

## Reading a row

Every result kind paints the same four slots:

1. **Lead** — the agent-state pip for a terminal (plain shells get the shell
   mark), the connection dot for a host, or a glyph for a command.
2. **Identity** — for terminals, the same headline as the dock: the intent line
   when one is set, otherwise the branch. Host rows show `user@host`, commands
   the command name. Matched tokens are bold in place.
3. **Context** — one truncating line: the branch when the identity is the
   intent, otherwise the agent summary or foreground command. Host status or
   command description for other kinds, and never the host name.
4. **Right rail** — the host chip (only for a terminal on another host),
   recency, keybind, drill chevron, and a kind tag (`term` / `host` / `cmd`)
   only at the mixed root.

The switcher only finds terminals that already exist on connected hosts. Sleep,
restore and session memory live under [Sessions](/sessions).
