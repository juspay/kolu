The **switcher** is kolu's unified search surface. Press
<kbd>Cmd/Ctrl</kbd> + <kbd>K</kbd> and type — a branch, a repo, a host, a
command — without first deciding which drawer to open. Terminals, hosts, and
commands share one index and one muscle memory; the extra chords are deep links
into scoped views of the same surface, not separate apps.

## What opens at the root

At the empty root you see three bands:

1. **Recent** — the three most-recent live terminals (the same recency clock
   the [Dock](/dock) uses), so "go back to what I was doing" is often row one.
2. **Hosts** — every machine in the pool (only when more than local is
   configured), each with its connection status.
3. **Commands** — New terminal, active-terminal actions, canvas, UI, help.

Type to search **across every kind at once**. Matching is multi-token: every
whitespace-separated word must appear somewhere in the row's corpus (repo,
branch, intent, agent, cwd, host label, command name…). Token order does not
matter — `kolu auth` finds the same row as `auth kolu`.

## Terminals across every connected host

The switcher indexes **live top-level terminals on every connected host** in
the padi pool — not only the machine whose canvas you are viewing. **Split
children** (terminals with a parent) are omitted: activating the parent tile
brings its splits with it, same as the Dock.

- **Plain shells** appear (no agent required), with the same state pip language
  as the Dock (shell mark / idle paint).
- **Order** is fleet-wide recency (`lastActivityAt` / sleep clock, reprojected
  per host). Parked rows the activity window would hide are dropped here too.
- **Cross-host rows** carry **one host chip** in the right rail — the same
  identity hue + connection-status language as the chrome-bar host strip — so
  `srid@builder` vs local is obvious without repeating the name in the context
  line. Selecting one **switches the canvas to that host and activates the
  terminal** in one step.

### Browse by host, type to pierce

**Terminals** is a three-level hierarchy when you *browse*:

1. **Terminals** — one row per host that has live terminals (with a count).
2. **$host** — that host's top-level terminals.
3. Select a terminal — switch + activate.

Breadcrumbs show the path (`Commands › Terminals › zest`); **Backspace** on an
empty query pops a level.

**Typing pierces the hierarchy.** At the Terminals level (and at the root),
typing a branch or repo name matches terminals **across every host** as a flat
list — host chips still mark foreign rows, and the breadcrumb reflects the
highlighted match's host. You do not have to drill into a host first to find a
name you already know.

The active host's Dock remains the always-on navigator for the machine you are
looking at; the switcher is the jump path over the whole fleet.

## How results rank

With a non-empty query, hits are ordered by **kind first**, not by how close the
string match is:

| Priority | Kind | Tie-break |
| --- | --- | --- |
| 1 | Terminals | Recency — most recently active first (Dock clock) |
| 2 | Hosts | Pool order |
| 3 | Commands | Existing section order |

So a branch name outranks a host that happens to share a substring, and both
outrank a command. There are **no prefix sigils** (`>` commands, `@` hosts) —
scoping is the existing drill-in path (below), not a mode character.

## Deep-link chords

| Chord / control | Opens |
| --- | --- |
| <kbd>Mod</kbd> + <kbd>K</kbd> | Root — search everything |
| <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>K</kbd> | **Terminals** host list (type to pierce all hosts) |
| Dock search icon | **Terminals › $active host** — only that machine's terminals |
| <kbd>Mod</kbd> + <kbd>Shift</kbd> + <kbd>H</kbd> | Scoped **host list** (switch canvas host) |

**Mod** is <kbd>Cmd</kbd> on macOS and <kbd>Ctrl</kbd> on Linux and Windows. The
full chord table lives under [Keyboard shortcuts](/keyboard-shortcuts).

## Scoped views

Deep links do not leave the switcher — they **drill in**. Breadcrumbs show the
path; **Backspace on an empty query** (or the breadcrumb) pops one level back to
root. Escape closes the whole surface.

### Terminals (⌘⇧K / dock search)

⌘⇧K lands on the **host list** under Terminals — pick a host to browse its
terminals, or type to search every host flat. The **dock search** icon skips
the host list and opens **Terminals › the host you are viewing**, so the list
matches the Dock's machine. Either way, selecting a row **switches host if
needed and activates** the terminal.

### Hosts (⌘⇧H)

The scoped host list is the pool as plain rows (connection status, active
marker). Selecting a host re-keys the canvas to that machine with no reload —
same as clicking a chip in the [host strip](/remote-hosts). The chrome-bar chips
stay: they are **ambient status**, not a second switcher.

## Reading a row

Every result kind paints the same four slots so a mixed list stays scannable:

1. **Lead** — agent-state pip (terminal; plain shells get the shell mark),
   connection dot (host), or glyph (command).
2. **Identity** — for terminals, the **same headline as the Dock**: repo
   colour eyebrow + **intent first line** when one is set, otherwise the
   branch. Host rows show `user@host`; commands show the command name.
   Matched tokens bold in place.
3. **Context** — one truncating line. When the identity is the intent, the
   **branch** sits here; otherwise agent summary / foreground (Dock
   subline). Host status or command description for other kinds. Never
   carries the host name on a terminal row.
4. **Right rail** — **host chip** (only when the terminal is on a non-active
   host — hue ring + label), recency, keybind, drill chevron, and a kind tag
   (`term` / `host` / `cmd`) **only at the mixed root**.

## What this is not

- The **dock** is still the always-visible navigator down the left edge —
  glanceable without opening anything. The switcher is the jump / search path
  over the **same** terminal set.
- The **host strip** is still ambient multi-host status; ⌘K does not replace it.
- Sleep, restore, and session memory live under [Sessions](/sessions); the
  switcher only **finds** terminals that already exist on the active host.

<Aside type="note" title="Mobile">
  On a phone the same chords and palette open from the chrome sheet; the
  spatial canvas is gone, but search and host switch still reach every live
  terminal and pool member. See [Mobile](/mobile).
</Aside>
