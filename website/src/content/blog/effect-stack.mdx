Kolu's plumbing used to be five libraries: [zod](https://zod.dev) for schemas, [oRPC](https://orpc.io/) for the wire, [partysocket](https://github.com/partykit/partysocket) for reconnects, [hono](https://hono.dev/) for HTTP, [`@preact/signals-core`](https://github.com/preactjs/signals) for reactivity. As of <PR id={2101} /> they're all gone from `package.json`. Underneath everything now sits one library: [Effect](https://effect.website/), pinned at `4.0.0-beta.103`. Yes, a beta. Hold that thought.

This isn't the migration war story — that diff was +78,690/−31,896 across 848 files, and the PR carries its own log. This is about the shape that came out the other side, and why we wanted it.

## The wire

The RPC contract is a flat, slash-tagged `RpcGroup` from `effect/unstable/rpc`, frames as ndjson over an Effect `Socket`:

```ts
// packages/common/src/contract.ts
export const koluRootGroup = RpcGroup.make(
  Rpc.make("server/info", { success: ServerInfoSchema }),
  Rpc.make("daemon/restart"),
  Rpc.make("hosts/add", { payload: HostRefSchema }),
  Rpc.make("hosts/reconnect", { payload: HostRefSchema }),
);

export const contract = koluSurfaceGroup.merge(koluRootGroup);
```

The [surface framework](/blog/surface-framework) kept its five shapes — cell, collection, stream, event, procedure — and each one now mints its verbs as `Rpc.make` entries; a collection's delta feed is just an RPC with `stream: true`. [oRPC-over-ssh](/blog/orpc-over-ssh) still works exactly as that post describes, minus the oRPC: the boundary held, and swapping the wire vendor never touched a domain module. Reconnect, partysocket's old job, is now a `Schedule` handed to the client protocol as a retry policy. One less library with its own opinions about time.

## Schemas that carry their types, and their errors

Every zod schema is Effect Schema, and the TypeScript type falls out of the schema instead of being maintained next to it:

```ts
// packages/common/src/hostKey.ts
export const HostKeySchema = Schema.Union([
  Schema.Struct({ kind: Schema.Literal("local") }),
  Schema.Struct({
    kind: Schema.Literal("remote"),
    target: Schema.String.check(Schema.isMinLength(1)),
  }),
]);
export type HostKey = typeof HostKeySchema.Type;
```

Errors are schemas too. A failure the caller can act on is a class that travels the wire and decodes on the far side as itself:

```ts
// packages/padi/src/errors.ts
export class TerminalNotFound extends Schema.TaggedErrorClass<TerminalNotFound>(
  "padi/TerminalNotFound",
)("TerminalNotFound", { id: Schema.String }) {
  override get message(): string {
    return `Terminal ${this.id} not found`;
  }
}
```

And the rule written in that file's header: if a failure means "the daemon is broken" rather than "you can handle this," it stays out of the type entirely — it's a defect, and defects crash loud. No error-code string soup, no `catch (e: unknown)`.

One bound does a lot of quiet work: every wire schema is `Schema.Codec<T, unknown, never, never>` — the two `never`s say decoding can require no services and fail into no untyped channel. zod had no way to even state that.

## Daemons on Layers

padi's boot sequence is a dependency-ordered Layer graph — gate, then stores, then identity, then surfaces, then the endpoint:

```ts
// packages/padi/src/daemonBoot/daemonMain.ts
const bootLayer = endpointLayer({ kavalHome, stateRoot, log }).pipe(
  Layer.provideMerge(surfacesLayer({ stateRoot, onDrain, log })),
  Layer.provideMerge(identityLayer(opts, home.socketPath, PADI_BOOT)),
  Layer.provideMerge(storesLayer(stateRoot, log)),
  Layer.provideMerge(gateLayer),
);
```

Each phase's type names the phase it needs, so booting out of order is a compile error, not a 3am log line. Teardown rides `Effect.acquireRelease` inside the scope — the hand-written `try { ... } finally { await served.close() }` is gone. hono is gone the same way: the HTTP app is `HttpRouter` layers merged together, and since the router ranks routes by specificity instead of registration order, the old "register the preview route before the static catch-all or it silently loses" footgun died with it.

## Why

**One semantics.** Five libraries meant five ideas of failure, retry, cancellation and teardown, and the glue between them was ours to write and ours to get wrong. Now failure is the error channel, retry is `Schedule`, teardown is `Scope`, everywhere — 489 files under `packages/` import `effect`, and the glue code between vendors is just deleted.

**Types with teeth.** zod tolerated a key that was present but `undefined`; Effect Schema refuses it. That one difference flushed out eight producer/schema mismatches we'd been shipping, two of them live in production paths. The bugs were ours all along. The strictness found them.

**Agents write most of this code.** Here's the part nobody prints on the box. Kolu is built mostly by coding agents, and an agent's nastiest failure mode isn't a crash — it's code that compiles and silently does nothing. `await` on a function that now returns an `Effect` typechecks fine and never runs; that pattern bit us eleven times across kolu and its consumers before we closed it. Effect moves that class of wrong to where an agent actually sees it: into the compiler. And where types can't reach, scanners do — every `Effect.run*` edge in the tree is a named allowlist row (109 sites in 54 files at merge), and the await-an-Effect and build-but-never-run patterns are banned by CI checks that were themselves tested against the known dodges. A human reviewer skims. The compiler and the scanners don't.

**The beta, then.** Sharp edges exist and we hit them. Effect RPC's default treats one handler's defect as fatal to the whole multiplexed connection — a single dead terminal tap took down the entire daemon link before we set `disableFatalDefects` at the one shared server layer. `RpcGroup.merge` is last-writer-wins with no collision detection, so every contract assembly is followed by a tag-count guard that crashes at import. And every place we depend on beta *behavior* — not API, behavior — carries a grep-able `BETA-ASSUMPTION(beta.103)` marker; bumping the pin fails CI until each one is re-measured. The library is beta. The discipline isn't.

One island remains: vazhi still renders its TUI with Ink, deliberately, because there's nothing orchestral about drawing frames. Everything else — the wire, the schemas, the HTTP app, both daemons, the reactive engine, the CLIs — is Effect, and 509/509 e2e scenarios rode it green the day it merged. That's the trade: one beta library watched hard, instead of five stable ones half-glued together. So far it's a good trade.
