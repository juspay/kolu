A remote dial normally needs the host's Nix to trust something: your ssh login
(`trusted-users`) or your cache's key. A **content-addressed** store path needs
neither, because its name is the hash of its contents. Publish your
[daemon](/surface/glossary) that way and `provisionAgent` has the host pull it
straight from your cache.

You need a binder built with `mkProvenAgentSource`
([@kolu/surface-daemon](/surface/ref-surface-daemon)), GitHub Actions, and a
binary cache already named in your agent flake's `nixConfig`: an
[attic](https://github.com/zhaofengli/attic) cache, or an
[odu](https://github.com/juspay/odu) cache bucket.

## 1. Declare where your builds are published

Give `mkProvenAgentSource` a `closureIndex` — a branch of a GitHub repository
that will hold small JSON files naming each build:

```nix
agentSource = mkProvenAgentSource {
  # …root, fileset, pkgs, commitHash, agents, flakeNix as before…
  closureIndex = { repo = "you/your-app"; branch = "ca-index"; };
};
```

It lands in the baked `binary-cache.json` beside your caches, with the raw URL
derived for you. The argument is required: a source that publishes nothing says
`closureIndex = null`.

## 2. Publish from CI

Add a job that runs the `publish-closure` action on each system you serve. It
must be the job's only Nix installer, because the action installs the Nix it
rewrites with.

```yaml
publish-closures:
  needs: build-and-push          # your job that pushes the normal closures
  strategy:
    matrix:
      os: [ubuntu-latest, macos-latest]
  runs-on: ${{ matrix.os }}
  permissions:
    contents: write              # it pushes the index branch
  steps:
    - uses: actions/checkout@v4
    - uses: juspay/kolu/.github/actions/publish-closure@master
      with:
        source: .#agent-flake-source   # your binder's baked source
        installables: my-daemon        # attribute names under it
        latest: ${{ github.ref == 'refs/heads/main' }}
        smoke: |                       # one line per installable — required
          my-daemon=bin/my-daemon --version
        attic-nixpkgs: github:NixOS/nixpkgs/<a pinned rev>
        attic-token: ${{ secrets.ATTIC_TOKEN }}
```

Without `source`, pass `sidecar` (the declaration) and, optionally, `rev`, the
key entries are written under. Omitted, `rev` is the commit being published
(`github.event.pull_request.head.sha || github.sha`). Never pass a bare
`github.sha` on a pull request, where it is GitHub's merge commit and is
refused.

The action refuses to run in a repository other than your declared
`closureIndex.repo`, and an installable with no `smoke` line fails the run
rather than skipping. For each attribute it:

1. builds the closure;
2. rewrites it content-addressed (not on macOS);
3. runs the program out of the rewrite;
4. pushes both forms to your cache;
5. imports the rewrite back into a throwaway store to verify it;
6. writes `<rev>/<system>/<attr>.json` to the index branch.

On a pull request it does everything except the last step.

### How the cache is pushed

The cache it pushes to is the declaration's **first substituter**, and the
declaration also says how that cache is pushed. No action input decides it.
Absent (or `{"kind": "attic"}`) means an attic cache, pushed with `attic push`
under `attic-token`. An odu cache bucket says so instead:

```json
{ "substituters": ["https://cache.example.dev/my-daemon"],
  "pusher": { "kind": "odu" } }
```

An odu cache's `nix-cache-info` carries `Odu-Origin` (the server a push is taken
at) and `Odu-Bucket` (the bucket it lands in). The action runs
`odu cache push --cache <substituter>` from its own npins pin (url and hash
both) under `odu-cache-token`, and that command reads both headers off the
cache.

- A bucket served from object storage (read at `<store>/<bucket>`, pushable nowhere) needs nothing extra said about it.
- The substituter must be `https://`. That read carries the bucket token as a Bearer header, so a plaintext URL is refused before anything is built.
- Verification is identical either way: the action imports the published paths back out of the substituter URL, and a Nix binary cache is a Nix binary cache.

`pusher` lives in the declaration, so where you set it depends on who writes
that file. A baked source takes it from `mkProvenAgentSource`:

```nix
agentSource = mkProvenAgentSource {
  # …as before…
  pusher = { kind = "odu"; };
};
```

In `sidecar` mode you set it in the declaration you pass. Omit it and the field
is not emitted at all, and the publisher takes attic.

Each pusher reads one credential: `attic-token` for attic, `odu-cache-token`
for odu. A run whose declaration needs one and has none fails rather than
skipping the push it was asked for. A fork pull request is the exception: it has
no secrets, so it rewrites, smokes and import-verifies, and pushes nothing.

## 3. Dial as usual

Nothing changes at the call site. A dial from a published revision reads its own
entry and has the host pull it; the progress log says
`landed … from the closure index`. A dial from anything else (a dirty
checkout, a revision CI never published) reads a 404 and takes the usual
route (rewrite, ship, or build on the host), saying so.

A host the rewrite cannot serve is sent the signed path instead, which needs the
host to trust your login or your cache's key.

<Aside type="caution" title="Two hosts still need trust">
  The rewrite is written by Nix 2.34, and Nix 2.35 changed how it hashes the
  same paths, so only hosts on Nix **2.17 through 2.34** take the
  content-addressed form. A **macOS** host never does: rewriting a Mach-O breaks
  its code signature ([`closureRoute`](/surface/ref-surface-remote)).
</Aside>
