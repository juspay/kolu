A [link](/surface/glossary) is how a client reaches a served surface. Every
link produces the same `SurfaceDispatch`, one flat `{ unary, stream }` pair
keyed by wire tag, and so the same typed client. The choice is about transport,
and you can change it later without touching a call site.

## Pick by where the server is

| Where the server runs | Link | Import | Serve side |
| --- | --- | --- | --- |
| In the same process (tests, single-process apps) | `directDispatch(served)` | `@kolu/surface/links/direct` | Nothing: it calls the handlers directly. |
| In a browser, talking to a Node server | `websocketLink({ group, url, isTerminalClose })` | `@kolu/surface/links/websocket` | `serveSurfaceApp` from `@kolu/surface-app/serve` |
| A daemon on the same machine | `unixSocketLink({ group, socketPath })` | `@kolu/surface/links/unix-socket` | `serveOverUnixSocket` |
| A subprocess, or a remote box over ssh | `stdioLink({ group, read, write })` | `@kolu/surface/links/stdio` | `serveOverStdio` |

Every serve function takes the same `{ group, handlers }` pair
`implementSurface` returns. `serveSurfaceApp` is the turnkey one: it owns the
whole listener, meaning shell and socket, gates, heartbeat, bind and teardown.
Reach past it to the granular `serveSurfaceSocket` (`@kolu/surface-app/server`)
only when the app owns its own listener, such as routing each upgrade to a
different runtime by `?host=`.

- **`directDispatch`** is the identity link. Hand it the served surface itself,
  as `directDispatch(implementSurface(surface, deps))`, and every call runs the
  handler in-process, with no serialization in either direction. Use it for
  tests, and for the in-process phase of a service you will later put behind a
  socket.
- Every wire link is async, because building a protocol and its fibers is an
  effect. Each returns `{ dispatch, dispose }`, and the websocket link adds the
  watchable `wire`. `dispose()` releases the link's scope, so its dial, ping and
  response fibers go with it.
- Every wire link takes the served surface's `group`, so the client and the wire
  agree about which members exist.
- **`stdioLink`** carries both a local subprocess and an ssh peer. Over ssh you
  usually drive it through `makeSession` (see
  [Mirror over ssh](/surface/mirror-over-ssh)) rather than wiring `read` and
  `write` by hand. For a test, `createLoopbackPair()` (`@kolu/surface/loopback`)
  gives you both ends of the same ndjson framing with no subprocess.

<Aside type="caution" title="A wire link needs a watchdog to reach surfaceClient">
  `surfaceClient` and `surfaceClients` throw if handed a bare `websocketLink`,
  `unixSocketLink`, or `stdioLink` dispatch, because a wire link can half-open
  silently. Pass a watchdog-backed handle: `connectSurface` mints one for the
  browser, `makeSession` for ssh. Only `directDispatch` may be passed bare.
</Aside>
