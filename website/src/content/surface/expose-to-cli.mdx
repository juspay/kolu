A shell drives a [surface](/surface/glossary) through `@kolu/surface-cli`. Your
cells and collections become readable members, and your procedures become
callable verbs. It is the argv sibling of
[exposing a surface to agents](/surface/expose-to-agents): the same surface, the
same allowlist, the same verb table, spelled for a terminal.

## 1. Install and import

```json
{
  "dependencies": {
    "@kolu/surface-cli": "workspace:*",
    "@effect/platform-node": "catalog:"
  }
}
```

`@effect/platform-node` is for the run edge in step 5 (`NodeRuntime.runMain`),
not for the projection. `surfaceCommands` itself is platform-blind.

## 2. Say where to dial

A command reaches a server, so your app decides which one. The resolution order
(`--socket`, then an environment variable, then a dev file, then the per-user
runtime socket) is yours to pick.

You write that decision once, as a `resolve` that reads the flags and answers
with the endpoint's name beside the thunk that opens it:

- The name travels with the thunk because you need it exactly when the dial
  fails, and there is no connection left to ask. A separate `describe` beside a
  `connect` would walk your resolution order twice, and could name one endpoint
  while dialling another.
- `resolve` returns an `Effect`, so an order that comes up empty has somewhere
  to say so. Fail it and the user gets exit `3` ("no endpoint to dial"), the
  same arm as a failed dial, instead of a crash.
- `values` is typed from your own flag record, so renaming a flag is a compile
  error rather than an `undefined` your app dials.

<Snippet src="packages/surface/example/snippets/cli.ts" region="endpoint" />

<Aside type="note" title="dispose is required">
  A CLI dials, does one thing, and exits, so the failure that costs a user
  something is a socket left open under a shell loop. An in-process host with
  nothing to release passes `() => {}`, which states the decision rather than
  leaving the adapter to guess it.
</Aside>

## 3. Hand over the same verb table

A hand-authored verb is a [`SurfaceVerb`](/surface/ref-surface#the-projection-vocabulary-kolusurfaceverbs),
the same record you hand `serveSurfaceAsMcp` as its `tools`. One table, two
faces, one set of names.

## 4. Project it

`expose` is default-deny, and it is [the same map](/surface/ref-surface#per-face-expose-kolusurfaceexpose)
the agent face and the wire faces take. `surfaceCommands` returns an array of
commands, a value rather than a program.

<Snippet src="packages/surface/example/snippets/cli.ts" region="project" />

CLI-only ergonomics ride in `annotate`, beside the verb table rather than inside
it: a `positional` is a shell concern, and the verb record stays a value the MCP
face can take verbatim.

The `core` is the unprefixed root; its verbs and readers sit at the top of the
mounted tree. Several surfaces on one binary go in `surfaces`, and each one is
mounted behind its key as the first argv word: `example outlines ops_run`,
`example outlines get entries`. That is the MCP face's `outlines_ops_run` in
argv's own separator. `list` stays at the top and describes the whole bundle,
each row named the way a caller types it.

## 5. Mount them in your binary

<Snippet src="packages/surface/example/snippets/cli.ts" region="mount" />

Which faces your binary offers is your decision, so the adapter hands back
values and runs nothing. Your `Command.run` is already the run edge; there is no
`runSurfaceCli` to learn.

Take both lines above, the edge and the flag, as one recipe:

- `reportingRunEdge` writes the line. Every failure this face raises carries its
  own line and its own exit code, and marks itself already reported so Effect's
  cause dump does not print on top of it. A host that re-fails without writing
  that line exits with the right code and says nothing at all. That line is what
  makes the [exit matrix](/surface/ref-surface-cli#exit-codes) true of your
  binary rather than only of this package's own failures.
- A refusal from the CLI library (a rejected flag, an unknown subcommand)
  carries no code of ours until the edge gives it one.
- A defect is not a failure, so `Effect.catch` never sees one, and the runtime
  reports it through the default logger onto stdout, in the middle of your data.
  The edge catches the cause for that reason.
- `disableErrorReporting` stays yours because it is `runMain`'s own argument.
  Without it the runtime prints a second, differently worded copy of the line
  the edge already wrote, on stdout.

<Aside type="note" title="Declare the endpoint flags in one place only">
  `surfaceCommands` merges your endpoint flags into every command, so
  `example proc_kill 4321 --socket /run/x.sock` parses. For `example --socket X
  proc_kill 4321` instead, declare them with `Command.withSharedFlags`, omit
  `flags` from the seam, and read them back in
  `resolve` (`Effect.flatMap(root, …)`). Both at once fails to start
  (`DuplicateOption`).
</Aside>

## What you get

```sh
example proc_kill 4321 --signal TERM     # a procedure, by its flat name
example top                              # a hand-authored verb
example get load                         # a cell's current value
example get processes 4321               # one item of a collection
example keys processes                   # the key set
example watch processes                  # snapshot, then ndjson deltas
example get load --follow                # the live subscription as ndjson
example list                             # what this face offers
```

Every verb also takes `--input '{…}'` (or `--input -` to read it from stdin) as
the alternative to the field flags: the whole input, as data, for the cases a
shell would fight you over. Every verb takes `--json` too, which asks for the
whole answer as data instead of whatever summary the host wrote for it.

## Read it from a script

The two facts a script needs are the shape of the output and the exit code.

- stdout is data: one JSON value for a read, one compact JSON line per frame for
  anything streamed. It is indented only when stdout is a terminal, which
  decides the spacing and nothing else. What the answer is gets decided by
  `--json`, so a command prints the same thing in a pipe, in a CI log and in
  front of a person.
- stderr is prose, with one exception: a verb's declared refusal is JSON on
  stderr, because it is data you can act on but is not the verb's answer.
- The exit code says which happened. See
  [the matrix](/surface/ref-surface-cli#exit-codes).

An absent collection item is a successful read whose answer says so, not a
failure: the read happened, and "not there" is what it found. Branch on the
payload, and keep the exit code for the things that are not answers.

A read that never found out is the other thing. A one-shot item read is bounded
against a deadline as well as against membership, so a quiet producer or a
collection with no key set to resolve against can run it out while the item is
alive.

That does not arrive as an answer: it is exit `3`, the endpoint's arm, naming
the member, the key and the budget. Your script never has to tell "gone" from
"could not tell" by reading a payload, because the exit code has already done
it:

```sh
if ! proc=$(example get processes 4321); then
  case "$?" in
    3) echo "no answer — nothing serving, or the read ran out of time" >&2 ;;
  esac
  exit 1
fi
if [ "$(jq -r '.present // true' <<<"$proc")" = "false" ]; then
  echo "4321 is gone"        # membership said so: safe to reap
else
  echo "still running: $(jq -r .command <<<"$proc")"
fi
```
