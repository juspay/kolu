### [The Right Panel](/right-panel)

- <Change kind="added" title="See what a terminal is serving — a Ports section in the Inspector" pr={1982}>When something in a terminal starts listening on a TCP port, a **Ports** section appears in the Inspector listing it — the number and the program holding it — usually within a second. No more scrolling back through a wall of agent output hunting for a URL that went by ten minutes ago. It is not a guess at printed text: kolu reads the machine's own socket table every few seconds (and immediately whenever the terminal produces output), and attributes each listener to the terminal whose processes hold it. So a port appears because something genuinely is listening, and it disappears when that stops. Splits count as the same terminal, which matters because a dev server is usually where you put it — in the split. A port bound to **all interfaces** on the machine running kolu already answers at the address you are viewing kolu at, so its chip has an **open** link. A **loopback-only** port, or one on a remote host, cannot be reached from your browser as-is and is listed with a "needs a forward" note; reach those with [vazhi](/vazhi) until forwarding lands in the Inspector itself.</Change>

### [vazhi](/vazhi)

- <Change kind="added" title="Open the port an agent just started — vazhi" prs={[1975]}>An agent starts a dev server on `127.0.0.1:5173` and the URL scrolls away — and even when you find it, loopback never leaves the machine it is on, so a port on a remote box or on kolu's own host is invisible from the laptop you are looking at. **vazhi** (Tamil: *way, passage*) is a small standalone TUI that fixes exactly that: press **a**, type `host:port`, and the service answers at `http://<this machine>:<port>` — a real terminal hyperlink you can click. The local port **is** the remote port whenever that number is free, so the URL is predictable and bookmarkable; when it is taken, the row shows the one you got. **x** cancels the selected forward and **q** quits, taking every forward down with it — and so does a crash or a `kill -9`, because each forward is its own ssh connection owned by the vazhi process rather than a listener parked on a shared one. Run it with `nix run github:juspay/kolu#vazhi`, on any host you can already `ssh` to without a prompt. A forwarded port is unauthenticated on every interface of the machine running vazhi — the same exposure as starting the dev server on `0.0.0.0` yourself — so keep it to a network you trust.</Change>
