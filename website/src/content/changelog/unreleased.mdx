### [ACP agents](/acp)

- <Change kind="added" title="Run a headless coding agent in a tile, and drive it over ACP">Driving a coding agent by typing into its TUI means watching a screen and guessing — has the turn ended, did that keystroke land, did the tool finish? **`acp-proxy`** runs an agent behind the [Agent Client Protocol](https://agentclientprotocol.com) instead, where a prompt is a request that returns when the turn ends and everything in between arrives as a typed frame. Run it in a kolu tile and it re-serves that same protocol on a unix socket: a program drives the agent while you watch the identical session scroll past in the terminal, message by message, tool call by tool call. **`acp-chat`** is the REPL you talk to it with — `nix run github:juspay/kolu#acp-proxy -- --id demo -- claude-agent-acp`, then point `acp-chat` at the socket it prints. The agent is whatever you name on the command line: `claude-agent-acp` and `codex-acp` both ship with it, need no global install, and use the login your machine already has, and any other stdio ACP agent works the same way. The harness absorbs what makes agent processes awkward to script — an adapter that dies mid-turn is replaced and your next prompt works, a cancellation that the agent ignores still ends the turn, and permission requests are answered "allow once" and shown in the transcript.</Change>

### [vazhi](/vazhi)

- <Change kind="added" title="Open the port an agent just started — vazhi" prs={[1975]}>An agent starts a dev server on `127.0.0.1:5173` and the URL scrolls away — and even when you find it, loopback never leaves the machine it is on, so a port on a remote box or on kolu's own host is invisible from the laptop you are looking at. **vazhi** (Tamil: *way, passage*) is a small standalone TUI that fixes exactly that: press **a**, type `host:port`, and the service answers at `http://<this machine>:<port>` — a real terminal hyperlink you can click. The local port **is** the remote port whenever that number is free, so the URL is predictable and bookmarkable; when it is taken, the row shows the one you got. **x** cancels the selected forward and **q** quits, taking every forward down with it — and so does a crash or a `kill -9`, because each forward is its own ssh connection owned by the vazhi process rather than a listener parked on a shared one. Run it with `nix run github:juspay/kolu#vazhi`, on any host you can already `ssh` to without a prompt. A forwarded port is unauthenticated on every interface of the machine running vazhi — the same exposure as starting the dev server on `0.0.0.0` yourself — so keep it to a network you trust.</Change>
